图号规划器——第二轮实际使用验收修正
本轮以实际使用效率、操作灵活性和减少重复录入为核心。不要只针对截图逐个打补丁，需要检查相关数据模型和业务关系，避免 UI 改完但底层规则仍然冲突。
1. 图号“作废”后必须允许重新启用
当前正式图号作废后只能显示“作废”，无法恢复使用，不符合实际业务。
图号状态需要支持双向切换：
使用中 → 作废
作废 → 恢复使用
历史扫描图号同样需要保持足够的操作灵活性，不要因为“历史来源”就把状态锁死。
需要明确区分：
停用/作废 ≠ 删除
作废只是暂时不使用，仍然占号；重新启用后恢复正常业务状态。
2. 图号库增加“批量删除图号”
目前只能进入单个图号处理，不适合清理错误导入、测试数据或一批不需要的历史图号。
图号库增加：
□ 多选
全选当前页
批量删除
批量删除时仍然遵守已经确认的图号删除规则，并在执行前汇总：
已选择 XX 个图号
可直接删除 XX 个
存在当前业务引用 XX 个
存在文件 XX 个

对于存在阻塞关系的图号，应明确列出原因。
不要因为其中一个图号不能删除，导致整批全部失败；应允许：
删除可删除项 / 跳过阻塞项

实际磁盘文件仍然不得跟随图号删除。
BOM 管理
3. “查看”和“删除”操作分开
当前：
查看 删除
距离过近，非常容易误点。
调整为明显独立操作，例如：
查看详情　　删除
删除保持危险操作视觉样式，并增加确认。
不要让两个文字按钮紧挨在一起。
4. 删除 BOM 的交互重新整理
当前点击“查看”后，在详情底部又出现一个巨大的：
删除整个型号 BOM

这个区域太重，而且容易和普通记录删除混淆。
需要明确区分：
删除本次 BOM 记录
与
删除该型号全部 BOM 历史
正常情况下最常用的是删除某一次错误建立的 BOM 记录。
“删除整个型号 BOM”属于极低频危险操作，不应该成为每次查看详情时最显眼的区域。
5. 删除 V1 / V2 版本概念
截图中的：
V2
我目前业务中不需要。
BOM 本身已经有：
- 业务变更日期；
- 生效批次；
- 提交时间；
- 历史记录。
这些已经能够表达 BOM 的先后关系。
因此取消面向用户的：
V1 / V2 / V3
版本概念。
查询、排序和历史关系使用：
业务变更日期 + 提交时间
判断即可。
如果底层因为兼容性需要保留内部 revision ID，可以保留，但不要在 UI 中作为“V2”展示，也不要要求用户管理版本号。
6. 生效批次显示去除文件夹排序前缀
当前读取文件夹名称，例如：
06.20260309
这里：
06.
只是我为了 Windows 文件夹排序使用的编号，不属于真正的资料批次。
因此 UI、BOM、邮件等业务显示中应自动去掉排序前缀：
06.20260309
显示为：
20260309
同理：
05.20251216 → 20251216
04.20250707 → 20250707
但：
00.首批大货
属于特殊业务名称，可以显示为：
首批大货
实际磁盘文件夹名称不要修改。
只是业务展示和业务数据提取时进行标准化。
BOM 二次修改
7. 已建立的 BOM 必须允许再次编辑
目前 BOM 保存以后只能查看/删除，不能修改。
实际使用中一定会出现：
- 材质写错；
- 尺寸补充；
- 位置调整；
- 图片换错；
- 修改明细补充；
- 生效批次选错。
所以 BOM 历史详情增加：
编辑
编辑时载入当前记录全部内容。
保存后需要保留：
最后修改时间
不要因为修改一处文字就强制用户重新建立一份完整 BOM。
如果该记录已经被历史外发快照使用，外发历史继续保持当时快照，不随当前 BOM 编辑而变化。
BOM 字段重新整理
8. BOM 项目字段最终确定
不要再把多个业务字段拼成一个字段。
最终每一个 BOM 项目按以下字段独立管理：
项目｜图号｜生效批次｜材质｜尺寸｜图片｜位置｜位置示意图｜修改明细

删除：
二维码

BOM 中暂时不要显示或维护二维码。
二维码继续作为独立模块处理，后面另行优化。
9. “材质 / 尺寸 / 位置”完全拆开
当前截图里的：
材质/尺寸/位置

不利于录入、修改、查询和后续邮件生成。
必须变成三个独立字段：
材质
例如：
亚银特多龙 银底黑字
尺寸
例如：
宽45.5mm × 高34.5mm
位置
例如：
本体背部下侧
数据库和 UI 都应独立保存，不要只是在显示层拆开、数据库里仍然拼成一个字符串。
10. “图片”和“位置示意图”分开
两个概念不同。
图片：
表示该 BOM 项目本身的图片/效果图/资料图片。
位置示意图：
表示该物料安装、粘贴、丝印等具体位置的示意图片。
因此必须是两个独立附件字段：
图片
位置示意图
允许：
- 只有图片；
- 只有位置示意图；
- 两者都有；
- 两者都没有。
BOM 图片本地存储
11. BOM 图片按“型号 → 日期”归档
目前附件虽然已经保存到本地，但目录结构和文件名不符合实际管理需求。
统一调整为：
BOM附件
└─ T40
   └─ 20260903
      ├─ 铭牌-20260903.png
      └─ 铭牌-20260903-位置示意图.png
即：
第一级：型号
第二级：业务变更日期
第三级：实际图片

例如：
T40 铭牌于 2026-09-03 变更：
普通图片：
T40\20260903\铭牌-20260903.png
位置示意图：
T40\20260903\铭牌-20260903-位置示意图.png
12. BOM 页面显示的附件名称也统一
现在页面显示：
image.png
这种上传时的原始文件名没有业务意义。
无论用户上传的原文件叫什么，保存后及 BOM 页面显示都按照系统规则：
铭牌-20260903.png
铭牌-20260903-位置示意图.png
即：
UI显示名称 = 本地归档文件名称
不要一个地方叫 image.png，磁盘里又是另一个名字。
文件扩展名保持原始格式，例如 PNG/JPG/JPEG，不要无意义转换。
如同一项目同一天确实需要多张普通图片，再考虑：
铭牌-20260903-1.png
铭牌-20260903-2.png
不要覆盖。
BOM 页面排版
13. BOM 详情重新排版
现在详情横向挤在一行，可读性较差。
不要为了“全部一行显示”把内容压得很窄。
建议：
第一层主要信息：
项目｜图号｜生效批次

第二层：
材质｜尺寸｜位置

第三层：
图片｜位置示意图

第四层：
修改明细

尤其“修改明细”允许自然换行，占用较宽区域。
图片不要只显示文件名，可以保留：
缩略图 / 文件名 / 打开位置
这样更符合实际查看习惯。
图号库文件显示
14. 转曲后文件只显示当前有效的一个
截图里同一个图号显示了多个不同资料批次中的转曲后 PDF。
日常查看图号时没有必要把所有历史转曲文件全部堆出来。
“转曲后文件”区域默认只显示：
该图号当前实际使用的最新有效批次中的转曲后文件

例如当前有效批次：
20260309
那么这里只显示 20260309 对应的转曲文件。
历史文件并没有删除。
如果需要查看历史，可以增加：
查看历史文件
展开后再显示其他批次。
15. 当前资料批次必须明显高亮
截图里：
06.20260309 · 当前
虽然已经有“当前”文字，但视觉区分仍然太弱。
当前批次需要明显区别于历史批次。
例如：
20260309　当前使用

并使用“当前使用”的统一状态色/标签。
其他：
20251216
20250707
20250526
……

作为历史批次使用另一种弱化样式。
整个系统后面统一遵守这个视觉规则。
产品档案删除问题
16. 产品删除不能要求用户手工到每个模块逐个清理
截图中 T40 已经把相关资料手工清理，但产品档案仍然提示：
计划图号(1)、历史图号(22)、资料批次(8)、BOM(2)、已配置二维码(2)

导致产品无法删除。
这里需要先调查：这些到底是真实业务引用、软删除数据、历史快照，还是已经删除后遗留的引用。
但从产品使用角度，我不接受：
想删除一个型号 → 自己去图号库删 → BOM删 → 二维码删 → 批次删 → 回产品档案再试一次。

操作成本太高。
17. 增加“产品删除检查/清理向导”
点击产品：
删除
系统自动检查全部关联：
正式图号
历史图号
BOM
资料批次
二维码
PDF实时索引
外发历史
其他业务引用

然后集中展示。
例如：
删除 T40
当前业务数据：
图号 23
BOM 2
资料批次 8
二维码 2
历史快照：
外发记录 3

允许用户在一个地方完成清理。
对于允许安全删除的数据：
清理关联数据并删除产品
对于必须保留的历史快照：
保留历史快照，但解除其对当前产品删除的阻塞。

不要要求用户自己跨 5 个模块逐项处理。
18. 产品删除必须区分“当前业务数据”和“历史快照”
已经发生的历史外发记录、邮件草稿、历史快照不应该永远阻止产品档案删除。
产品删除后：
历史记录继续保留当时的型号/SKU/品牌等快照。

但产品本身可以从当前业务中退出。
请重点检查现在提示的：
计划图号(1)、历史图号(22)、资料批次(8)、BOM(2)、二维码(2)
是否存在软删除后仍然计入阻塞数量的问题。
如果是，则属于 BUG，需要修复。
外发资料重新设计
19. 外发资料页面整体重新设计
当前外发资料页面视觉和操作流程不符合实际使用。
不要只改颜色。
按实际工作顺序重新组织：
① 选择产品
② 选择外发类型
本次变更资料 / 当前完整包材
③ 选择资料批次
④ 自动生成本次文件及变更内容
⑤ 检查文件
⑥ 生成压缩包
⑦ 自动生成邮件
⑧ 复制收件人 / 抄送 / 主题 / 正文

尽量做到一个页面完成，不要让用户来回切换多个模块。
邮件正文自动生成

21. 邮件不要显示系统内部来源信息
正文中不要出现：

这属于系统内部追溯信息，不应该发给供应商。
邮件中的“新文件”只需要：

默认不显示 .pdf。
也不显示：
来源批次

BOM → 外发邮件自动联动
22. 邮件“本次修改内容”直接读取 BOM 修改明细
这是本轮很重要的提效点。
你在 BOM 中已经填写：
修改明细

因此外发资料时不要让我再写一次。
系统根据：
产品 + 本次资料批次
自动找到对应 BOM 变更项目。
例如 BOM：
项目	修改明细
说明书	删除压缩机背板以及换门引导的说明，更新排版
顶部贴纸	修正温控文案


自动生成：
1.说明书：删除压缩机背板以及换门引导的说明，更新排版
　　新文件：XXXXX-说明书（转曲）
2.顶部贴纸：修正温控文案
　　新文件：XXXXX-顶部贴纸（转曲）

23. 外发操作尽可能减少人工步骤
理想流程：
选择型号
↓
选择本次变更资料
↓
选择批次
↓
系统自动读取 BOM
↓
自动识别本次修改项目
↓
自动找到对应最新转曲文件
↓
自动生成 ZIP
↓
自动生成邮件正文

用户只需要：
检查 + 必要时修改 + 复制

不要要求再次输入：
- 项目；
- 修改内容；
- 文件名；
- 型号；
- 产品类别；
- 品牌；
- 批次。
已有数据能读取的一律自动读取。
邮件正文仍然允许人工编辑，因为实际外发时可能需要补充特殊说明。
ZIP 50MB限制
24. 单个压缩包不得超过50MB
考虑邮箱附件限制，资料打包需要增加：
单个 ZIP 最大 50MB

但不要正好做到 50.00MB 才切包，建议代码内部保留少量安全余量，避免不同计量方式或附件处理导致实际发送超过限制。
如果本次资料超过单包限制，自动拆分：
D&D - SAMKYO F60空气炸锅 【更新包材资料-2026年9月22日】-1.zip
D&D - SAMKYO F60空气炸锅 【更新包材资料-2026年9月22日】-2.zip

依次类推。
25. 拆包必须以“文件”为单位
不能把一个 PDF 自身切成多个 ZIP 分卷。
应尽量完整放置每一个资料文件。
例如：
说明书 22MB
铭牌 5MB
彩盒 31MB

可以：
ZIP-1：说明书 + 铭牌
ZIP-2：彩盒

如果单独一个文件本身已经超过50MB，不能静默生成超限附件，应提示：
说明书.pdf 单文件大小为 63MB，超过邮件附件限制，请单独处理。

全系统视觉状态统一
26. “当前使用”和“历史使用”统一使用不同视觉层级
现在很多地方：
使用中
历史已用
已停用
当前
历史

颜色和布局太接近，不容易快速判断。
全系统建立统一视觉语义：
当前使用 / 启用中
使用明显的主状态标签。
历史使用
使用弱化的历史标签。
已停用 / 作废
使用警示/停用样式。
缺失 / 异常
使用错误状态。
不要每个页面自己定义一套颜色。
27. 产品档案二维码区域不要全部挤在一列
截图里类似：
说明书·已停用
售后·已停用
菜谱·启用中

全部堆在狭窄的“二维码”列中，非常拥挤。
需要重新排版。
可以换行，但不能挤压其他列。
例如：
说明书　已停用
售后　　已停用
菜谱　　启用中

不同状态使用统一状态标签。
后面二维码模块还会单独调整“新建/沿用”关系，本轮暂时只处理显示拥挤问题，不实施新的二维码业务模型。
28. 全局排版原则
不要以“尽量一行显示完”为目标。
优先保证：
信息层级清楚 > 塞进一行

尤其：
- 产品档案；
- 图号详情；
- BOM详情；
- 二维码状态；
- 外发资料；
- 文件路径。
该换行就换行。
长路径属于次要信息，应弱化显示。
操作按钮之间保留足够间距。
危险操作与普通操作明显分离。
当前使用的数据突出，历史数据弱化。
29. 本轮先调查再实施的重点
实施前重点检查以下问题，不要直接按 UI 表面现象修改：
1. 为什么作废图号不能重新启用；
2. 产品档案删除阻塞数量是否包含已经软删除的数据；
3. 删除产品时哪些关系实际上必须保留，哪些可以级联清理；
4. BOM 的 V2 是否只是内部 revision，移除 UI 后会不会影响历史快照；
5. 当前 BOM 附件存储结构如何迁移到“型号/日期”；
6. 已有 BOM 图片迁移后如何保持旧记录可打开；
7. 生效批次 06. 前缀目前是在扫描时保存还是展示时产生；
8. 当前有效转曲文件的判定依据；
9. 外发模块如何直接复用 BOM 修改明细；
10. ZIP 分包时如何保证文件完整和单包限制；
11. 已有外发历史快照不得因为 BOM 编辑/产品删除受到破坏。
如果涉及 Schema 修改，请采用最小、安全的迁移方式，并确保已有数据可迁移。
