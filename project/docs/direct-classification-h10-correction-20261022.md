# 图号直接归类与 H10 首批大货修正（2026-10-22）

## 已取得的现场证据

用户诊断截图：758 条历史图号，已关联 1、唯一候选待确认 697、歧义 0、冲突 0；点击人工确认后用户报告产品导航仍为 0。用户真实数据库未上传，因此不能宣称已经定位或修复该库全部 758 条数据。

用户 H10 目录截图：`吸尘器/AKVCH010JP-H10/03.量产后的变更明细（已量产的产品看最新日期）/00.首批大货`。

已复现的 H10 根因：批次解析与历史文件转曲判断均仅接受“03.量产后的变更文件”，漏掉实际存在的“变更明细”；会导致首批大货无批次，且无转曲文件名后缀时被判成源文件。

## 后续明确授权

用户明确要求“你不用等我审查，你直接归类，归类错的，给我一个修改的功能”。本次按此替代唯一候选必须先审查的交互：提供一次点击“自动归类”，无需先展开数百条诊断预览再确认。保留诊断与人工纠错，不在启动时擅自写真实库。

## 实现

- `POST /api/drawings/association-classify` 在实际执行时重新读取关联依据，唯一候选直接保存；有选中记录时只处理所选，否则处理全部未绑定候选。
- 复用现有绑定与审计结构、备份机制；备份在业务事务外，读取、写绑定/审计及保存校验在同一立即事务内。已有明确归属不自动覆盖，歧义和冲突保留待处理。
- 补足旧扫描字段为空时的候选：读取关联 PDF 的完整 SKU-型号目录，精确对应现有产品 ID；与 PDF 导航复用相同只读目录表达式。共享图号对应多个产品目录时保持歧义，不强选第一个。
- 返回真实写入数量及前后统计，刷新图号列表及产品目录计数；错误明确显示，诊断长列表内部滚动，操作按钮不再被挤到数百行之后。
- 归错时：查看 / 管理 → 管理图号 → 产品关联修正，选择正确型号、填写原因并保存。修改保留审计，不改图号或释放占号；已有外观沿用关系的历史归属继续受保护。
- 文件与明细两种目录拼写共享判断，同时修复批次解析及转曲分类。重新“扫描资料库”会给已有索引补上批次，保留索引 ID 和原始路径；无需清空索引或重建产品。
- 无 Schema 修改；不改历史图号原行、占号状态、BOM 或外发快照，不移动、重命名或删除 PDF。
