# 图号详情四板块与释放资格修正（2026-10-22 后续）

本次增量仅调整图号详情展示、真实首批/BOM摘要查询及现有删除资格，不增加外观管理、审批或占号体系；无Schema迁移。

- 四个主板块：基础信息、文件信息、业务关联、状态与操作。基础信息保持双列六字段。浅灰、蓝灰、绿灰、紫灰，间距20px。
- 文件卡片 flex 同排、52px；文件名可收缩、省略且完整名悬停可见，“打开位置”不收缩、不换行。存在状态仅在文件类型标题右侧显示；无文件用“暂无转曲前/后文件”；去除路径及查看路径。
- 业务关联只显示出现批次与首次BOM。出现批次来自实际PDF/BOM/已完成外发的批次ID，同目录采用完整业务序号，否则仅在全有可靠日期时比较；并列或不可比显示待核实，不按批次名、文件修改时间猜测。首次BOM指实际关联记录最早创建的BOM（created_at/id），保留软删除历史引用；不把后填的较早业务日期冒充首次入库。
- 状态编辑提供使用中/历史版本两个业务选项，复用原有状态转移API；对于尚未正式使用的reserved，显示不可选占位“仅占号，未正式使用”，选择使用中才调用正式启用。不能把reserved显示成已正式使用而失去启用入口。
- 改变产品所属在状态与操作内展开原有编辑表单，不建立独立关联维护板块。归类、纠错后的图号/产品ID/审计和历史引用不丢失。
- 保留删除占号与取消占号两按钮；历史扫描active/inactive均可进入释放检查，禁止仅因历史状态隐藏入口。

## 释放资格

旧服务只依据当前引用判断两种删除，有可能放行历史扫描和历史引用。按本次明确要求分离 `deletable/blockers` 与 `releaseEligible/releaseBlockers`。释放在同一事务内重新计算，UI禁用不是安全边界。

只有正式规划、可证明未启用的reserved且没有受保护引用可以释放。历史扫描无论启用/停用都保留占号；active不允许释放。旧库没有状态变更审计，voided无法证明从未启用，因此可发起检查但返回缺少未使用依据的阻止原因，不能通过active→voided绕过。

检查包括当前及缺失PDF（含删除保留后脱开的detected_codes_json）、软删除BOM、外发项目和图号快照、已删除图号关系、外观沿用，以及保留删除前的引用汇总。先保留删除再释放不能抹去历史证据。普通保留占号删除继续复用原当前引用限制及审计；不删除磁盘PDF或历史快照。

## 关联安全联动

完整回归发现产品集中退出也复用该删除服务。为避免先清历史再失去释放依据，产品退出必须在任何清理前预取并检查全部占号记录的释放资格；保留删除时将引用计数及protectedReleaseEvidence写入现有删除事件JSON，包括此前已保留删除的记录。追加本次操作审计而不覆写旧事件。用户可继续选择保留占号及按既有权限处理历史，不能通过清历史后再释放绕过保护。已有保留记录、旧审计为空、软删除BOM、产品清历史后再释放的完整路径已先失败再修复并通过。
