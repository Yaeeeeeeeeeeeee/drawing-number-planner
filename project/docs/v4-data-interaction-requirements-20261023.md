# 图号规划器｜数据关联修复与全局交互优化需求 V4.0

**开发对象：Codex**  
**实施方式：在现有项目中增量修改**  
**开发优先级：数据关联正确性 > PDF 人工归纳 > 页面操作精简 > 全局表格交互与视觉优化**

## 一、开发总原则

本次修改不是重新设计业务系统，而是解决实际使用过程中发现的问题。

主要目标：

1. 同一个产品能够正确关联不同外观编码的图号和 PDF。
2. 产品档案允许 SKU、型号重复。
3. 图号库、PDF 文件中心和产品档案的关联结果保持一致。
4. PDF 文件中心支持人工归纳未关联文件。
5. 删除重复的操作和无意义的界面元素。
6. 所有多列表格支持列宽调整、列顺序拖动及吸附对齐。
7. 页面保持间距舒适、文字清晰、对齐准确。
8. 修复长文件名跨列重叠的问题。
9. 减少页面顶部工具区、分页栏和详情面板占用的空间。
10. 保证所有图号占用、历史 BOM、外发历史和原始 PDF 安全。

开发前先读取项目 Skill，以及 Skill 指向的必要业务规则、Schema、历史数据和安全文档。

不要为了此次改动增加新的外观版本管理、审批流程或重复功能。

# 二、P0：修复产品、图号库、PDF 文件中心的关联

## 2.1 当前问题

目前一个产品使用不同外观编码时，系统无法在以下三个模块中完整建立关联：

- 产品档案
- 图号库
- PDF 文件中心

例如：

**产品：** SKFZC100JP  
**型号：** ZC100

对应图号：

- 1 号外观：`02.0305.010.0201001`
- 2 号外观：`02.0305.020.0201001`

这两个图号应能归属同一个产品档案。

其中 `010`、`020` 应按照原有编码字典拆解外观码与颜色码，不能直接假定整个字段都是外观码。

## 2.2 正确的产品与外观关系

一个产品可以使用多个外观编码。

产品外观改变时，使用新的外观编码规划图号。

旧外观不再用于新生产，但其历史图号、PDF、BOM、批次及外发资料必须保留。

产品档案里的默认外观编码，只用于图号规划时提供默认选择。

**不得把默认外观编码当成该产品唯一允许关联的外观。**

## 2.3 取消独立外观版本管理

不再要求用户维护：

- 初始外观
- 当前使用外观
- 历史外观状态
- 独立外观版本档案
- 外观版本使用状态
- 沿用到外观版本
- 外观待确认、使用未确定等额外状态

保留编码字典中原有的外观码及编码规则。

如果数据库中已经有相关结构，应先检查历史依赖，采用兼容方式处理，不能直接删除历史数据或引用。

## 2.4 产品档案允许重复

**正式业务规则：SKU 和型号都允许重复。**

要求：

- 不以 SKU 重复作为禁止创建或保存的条件。
- 不以同品牌型号重复作为禁止创建或保存的条件。
- 同品牌、同 SKU、同型号的不同产品记录也允许存在。
- 以产品内部 ID 区分不同产品档案。
- 编辑产品时不得错误提示自身 SKU 或型号重复。

例如以下记录允许同时存在：

| 产品 ID | SKU | 型号 |
|---|---|---|
| 101 | SKFZC100JP | ZC100 |
| 102 | SKFZC100JP | ZC100 |

但这不表示外观更新就必须新建产品。

同一个产品原本有两个外观编码时，仍可在同一个产品档案下管理。

## 2.5 自动关联必须防止误匹配

因为 SKU、型号都允许重复，不能单纯通过 SKU 或型号字符串自动指定产品。

需要综合：

- 产品内部 ID
- 完整图号
- 编码字典
- PDF 已确认的产品关联
- 实际资料目录
- 资料批次
- 历史确认关系

如果只能得到多个候选产品，不能随机选择其中一个。

应保留未关联状态，等待可靠证据或人工归纳。

## 2.6 三个模块的数据一致性

### 产品档案

同一产品可包含多个外观编码范围的历史图号及 PDF。

更改图号规划默认外观时，不得清除其他外观的历史关系。

### 图号库

同一个产品应能查看所有已可靠确认归属的外观编码图号。

不能因图号外观编码与产品默认值不同，就显示待关联。

### PDF 文件中心

不同外观编码的 PDF 可以属于同一个产品。

但必须保留各自真实资料批次，不能跨批次或跨产品错误合并。

## 2.7 重点排查

Codex 必须检查：

1. 产品默认外观是否被用作唯一匹配条件。
2. PDF 文件中心与图号库是否使用不同的产品关联规则。
3. 历史扫描记录中是否缺少产品 ID。
4. 图号库查询是否遗漏已有关系。
5. 新建或编辑产品是否覆盖原有关联。
6. 旧外观版本字段是否限制了关联。
7. 历史图号占用与产品关联是否被错误绑定。
8. 已确认的 PDF 关联能否安全复用到图号库。

不能只修改界面显示。

## 2.8 验收要求

以 ZC100 为重点案例：

- 1 号外观图号能够关联产品。
- 2 号外观图号能够关联同一个产品。
- 对应 PDF 可在 PDF 文件中心正确查看。
- 图号库显示与 PDF 文件中心一致。
- 修改默认外观不影响原有关联。
- 同 SKU、同型号的其他产品不会被误关联。
- 历史图号占用不丢失。

完成后报告修复前后关联数量，以及剩余未关联原因。

# 三、P0：PDF 文件中心人工归纳

## 3.1 增加人工归纳功能

目前 PDF 文件中心存在：

- 未关联产品
- 未关联产品批次
- 已扫描但归属错误
- 产品正确但资料批次不正确

需要允许用户人工修正归属。

## 3.2 支持单个及批量归纳

用户在 PDF 表格中勾选一个或多个文件后，可执行「人工归纳」。

操作内容：

1. 选择目标产品。
2. 选择目标资料批次。
3. 预览原归属与目标归属。
4. 确认后保存。

支持一次归纳多个同一产品、同一批次的文件。

不要求逐条修改。

## 3.3 产品选择

由于 SKU、型号允许重复，产品选项不能只显示 SKU 或型号。

必须能够区分实际产品记录。

可以显示：

`SKU · 型号 · 产品类别 · 内部产品ID`

内部 ID 主要用于区分重复记录，不需要在所有普通页面长期展示。

## 3.4 归纳后的结果

归纳完成后：

- PDF 文件关联到选定产品。
- PDF 文件关联到选定批次。
- 左侧目录树正确显示。
- 未归纳文件继续保留在原位置。
- 图号库能够利用该确认关系更新相应产品关联。
- 如果图号已经与其他产品存在冲突，不得静默覆盖。

归纳针对具体 PDF 文件实例。

同一个图号可以在多个批次中出现，不能因归纳一个文件实例而破坏其他实例的历史关系。

## 3.5 数据安全

人工归纳不得：

- 移动磁盘 PDF。
- 修改文件名。
- 删除文件。
- 修改完整图号。
- 释放图号。
- 自动修改 BOM。
- 覆盖外发历史。

同名「首批大货」批次如果来自不同实际目录，不得仅因名称相同就自动合并。

## 3.6 验收

支持将当前未归档的 ZC100 PDF 批量归纳到指定产品和批次。

保存后左侧目录树、文件表格、图号库的关联结果一致。

重新扫描后已确认归属不应无故丢失。

# 四、P1：图号库左侧目录树

## 4.1 保留型号展开箭头

此前型号前面的箭头点击后没有实际子节点。

本次保留箭头，并让它具有实际用途。

目录结构：

**产品类别 → 产品型号 → 编码字典主类别**

例如：

```text
冰柜
└── ZC100
    ├── 铭牌类
    ├── 提示贴纸类
    ├── 印刷件
    └── 包装类
```

具体分类必须读取编码字典中的真实主类别。

不使用 PDF 文件名猜测主类别。

不重新加入外观版本层级。

## 4.2 点击行为

- 点击产品类别：筛选该类别图号。
- 点击型号文字：筛选该产品全部关联图号。
- 点击型号箭头：展开或收起主类别。
- 点击主类别：筛选该产品对应主类别的图号。

不显示没有图号的空主类别。

不能解析主类别的历史图号仍需能在型号全部图号中查看，不得隐藏或删除。

## 4.3 测试产品

`ZC100-WB55` 等用户明确说明的测试产品，本次不单独处理、不自动删除。

# 五、P1：PDF 文件中心布局精简

## 5.1 删除右侧文件详情面板

目前右侧文件详情与主表格内容高度重复，还压缩表格宽度。

要求：

- 删除常驻右侧文件详情面板。
- 删除打开、关闭该详情面板的入口。
- 文件表格占满右侧可用宽度。
- 不再为详情面板预留空间。

文件名、图号、产品、批次、类型、匹配状态和文件状态等继续在表格展示。

异常匹配的具体原因仍需能够查看，但不得为了该信息恢复整个常驻详情面板。

## 5.2 精简文件行操作

删除每条文件行的：

- 更多
- 清除索引
- 暂不纳入
- 重复的批次改名入口

文件行操作只保留：

- 查看路径
- 打开位置

两个操作同一行水平排列，垂直居中。

清除索引、暂不纳入、恢复纳入等功能继续使用顶部已有的批量操作。

## 5.3 批次改名

只保留左侧目录树批次旁的编辑图标。

不在每个文件行重复提供批次改名。

改名只影响系统显示名称，不修改磁盘路径和历史快照。

## 5.4 顶部工具栏压缩

目前资料根目录、扫描按钮、详细信息和恢复默认宽度分为多行。

改成一行：

`资料目录 · PDF数量 · 未匹配数量                         详细信息 | 恢复默认宽度 | 扫描资料库`

要求：

- 正常宽屏情况下高度约 44–52px。
- 内容垂直居中。
- 路径和统计靠左。
- 操作靠右。
- 详细信息默认折叠。
- 移除常驻开发说明小字。
- 保留扫描功能和详细统计。
- 窄屏时可合理换行，不得错位。

## 5.5 表格宽度利用

不允许文件名列与资料批次列之间出现不合理的大片空白，同时产品列、操作列却被挤压。

默认布局应合理分配各列宽度。

用户还可以通过后面要求的全局列调整功能自行修改。

当前「自动归类」「诊断图号关联」「产品/批次导航」占据多行。

要求：

1. 将自动归类、诊断关联放在顶部紧凑工具区。
2. 当前型号、图号数量同一行展示。
3. 关键词、主类别、状态筛选尽量放在一行。
4. 删除独立的大面积空白工具区。
5. 产品目录树的展开收起使用侧栏现有控制方式。
6. 删除常驻说明小字。
7. 不改变自动归类和诊断关联的底层业务功能。

# 七、P1：全局表格拖动与吸附对齐

这是本次新增的全局交互要求。

## 7.1 适用页面

对所有具有多列表格的页面统一支持，包括：

- 图号库
- PDF 文件中心
- 产品档案
- 二维码管理
- BOM 管理
- 外发资料

其他使用同一表格组件的页面，也应遵循相同规则。

不需要在每个页面重复开发一套独立实现。

## 7.2 手动调整列宽

用户可拖动表头列边界改变列宽。

要求：

- 鼠标靠近列边界时显示左右调整光标。
- 拖动时实时预览宽度。
- 松开后固定宽度。
- 表头与整列内容同步调整。
- 不出现列边界错位。
- 设置合理最小宽度。
- 双击边界可自动适应内容宽度。

## 7.3 手动调整列顺序

支持通过拖动表头改变列排列顺序。

要求：

- 拖动时显示目标插入位置。
- 松开后整列移动。
- 表头和对应数据必须一起移动。
- 不出现标题与数据错位。
- 复选框、操作列等关键列可根据交互安全需要限制可移动范围。

## 7.4 吸附对齐

加入吸附对齐机制。

- 列边界接近推荐宽度时可轻微吸附。
- 拖动列顺序时显示清晰的插入参考线。
- 鼠标释放后列边界准确对齐。
- 不能出现半列重叠或留下异常缝隙。
- 不允许因为吸附而强行将两列压到不可阅读。

吸附应轻量，不需要另外增加复杂设置面板。

## 7.5 布局自动保存

用户调整后的列宽及顺序自动保存。

要求：

- 每张表格分别记忆布局。
- 重新打开应用仍保留设置。
- 切换产品或批次不重置布局。
- 提供恢复默认布局能力。
- 优先复用现有「恢复默认宽度」入口，扩展为恢复默认表格布局，不新增重复按钮。

表格布局设置不得修改业务数据。

## 7.6 正确换行规则

此前要求「不强制换行」，但实际出现了文件名覆盖资料批次列的问题。

现正式统一为：

**优先单行；宽度不足时允许合理换行；绝不允许文字重叠。**

具体规则：

| 内容 | 显示要求 |
|---|---|
| 文件名 | 优先单行，必要时最多两行 |
| 资料批次 | 优先单行，必要时两行 |
| 图号 | 尽量单行，超出省略 |
| SKU、型号 | 优先单行，超出省略 |
| 状态标签 | 单行、完整、居中 |
| 操作按钮 | 保持可用，禁止挤压错位 |
| 路径和备注 | 按实际需要自然换行 |

文件名两行仍放不下时，使用省略号，并允许悬停查看完整内容。

**所有换行必须限制在本列单元格内部。**

拖动列宽后，行高可以根据实际内容适度变化。

同一行的状态标签、复选框和操作按钮保持垂直居中。

## 7.7 必须修复的重叠问题

此前 PDF 文件中心出现：

- 文件名超出本列。
- 覆盖到资料批次列。
- 两列文字叠在一起。
- 列宽调整后布局不正常。

必须重点检查文本容器、表格布局、列宽计算、溢出和换行样式。

不能仅通过增加所有列的宽度掩盖问题。

## 7.8 窗口尺寸变化

在普通桌面和 4K 宽屏中均需正常显示。

窗口变窄时：

- 保持表头与数据对齐。
- 不出现内容重叠。
- 必要时允许表格整体横向滚动。
- 不允许整个页面因某一列过长被撑坏。

# 八、P1：图号库详情页保持精简

沿用此前确认的四块布局：

1. 基础信息
2. 文件信息
3. 业务关联
4. 状态与操作

## 8.1 文件信息

转曲前、转曲后各显示：

- 文件名
- 存在 / 缺失
- 打开位置

不显示路径全文，不重复显示文件存在状态。

文件名与打开位置优先同一行。

长文件名使用合理省略，不得挤压按钮。

## 8.2 业务关联

仅保留：

- 图号首次出现的可靠资料批次
- 首次实际进入的 BOM

不同批次出现同一图号的 PDF 实例属于正常情况，不能当成重复图号。

业务关联数据必须来自真实记录，不能用扫描时间随意猜测。

## 8.3 操作

保留：

- 改变产品所属
- 使用中 / 历史版本
- 删除图号（保留占号）
- 取消占号并删除

历史版本同样允许进入释放资格检查。

但已真实使用、存在历史占用或受保护引用的图号不能仅因为状态为历史版本就自动释放。

## 8.4 视觉

采用低饱和度浅色分组：

- 基础信息：浅灰
- 文件信息：浅蓝灰
- 业务关联：浅绿灰
- 状态与操作：浅紫灰

不同板块间距统一，减少多层白框。

# 九、P1：分页和滚动

以下页面取消传统分页控件：

- 产品档案
- 二维码管理
- PDF 文件中心
- 图号库

不再显示：

- 每页 50 条
- 上一页
- 下一页
- 第几页

改为单一列表滚动。

数据较多时使用虚拟列表或分批加载，避免一次渲染数千条导致卡顿。

要求：

- 保留筛选。
- 保留勾选。
- 保留展开状态。
- 合理保持滚动位置。
- 不因加载更多记录而重复或遗漏数据。

其他页面可以复用该行为，但不要因此大范围重写无关模块。

# 十、全局 UI 规范

用户特别重视以下要求：

**文字与段落之间的间距、整体对称、列对齐、按钮对齐、内容舒适度。**

必须统一执行。

## 10.1 间距

建议使用统一间距系统：

- 4px
- 8px
- 12px
- 16px
- 20px
- 24px

大板块之间一般保持 20–24px。

表格单元格左右内边距一般为 12px。

相同层级采用相同间距。

## 10.2 对齐

- 文件名、SKU：左对齐。
- 状态、数量、日期：居中。
- 操作按钮组：整体居中。
- 表头与数据：严格同列对齐。
- 图标与文字：垂直居中。
- 同一行下拉框、输入框：统一高度。

不是所有内容都强制居中，而是根据字段性质选择合适的对齐方式。

## 10.3 文本换行

不能机械地统一禁止换行，也不能任由文字随意换行。

要求：

- 优先单行。
- 空间不足时允许合理换行。
- 禁止跨列覆盖。
- 禁止中文逐字竖排。
- 禁止文字和按钮重叠。
- 禁止表头与内容错位。
- 必要时使用省略号与悬停查看全文。

## 10.4 常驻说明文字

删除长期占据页面的开发说明和重复提示。

异常真正发生时，才显示必要原因。

不能删除实际业务数据、状态和重要安全反馈。

## 10.5 颜色与底框

可以使用轻微不同的低饱和度浅色背景，区分主要信息板块。

不使用大量鲜艳颜色。

避免过多嵌套卡片、重复边框。

设计应与现有图号规划器整体风格保持一致。

# 十一、外发资料保持既定业务规则

# 十四、重点验收场景

至少完成以下验证：

**场景 1：ZC100 多外观**

同一产品能关联 1 号、2 号外观编码的图号和 PDF。

**场景 2：SKU 与型号重复**

能够创建两个 SKU、型号均相同的产品档案，不被唯一性检查错误拦截。

**场景 3：重复产品防误关联**

系统不能仅凭重复 SKU 或型号自动将文件分配给错误产品。

**场景 4：PDF 人工归纳**

选择 12 个文件，统一指定产品和批次，保存后目录树、表格和图号库关系正确。

**场景 5：图号库目录树**

展开 ZC100 后显示真实主类别，点击后右侧正确筛选。

**场景 6：文件详情移除**

PDF 文件中心不再存在右侧常驻详情面板，表格使用全部可用空间。

**场景 7：文件行操作**

只显示查看路径、打开位置，且两者在同一行。

**场景 8：列宽调整**

拖窄文件名列，文本最多合理换成两行，不覆盖资料批次列。

**场景 9：列顺序调整**

拖动资料批次列到其他位置，表头和整列数据同步移动。

**场景 10：吸附对齐**

拖动后边界准确，列之间没有重叠或异常空隙。

**场景 11：布局保存**

关闭并重新打开应用，列宽和列顺序仍保持上次设置。

**场景 12：恢复默认**

恢复默认后，列宽和列顺序均回到初始设计。

**场景 13：大量文件**

PDF 文件中心存在数千条数据时，滚动流畅，筛选和选择状态正确。

**场景 14：历史安全**

人工归纳、图号关联和表格调整不破坏图号占用、BOM 和外发历史。
