## 2. 推荐架构与页面/数据关系

推荐“规范产品主身份 + 外观版本 + 原始身份映射”，保留products已有行及历史raw product_id。不是仅把两条产品折叠显示：所有创建、引用校验、查询、清理、外发必须共用同一身份解析与版本作用域。

不推荐直接解除默认外观保护/改一个字段（BOM仍混用），也不推荐再复制产品或批量改旧外键（唯一性、QR、BOM触发器及快照冲突）。

规范身份代表SKFZC100JP/ZC100；两个旧raw身份分别映射至原始来源并保留SKU别名/目录识别。1号/2号版本有各自ID及BOM指针；2号为当前、1号历史，只通过明确启用事务切换。归并不删第二产品，不把旧外观标成产品作废/回收站。

当前PDF的产品字段主要由关联图号的product_id派生（file-repository.ts:55），不是一份独立产品证据。新匹配器必须区分原始目录/人工确认/明确批次归属与这种派生字段，不能让“PDF由图号得出产品”再反过来证明同一图号应关联该产品。

图号主记录仍唯一，版本使用关系可多对多：2号可以显式复用1号图号的合规物料，不改该图号原编码。扫描到PDF不等于某版本实际使用；实际使用由明确BOM/外发关系证明。旧BOM和外发按原身份读取，规范身份聚合查询不能改写原快照。

需要调整：
- 产品：ProductService/Repository/types、products路由、ProductsPage/编辑器、外观版本与归并预览服务。
- 图号：规划/占号服务、DrawingRepository/QueryService、关联诊断、DrawingLibraryPage/抽屉及路由。
- PDF：scanner/classifier/文件与批次Repository/Service/路由，FilesPage、共享ProductCatalogNavigation及筛选适配。
- BOM：版本作用域、current指针、草稿复制/差异/启用、同产品/同版本或明确共享授权校验。
- QR：QrService/Repository/types、产品/用途/版本选择与QrCodesPage；不会参与图号占号。
- 外发：当前完整资料集合、BOM上下文、预览、打包和新历史的身份/版本冻结字段；旧包快照不更新。
- 共用：renderer API类型、DataTable列配置/分页偏好、查询缓存与失效通知、迁移/备份/回归及Windows打包守卫。

特别风险：现有外发完整资料按包含外观码的完整prefix聚合槽位。直接把两代批次合流会同时保留新旧外观槽位，不能自然代表“新代彻底替代旧代”。这是本次必须明确的业务规则。

## 4. 迁移、归并和回滚

A. 先在用户明确选定的备份上只读盘点：表/迁移版本、FK/唯一性、两产品精确ID与品牌/SKU/型号、各领域记录数、跨产品/版本引用、占号集合、旧快照哈希、真实路径；当前尚无该库，不能编造数量。
B. 停止写入和扫描，完成WAL一致性处理；沿用可读性/integrity_check验证的备份，并保存配置、原文件/受管附件清单与恢复演练结果。禁止仅复制一个活跃WAL数据库文件便宣称可恢复。
C. Schema迁移事务只建立结构/兼容层；可靠既有身份可一对一映射，混合/未知外观保留待确认，不按最新日期强填。故障注入应全部回滚。
D. ZC100归并是独立业务预览与确认，不随启动迁移执行。预览主/别名身份、各域受影响ID/数量、QR冲突、两套BOM、外发/文件路径、版本候选、阻塞项；执行前再次核对指纹/版本/FK。保留两条raw身份，仅规范列表显示一个主档案，不重写旧BOM日期/前序链或旧包JSON。
E. 归并事务后核对：旧行ID/内容、图号字符串和占号集合、BOM/外发快照、QR网址与状态、文件路径/哈希均保持；新增关系数量正确。冲突项不自动覆盖或拼接。
F. 回滚分层：事务内失败原状回滚；新业务尚未写入时可按审计撤销映射/恢复已核验备份；有新写入后不得盲目降级/删新表，应导出增量、评估依赖后补偿或前向修复。旧程序不能写新版本Schema（已有高版本拒绝机制需保留）。恢复整库备份会丢失备份之后的新写入，必须明确说明。

## 6. 待确认的业务默认（确认前不实施）

1. 外观版本与颜色：建议一代外观可含多个颜色，颜色本身不自动生成新的外观版本；先保持现有BOM项目/颜色模型，不擅自新增“每色一套BOM”。是否需要每颜色独立BOM须另定。
2. 新代启用/旧版本：只有一个当前外观；历史版本保留查询和原关系，回切须显式操作并预览。不自动进入产品停用/回收站。草稿可多条，启用须基于当前修订确认。
3. QR：建议可显式选择沿用产品共用QR或设置版本独立QR；不自动复制为启用、不覆盖旧网址。主档案三用途状态默认展示当前外观的有效选择，共用来源明示。
4. 外发当前完整资料：建议以明确选中的外观及其当前BOM为范围，只有显式沿用项才取旧版本资料，不把两代批次按日期/序号混成一套。它会改变现有完整包材集合的选择语义，需要确认。
5. 历史BOM：迁移/归并绝不改已有内容。后续是保留现有历史原位纠错，还是发布后只能新建修订且保留旧快照，需要确认。
6. 暂不纳入：建议默认只针对当前文件实例，同内容其他副本不自动忽略；原路径相同/指纹未变继续忽略；内容变化进入复核，移动仅在可靠唯一证据下继承或提示。是否同时禁止新BOM/外发选用，还是仅隐藏文件中心列表，需要确认；历史引用始终保留。

图号“版本”沿用有据可查字段，无记录显示未记录；末三位是流水号，不当作图纸修订。新建产品后的自动回查可以运行诊断，但无法唯一确定外观时不得自动归属。
