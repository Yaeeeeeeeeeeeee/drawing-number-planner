## 环境矩阵：同时检查宽度与高度

分辨率覆盖1920×1080、2560×1440、3840×2160；各自覆盖Windows支持的100%、125%、150%、200%适用组合。每个组合检查最大化、窗口化、半屏和最小支持窗口，并跨不同缩放显示器移动窗口后复核。无法配置或设备缺失须记录未执行及原因，不自动省略或标为通过。

| 物理分辨率 | 100%理论逻辑宽高 | 125% | 150% | 200% |
|---|---|---|---|---|
| 1920×1080 | 1920×1080 | 1536×864 | 1280×720 | 960×540 |
| 2560×1440 | 2560×1440 | 2048×1152 | 约1707×960 | 1280×720 |
| 3840×2160 | 3840×2160 | 约3072×1728 | 2560×1440 | 1920×1080 |

这些是整屏理论估算，不是Electron实际视口。任务栏、原生标题栏、窗口边框、缩放和可用工作区均影响结果。例如1080p@200%的可用高度低于600，不能宣称满足最低支持目标；该环境仍检查降级和操作可达性，完整工作流验收需在实际视口至少720×600的组合进行。半屏小于目标同理，不扩大为480px完整工作流承诺。

最小完整工作流目标是实际720×600 CSS px（宽、高同时满足）。检查正好720×600，以及各断点前后和短高窗口；覆盖原1080／1200／1280宽度。禁止全局CSS zoom。浏览器模拟或DPR模拟不能替代真实Windows系统缩放和跨屏验收。

## 测量与记录

每例记录：验收人／上海时间、准确提交及包版本、Windows／Electron版本、显示器和工作区、物理分辨率、系统缩放、应用缩放、devicePixelRatio、窗口模式、窗口外框和内容尺寸、实际innerWidth／innerHeight与布局容器宽高、折叠状态、数据场景、操作、预期、实际、通过／失败／未执行及截图或日志。

窗口配置需要验证外框、内容区域与CSS视口差异。不得将BrowserWindow最小宽高直接等同720×600 CSS px；测量仅为后续验收工具，不授权修改IPC、安全或恢复机制。跨不同缩放显示器双向移动、恢复／最大化后重测，不沿用旧DPR或尺寸。

## 布局与高DPI通过条件

- 720×600下核心查询、规划、BOM、产品、QR、文件、外发和字典／迁移已有工作流可操作。导航和详情可全为抽屉，完整图号可查看、选择和准确复制，确认按钮可到达。
- 无整页横向溢出；内容、表格、详情或弹窗可独立滚动。弹窗标题、关闭、错误和确认均在可操作范围，不能被固定栏遮挡或仅裁切隐藏。
- 长中文文件名、完整路径、最长图号、长型号、批次、异常说明允许换行或局部滚动；普通行目标40–44px，复杂行允许增高。关键状态不能因降密度消失。
- 自动折叠与恢复宽度不丢筛选、记录、勾选和编辑输入；详情选择与批量选择独立，折叠不产生新增业务写入、不自动选第一条。
- 4K提高信息量和可见行数，不简单整体放大；表单／危险确认保持适当阅读宽度。灰阶对比清晰，状态仍有文字和少量语义色。
- 高DPI文字、16–18px图标、边框、表格、弹窗和文件详情清晰，无模糊位图强拉伸、错位和截断；跨屏后重新检查。
- 键盘可访问导航、表格详情和危险动作，焦点清晰；Escape关闭回焦；模态抽屉正确管理焦点，非模态侧栏不错误锁焦点。动画遵循减少动态效果设置。
- P4分隔条可聚焦、方向键调整、恢复默认；拖动受主表预算保护，抽屉不拖动分栏，不持久化宽度；窗口缩小后重新约束宽度。

## 数据安全、验证和验收层级

- 只用隔离数据库、临时资料与输出进行未来写入验收；不使用正式用户数据，不修改／删除原始PDF，不通过退出或文件缺失释放图号。必要时对隔离样例原文件做前后哈希核对。
- UI改造不修改Schema、迁移或业务API；导航／折叠／调宽／只读查看不能引入扫描、导入、删除、占号或恢复写请求。现有写动作仍经原确认和服务保护。
- 后续按阶段运行相关renderer／交互回归、类型检查、生产renderer与Main/API构建及隔离E2E，记录实际输出；不新增数据库迁移任务。
- 新问题、环境／依赖问题、旧Mock失败和未执行分开列。旧记录outbound-mock 1、暂停product-bom-roundtrip 5、recovery-mock 1不得删除或改成通过以凑全绿。
- 分别报告设计批准、阶段实现、自动验证、桌面烟测、人工视觉／交互验收和最终发布验收；每一层仅凭对应证据升级。
- 完整恢复应用效果、生产权限及稳定性仍是独立未完成门禁，本轮UI通过不关闭它们。正式数据操作和master合并需另有明确授权。
