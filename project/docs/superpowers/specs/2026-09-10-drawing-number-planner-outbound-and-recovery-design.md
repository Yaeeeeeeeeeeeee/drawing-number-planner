# 图号规划器——真实使用修正、外发资料与安全恢复 Design Document

**日期：** 2026-09-10

**状态：** 待用户确认，禁止据此直接实施

**调查基线：** `codex/real-usage-acceptance-corrections` / `948fb5bb89ee332fa2fbf559e2a4d72ceb2269a0`

**当前数据库：** Schema v9

## 1. 目标与边界

本轮在不改变正式图号算法、历史永久占号和资料批次规则的前提下，补齐产品、图号、二维码和 BOM 的实际维护能力，并正式建设“外发资料”模块。桌面端增加安全恢复入口，使界面异常、API 异常和长任务响应缓慢时不再依赖任务管理器。

本轮不开发服务器同步、邮件直接发送、二维码图片反向解码、自动修改历史 PDF、自动重命名全库、多用户权限或自动覆盖 BOM。

以下规则继续保持：

- 正式图号结构、外观码、解析、查重和流水号推荐不变；
- 已确认历史图号永久占号，停用、文件缺失和清理文件索引均不释放号码；
- 文件实例以资料根目录内规范化相对路径唯一，不按图号、文件名或内容去重；
- 扫描、打包和预览只读源文件，不移动、不删除、不重命名原始资料；
- 产品档案继续作为图号、BOM、PDF、二维码和外发资料的统一产品身份；
- 二维码业务状态、文件存在状态和扫描匹配状态独立；
- “当前使用”由资料批次顺序决定，不使用 PDF 修改时间。

## 2. 现状调查

### 2.1 产品档案

- `ProductService`、仓储、路由、前端 API 和页面仅实现 `deactivate`。
- 已停用产品没有重新启用入口，也没有删除接口。
- 当前更新保护只检查正式图号引用，删除所需的完整引用调查尚不存在。
- 产品可能被以下关系引用：其他产品的参考来源、正式图号及其来源产品、历史图号、资料批次、BOM、产品二维码。PDF 通过图号或资料批次间接关联。
- 因此启用不需要 Schema 修改；删除应先返回分模块引用摘要，再由事务内相同条件复核并删除。任何业务引用存在时禁止物理删除。
- 系统自动为新产品建立的“未启用、无网址、无文件、无 BOM 引用”的默认二维码只是占位资料，不应导致所有产品永远无法删除。删除无业务引用产品时可在同一事务内先删除这些空白占位二维码；已启用、已编辑、有关联文件或 BOM 引用的二维码仍属于真实业务引用并阻止产品删除。

### 2.2 图号库分页、筛选和长路径

- 后端 `GET /api/drawings` 已支持 `page`、`pageSize`，仓储也正确使用 `LIMIT/OFFSET`。
- 页面没有 `page`、`pageSize` 状态，查询始终不传分页参数，所以后端每次返回默认第 1 页 20 条。这是“128 条但只能看第一页”的直接根因。
- 页面产品类别目前是自由文本并长期占据基础筛选区；外观和资料批次筛选尚未进入查询类型和路由。
- 通用表格单元格使用 `white-space: nowrap`，表格容器允许横向滚动。详情中的路径虽可换行，但主列表和 BOM 表仍可能被长内容撑宽。

### 2.3 图号删除边界

当前只有业务状态变更，没有删除接口。必须区分：

1. **正式规划图号：** 仅 `reserved`、从未关联 PDF、未进入任何 BOM、未被其他图号作为上一版/来源引用时允许删除。删除代表撤销一次误占号，号码可重新推荐。
2. **正式使用或作废图号：** 不允许物理删除，继续永久占号。
3. **历史已用图号：** 不提供普通物理删除。它是已确认占号事实；文件消失或清理索引不改变该事实。
4. **PDF 文件实例：** 当前缺失时可清理索引；这不是删除图号，也不释放号码。
5. **待确认扫描结果：** 尚未进入历史已用图号表，不占号，可随文件索引清理。

删除失败返回结构化引用摘要，例如 PDF 数量、BOM 记录、后继图号或来源图号，而不是统一显示“无法删除”。

### 2.4 二维码

- Schema v8/v9 已有可扩展 `qr_purposes`、`product_qr_codes`、`qr_code_files`。
- 默认用途已包含 `User Manual`、`Warranty`、`Recipe`；Recipe 通过产品类别“空气炸锅”映射。2026-09-10 的只读数据快照中 4 个空气炸锅产品均已有 Recipe 业务记录，因此问题不是迁移漏建，而是页面缺少新增/删除和用途管理入口。
- 当前业务接口只支持列表、详情、修改名称/网址、启停和人工关联文件，不支持新增或删除。
- 当前识别正则只接受字面量 `（网址编码）` 或 `（二维码的网址编码）`，不能可靠识别 `ZU70SD-User Manual（qagp85g）.pdf`。
- 当前目录要求文件正好位于 `{产品类别}\{SKU}-{型号}\文件`；该约束符合型号根层级规则。
- 当前 Warranty 特殊地忽略大小写，其他用途大小写敏感，规则不一致。

### 2.5 BOM

- Schema v9 已有产品级快照、业务变更日期、提交时间、生效批次、材质、尺寸、位置、图片/图示、沿用来源和二维码引用。
- “添加 BOM / 查询 BOM”已经分开，数量只保留兼容字段。
- `bom_items.drawing_id` 仍为非空外键，只能引用 `drawing_numbers`；候选查询也只读正式规划图号。这是无法录入历史 BOM 的直接原因。
- BOM 二维码当前只选择“同产品且启用”的现有二维码，业务方向正确，但文案“关联二维码”容易被理解成在 BOM 建立或匹配二维码文件。
- 查询页面没有删除 BOM 变更记录；快照链和 `bom_current` 使直接删行会破坏当前版本指向或上一版关系。
- 添加和查询页面的项目选择都直接显示全部项目，没有先按主类别过滤。

历史 BOM 采用同一套 `bom_versions/bom_items` 查询体系，不另建平行数据库。已与所选产品正式关联的历史图号可作为历史 BOM 候选；当前为“已停用”时仍可用于补录过去事实，但必须明确标记。不得用目录文字猜测未确认产品归属。当前 BOM 仍不默认选择已停用历史图号。

### 2.6 资料批次与“当前完整包材”

现有 `MaterialBatchService` 能：

- 依批次序号选择最新有效批次；
- 展示单批次转曲后文件；
- 聚合一个图号出现过的批次。

它尚不能计算跨批次沿用后的当前完整组合。新计算规则为：

1. 只使用同一正式产品目录下、`recognized`、当前存在且序号明确的批次；
2. 按 `sequence_number` 从旧到新排序，序号相同则视为歧义，不自动选择；
3. 每个“物料槽位”以完整图号去掉末尾流水号后的编码前缀标识，即品牌、品类尺寸、外观、颜色、主类别、项目明细组合；
4. 后续批次出现同一槽位的新图号时替换旧图号；没有出现则沿用上一批；
5. 同一批次同一槽位出现多个不同图号时标记冲突，生成 ZIP 前必须人工处理；
6. 批次中没有某项目不能推断为“停用”，因此 V1 继续沿用。用户可在打包预览中取消勾选。未来若需表达永久移除，应另增明确业务状态，不从缺席猜测。

“本次变更资料”不是简单打包选中目录的全部文件。系统先计算选中批次前后的有效组合，只默认选择在该批次新增或替换了图号的槽位；同一图号只是被复制到新批次时视为沿用，不算本次变更。首批没有前序批次时全部视为新增。若同一图号在不改版本号的情况下替换了内容，系统标记“同号内容变化，需确认”，由用户在预览中决定是否外发。“当前完整包材资料”使用累积结果，并保留每项来源批次。

### 2.7 外发资料现状

- 导航只有禁用占位项，没有领域服务、接口或页面。
- `AppPaths` 已预留应用数据目录下的 `exports`，但没有用户可配置的外发输出目录。
- 项目没有显式 ZIP 写入依赖。
- 可直接复用：产品、品牌字典、资料批次、PDF 文件实例、二维码业务记录、工作区相对路径解析和桌面“打开位置”能力。

### 2.8 Excel 模板调查

调查文件：`C:\Users\Administrator\Desktop\包材资料更新-沟通模版.xlsx`。只读取“首批包材资料”和“更新包材资料”工作表，其他工作表不属于本轮需求。

#### 名称规则

| 类型 | Excel 业务词 | 本轮确定名称 |
|---|---|---|
| 首批 | `【包材资料-{日期}】` | `D&D - {品牌} {型号}{产品类别} 【包材资料-{创建日期}】` |
| 更新 | `【更新包材资料-{日期}】` | `D&D - {品牌} {型号}{产品类别} 【更新包材资料-{创建日期}】` |

Excel 将 `D&D -` 放在邮件主题前缀，而用户已明确要求压缩包名称也包含该前缀，因此压缩包和默认邮件主题使用同一个完整名称。日期采用本机创建 ZIP 当天的中文年月日。

#### 联系人

工作表按供应商列维护公司、收件人和抄送人，不同供应商可能有多个收件人，更新资料的抄送名单也可能不同。联系人不写死在代码或模板中；系统建立独立联系人库，Excel 仅作为字段和初始人工录入参考。

#### 首批正文

共同结构为：公司抬头、称呼、附件说明、可选说明、异常联系、回执提示、签名。现有变体包含：

- 铭牌为初稿并等待 METI 后更新；
- 邮件大小受限，压缩包拆成多个附件；
- 完整交付可覆盖以前资料；
- 普通首批正文。

这些内容设计成可选附加段落，不让特殊说明默认进入每封邮件。

#### 更新正文

共同结构为：公司抬头、称呼、更新资料说明、本次修改内容、每项新文件、补充说明、请供应商更新并回传确认件、异常联系、回执提示和签名。具体变更描述必须由用户输入并可编辑，系统仅自动带入产品、文件清单和模板段落。

### 2.9 安全恢复现状

- Electron Main Process 直接在自身进程内调用 `startServer()`，Fastify、SQLite 与窗口壳共用主进程。
- Renderer 仅暴露打开 PDF/二维码文件的 IPC，没有任务、健康状态或恢复 IPC。
- 扫描接口是一个持续到完成的同步 HTTP 工作流，仅用内存布尔值防止并发，没有任务 ID、进度或取消能力。
- 界面卡死时普通 React 按钮不能工作；原生窗口菜单仍可能工作。但如果主进程也被同步数据库事务或服务故障阻塞，当前架构无法单独重启 API。

要满足“Renderer 完全冻结时仍可恢复”和“单独重启 API”，必须把本地 API/数据库服务移到 Electron 管理的独立子进程或 Utility Process。这是本轮唯一重大架构调整，实施前需要用户在批准本文时明确批准。

## 3. 目标架构

### 3.1 领域关系

```text
产品档案
├── 正式规划图号 ── 0..N PDF 文件实例
├── 历史已用图号 ── 0..N PDF 文件实例
├── 资料批次 ────── 0..N PDF 文件实例
├── 二维码业务记录 ─ 0..N 二维码文件实例
├── BOM 快照 ────── 正式图号或历史图号 + 可选二维码引用
└── 外发记录
    ├── ZIP 文件清单快照
    └── 邮件草稿 + 联系人快照
```

### 3.2 Schema v10：维护与历史 BOM

v10 采用小范围增量迁移：

- `bom_items.drawing_id` 改为可空；
- 新增 `historical_drawing_id INTEGER NULL REFERENCES historical_drawing_numbers(id) ON DELETE RESTRICT`；
- 增加 XOR CHECK，保证每个 BOM 项目恰好引用一种图号；
- `bom_versions` 增加 `deleted_at TEXT NULL`、`deleted_reason TEXT NULL`；
- `qr_code_files` 增加 `detected_identifier TEXT NULL`，保存括号中的网址编码/标识，不把它当成网址；
- 增加必要索引，不改变正式图号、历史图号、产品、文件路径或资料批次数据。

旧 BOM 行全部保持正式图号引用。迁移前备份；迁移后逐表校验行数、XOR 约束、外键、当前 BOM 指向和 v9 字段。

产品启用/删除、正式预留图号删除、图号分页与样式、二维码新增/删除本身不需要新增表。

### 3.3 BOM 删除语义

- 默认“删除”只软删除选中的 BOM 变更记录。
- 删除非当前记录时，后继快照仍保留原 `previous_version_id` 作为审计链；UI 查询跳过已删除记录。
- 删除当前记录时，确认框明确显示将回退到的上一条未删除快照；事务内更新 `bom_current`。没有上一条时删除 `bom_current`。
- 新增快照的内部 `version_number` 始终取该产品全部快照（含软删除）最大值加一，避免回退后与已删除记录发生唯一键冲突。
- “删除整个型号 BOM”放在独立高风险入口，需输入型号二次确认；它只软删除该型号全部快照，不删除产品、图号、二维码或文件。
- 恢复软删除不属于本轮 UI，但数据保留，避免错误操作不可恢复。

### 3.4 二维码识别

可靠自动匹配必须同时满足：

1. 文件位于 `{产品类别}\{SKU}-{型号}\` 型号根目录；
2. 文件名符合 `{型号}-{用途英文}（{非空标识}）.{扩展名}`；
3. 型号目录唯一对应一个正式产品；
4. 用途英文与启用用途做忽略大小写、压缩连续空格后的精确匹配；
5. 产品与用途组合唯一。

例如 `ZU70SD-User Manual（qagp85g）.pdf` 得到型号 `ZU70SD`、用途 `User Manual`、标识 `qagp85g`。不解析二维码图像，不根据标识猜网址。任一条件不唯一时进入待确认。

新增二维码从现有 `qr_purposes` 选择用途；如需新用途，在二维码模块的“用途管理”中新增，不改数据库枚举。一个产品同一用途保留一条业务记录。

删除二维码仅在没有二维码文件实例、没有 BOM 引用时允许；否则返回具体引用原因并建议停用。系统自动生成且从未配置的停用占位记录可随无引用产品一起删除。

### 3.5 外发资料

#### 资料打包

流程：

`资料类型（首批/更新） → 打包模式 → 品牌 → 产品 → 资料批次 → 文件预览 → 选择输出目录 → 生成 ZIP`

- 产品选定后自动带出 SKU、型号、产品类别和品牌；品牌仅用于核对，不允许制造与产品档案矛盾的数据。
- “本次变更资料”取相对前序有效组合新增或替换的槽位，并使用选中批次中的具体转曲后文件实例；同图号跨批次复制默认不重复外发。
- “当前完整包材资料”按 2.6 的沿用规则计算。
- 文件清单显示项目、图号、来源批次、文件名、正常/沿用/缺失/冲突。
- 只允许勾选当前存在的转曲后文件；缺失和冲突阻止生成。
- ZIP 去重键是规范化实际路径。不同批次的同图号不是扫描重复，但同一个打包结果只加入最终被选中的具体文件实例一次。
- ZIP 先写入同目录临时文件，成功关闭并核对条目数后原子改名；取消或失败删除临时 ZIP，不触碰源文件。
- 外发输出根目录独立配置并保存到设置文件。数据库只保存相对于输出根目录的 ZIP 路径。

#### 邮件撰写

- 不连接邮箱、不发送邮件。
- 联系人库字段：公司、联系人姓名/称呼、邮箱、默认类型、启用状态、备注。
- 模板字段：资料类型、主题模板、正文模板、启用状态。
- 可选段落单独管理；首批可选择“铭牌初稿”“拆分附件”“覆盖旧资料”等。
- 更新资料提供可编辑“变更内容”和自动文件清单。
- 签名为可配置资料，初始默认值采用用户确认的当前签名。
- 主题默认等于压缩包名称，允许人工修改。
- 支持分别复制收件人、抄送、主题、正文和全部复制。
- 保存邮件草稿与最终文本快照，但不把联系人地址或正文写死在程序源代码。

### 3.6 Schema v11：外发资料

新增独立表，不重构现有业务表：

- `outbound_contacts`：公司、称呼、邮箱、默认收件类型、状态、备注、时间；
- `outbound_email_templates`：首批/更新模板、主题模板、正文模板、状态、时间；
- `outbound_template_blocks`：可选附加段落；
- `outbound_signatures`：签名文本、是否默认、状态、时间；
- `outbound_packages`：产品、资料类型、打包模式、选中批次、ZIP 相对路径、名称、创建时间、状态；
- `outbound_package_items`：项目、逻辑图号来源、PDF 文件实例、来源批次、文件名和相对路径快照；
- `outbound_email_drafts`：关联包、收件人/抄送/主题/正文快照、创建和修改时间。

联系人、模板和签名是资料；外发包及邮件草稿是业务快照。后续基础资料发生变化不改写已生成的历史外发记录。

### 3.7 安全恢复与长任务

推荐并需要审批的架构：

```text
Electron Main Process
├── 原生窗口菜单“安全恢复”
├── Renderer 心跳与窗口重载
├── Local Service 子进程生命周期
└── 完整应用 relaunch

Local Service 子进程
├── Fastify + SQLite
├── Task Registry
├── 扫描/索引/打包/导入任务
└── 进度、取消与事务边界
```

桌面左下角显示“系统正常 / 正在处理 / 本地服务异常”和“安全恢复”。Renderer 可用时显示四项操作；Renderer 冻结时通过 Windows 原生菜单 `应用 → 安全恢复`执行。

操作语义：

- **终止当前任务：** 向服务任务发送取消信号。扫描在提交数据库前取消；ZIP 在原子改名前取消；迁移一旦进入事务提交阶段不可中途取消。
- **重新加载界面：** Main Process 调用窗口重载，不改数据库或文件。
- **重启本地服务：** Main 终止并重启服务子进程，等待健康检查成功后通知 Renderer 重新获取 session token。
- **完整恢复应用：** 停止可取消任务、关闭服务、`app.relaunch()` 后退出当前壳。

任务接口采用 `POST /api/tasks/{kind}` 创建、`GET /api/tasks/:id` 查询、`POST /api/tasks/:id/cancel` 取消。状态为 `queued/running/finalizing/completed/cancelled/failed`，进度记录已处理数和总数。短暂延迟只显示“响应较慢”，不自动强杀。

数据库安全边界：

- 文件扫描、清库和迁移在提交前构造结果，最终以短事务完整提交；
- 正在 `finalizing` 的任务不接受取消，避免半提交；
- ZIP 只写临时文件，成功后原子发布；
- 服务崩溃后启动时清理过期临时 ZIP，并把遗留运行中任务标为失败；
- 恢复操作绝不删除正式图号、历史占号、BOM、产品、字典、二维码、扫描批次或本地文件。

## 4. UI 设计

### 4.1 导航

日常工作：

1. 图号规划 / 更新包材
2. BOM 管理
3. 外发资料
4. 二维码管理

基础资料保持图号库、产品档案、PDF 文件中心、编码字典、迁移检查。左下角固定运行状态与“安全恢复”。

### 4.2 产品档案

每行显示 `编辑｜停用/启用｜删除`。删除先弹出引用检查结果；有引用时只提供“知道了”和“停用产品”，无引用时二次确认后删除。编辑与历史候选确认继续在当前记录下方展开。

### 4.3 图号库

- 基础筛选：型号/SKU、图号、资料批次。资料批次条件在按图号视角中通过文件实例与批次关系过滤，在按批次视角中直接过滤批次列表。
- 更多筛选：产品类别下拉、品牌、主类别、项目明细、颜色、外观、源文件状态、转曲后状态、图号状态。
- 主类别改变时只显示其项目明细。
- 页脚显示总数、上一页、紧凑页码、下一页和 20/50/100 条每页。
- 筛选、切换视角或资料批次时页码重置为 1；单纯打开详情不重置。
- 文件名为主信息，路径为可换行次级信息，操作按钮固定在右侧。任何单条文件记录不产生横向滚动。
- 图号详情显示“修改状态｜删除”，删除前展示可删除性和引用原因。

### 4.4 二维码

列表顶部增加“新增二维码”。产品行内显示 `查看/编辑｜启用/停用｜删除`。新增表单选择产品、用途、名称、状态和可选待确认文件。用途管理作为二维码页的次级入口。

详情明确分三项：业务状态、文件状态、扫描匹配状态。关联文件规则旁显示简短说明，不展示图像解码能力。

### 4.5 BOM

- 添加页增加“录入类型：当前 BOM / 历史 BOM”。两者写入同一快照体系。
- 每行先选主类别，再选项目明细；再选择“正式规划/历史已用”来源下的图号。
- “使用二维码”默认折叠，仅需要时从同产品现有二维码中选择，不在 BOM 新建或关联二维码文件。
- 查询页保留长路径换行和“打开位置”，记录行增加“查看｜删除”。
- “删除整个型号 BOM”与单条记录删除分开，并置于低频危险操作区。

### 4.6 外发资料

页面二级导航为 `资料打包｜邮件撰写｜联系人`。邮件模板和签名放在邮件撰写的设置入口，不增加顶级导航。

## 5. API 与错误处理

- 所有写接口继续使用共享 request 层和写入令牌刷新机制。
- 启用、删除、取消和恢复返回 JSON；204/空响应仍由共享客户端安全处理。
- 删除冲突统一返回 `409` 和 `references` 明细。
- 打包预览与真正生成都在服务端重新校验路径、存在状态、转曲状态和选中批次，防止页面数据过期。
- 浏览器预览可以查看和生成邮件文本，但打开文件、选择本机目录、生成 ZIP 和安全恢复只在桌面端开放，并显示明确提示，不显示 `Failed to fetch`。

## 6. Schema 影响分类

### 不需要 Schema 修改

- 产品启用、引用摘要和受保护删除；
- 图号分页、筛选布局、产品类别下拉、外观筛选和长路径样式；
- 受保护删除仅限未使用 `reserved` 正式图号；
- 二维码页面 CRUD 入口（现有表可容纳）；
- 主类别 → 项目明细 UI；
- BOM 路径展示和二维码文案；
- Renderer 左下角状态与原生菜单外壳。

### Schema v10 小范围 migration

- BOM 项目支持正式图号或历史图号；
- BOM 变更记录软删除；
- 二维码扫描保存括号标识。

### Schema v11 新增独立表

- 联系人、邮件模板、可选段落、签名；
- 外发包、文件清单快照和邮件草稿。

### 重大架构调整审批项

- 将 Fastify/SQLite 本地服务从 Electron Main Process 移到受 Main 管理的独立子进程；
- 将扫描、清库、导入和 ZIP 打包改为可查询、可取消的任务。

该调整不改变业务 Schema，但会改变桌面启动、健康检查、令牌刷新和进程生命周期。没有此调整，无法可靠保证 Renderer 完全冻结时仍能“重启本地服务”。

## 7. 数据兼容与迁移安全

- v9 → v10 和 v10 → v11 分开备份、迁移、校验和回滚测试；
- 任何迁移失败均回滚当前事务，保留备份和原数据库；
- 正式图号、历史图号、产品、PDF 路径、资料批次、二维码和 BOM 现有行数逐项校验；
- v10 旧 BOM 保持 `drawing_id`，`historical_drawing_id` 为空；
- 软删除列默认空，不改变现有 BOM 可见性；
- 二维码现有文件标识为空，下一次扫描按文件名补齐；
- 外发新表初始为空；不自动导入 Excel 联系人；
- 当前签名作为可编辑默认资料初始化，之后由用户维护。

## 8. 验收标准

- 已停用产品可启用；无引用产品可删除；有引用产品显示具体模块；
- 图号库可浏览全部 128 条等任意结果，20/50/100 分页正确；
- 长路径自动换行，文件记录内部无横向滚动；
- 图号删除不误删历史占号，不释放已使用或作废号码；
- Recipe 对空气炸锅正确默认存在，并可新增其他用途二维码；
- `ZU70SD-User Manual（qagp85g）.pdf` 可可靠解析，歧义文件待确认；
- 历史 BOM 可引用已确认且属于该产品的历史图号；
- 删除单次 BOM 正确回退当前快照，不误删整个型号；
- BOM 项目选择为主类别 → 项目明细；
- 首批和更新 ZIP 名称分别使用“包材资料”和“更新包材资料”；
- 两种打包模式均先预览，仅打包存在的转曲后文件；
- 当前完整包材显示每项来源批次和沿用状态；
- 联系人、主题、正文和签名可配置与复制，不发送邮件；
- Renderer 冻结时可通过原生菜单重新加载或完整恢复；
- 扫描和打包显示进度并可安全取消；
- 全程不修改 `E:\包材资料` 中的原始文件。

## 9. 明确不做

- 邮件发送和邮箱账号接入；
- 服务器/NAS 自动同步；
- OCR 或二维码图片解码；
- 自动推断某项目已永久移除；
- 自动生成或覆盖 BOM；
- 自动修改、移动、删除或重命名历史文件；
- 多人权限、审批流和复杂工作流引擎。
