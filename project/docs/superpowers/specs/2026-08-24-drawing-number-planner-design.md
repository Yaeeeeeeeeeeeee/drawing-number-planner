# 图号规划、BOM 及包材文件管理系统设计

日期：2026-08-24  
版本：V1.0  
状态：已批准，进入实施计划

## 1. 目标与边界

本系统是单人长期使用的 Windows 公司内部工具。系统负责图号字典、产品档案、永久占号、BOM 版本、PDF 文件匹配、批量重命名、新型号参考复制、外发打包和外发历史。

V1 不实现复杂权限、审批、通知、ERP/MRP、采购库存成本、OCR/AI 转曲识别、跨型号自动共用图号、云同步、服务器 API、自动上传、自动双向同步、微服务、消息队列或插件系统。

本地资料库是日常工作主库，公司服务器仅作为用户定期人工同步/备份的目标。所有 PDF 扫描、匹配、复制、重命名和外发打包均针对本地资料根目录执行。

## 2. 核心业务不变量

图号结构保持为：

`品牌码.品类尺寸码.外观码+颜色码.主类别码+项目明细码+版本流水号`

示例：`02.0404.010.0401001-SAMKYO-ZC200白色-LOGO`

- 正式资料每次修改都生成下一流水号；不使用 Rev.A/Rev.B。
- 已占号、正式使用和已作废的号码均永久占用，不重新分配。
- 跨型号不共用图号；新型号基于旧型号时仍生成全新图号。
- 同型号不同颜色共用物料时，BOM 直接引用白色图号。
- 转曲前和转曲后 PDF 属于同一图号，不因转曲生成新图号。
- 文件名包含完整 `（转曲）` 时识别为转曲后文件，否则为转曲前文件；不解析 PDF 内容。
- 编码字典值被正式记录引用后只能停用，不能改写历史含义或硬删除。

## 3. 技术架构

采用 Electron + React + TypeScript + SQLite：

```text
Electron 桌面窗口 / 开发期浏览器
                ↓
            React 界面
                ↓
      本机 TypeScript 业务服务
          ↓                 ↓
      SQLite 数据库     用户指定资料根目录
```

- Electron 负责桌面窗口、生命周期和系统集成。
- React 负责全部用户界面；桌面窗口和浏览器预览使用同一构建产物。
- 本机服务绑定 `127.0.0.1`，负责业务规则、数据库和文件操作。
- 桌面窗口和浏览器预览连接同一真实服务、真实数据库，不使用 Mock 数据冒充完成。
- 服务限制允许来源，并为每次启动生成本地访问令牌，避免其他网页误调用文件写操作。
- 项目保持单体结构，不引入微服务或外部基础设施。

## 4. 数据模型

### 4.1 编码字典

品牌、品类尺寸、外观、颜色、主类别、项目明细和层数分别保存。项目明细隶属于主类别。所有字典项包含编码、名称、启用状态、创建时间和停用时间。

Excel 迁移先产生检查报告；重复编码、缺失名称或不完整映射必须人工确认，不自动改写源文件。

### 4.2 产品档案

产品档案保存品牌、型号、品类尺寸、产品类别、默认外观、启用状态和可选参考来源型号。不同型号始终是不同产品记录。

### 4.3 图号记录

图号记录保存完整图号、显示文件名、全部编码段、流水号、产品、颜色、主类别、项目明细、状态、前一版本图号、变更原因、参考来源型号/图号、创建时间和备注。

完整图号设置数据库唯一约束。批量占号在单个数据库事务内完成，全部成功或全部失败。流水号按除最后三位之外的完整编码前缀递增。

状态为：

- `reserved`：已占号，资料可能尚未齐全；
- `active`：正式使用；
- `voided`：已作废但永久保留。

三种状态均阻止号码再次分配。

### 4.4 BOM

BOM 由型号、颜色和不可变版本组成。修改当前 BOM 时复制出新版本，再执行新增、替换或移除；旧版本只读保留。BOM 项保存项目明细、图号、数量、备注和是否引用白色物料。

同一型号和颜色只有一个当前 BOM 版本。外发历史不依赖后续 BOM 状态，而保存当时的独立快照。

### 4.5 PDF 文件

文件记录保存相对于“资料根目录”的相对路径、实际文件名、关联图号、转曲类型、文件大小、最后修改时间和最近扫描时间。PDF 本体保存在用户指定的本地资料根目录，不写入数据库。

资料根目录是可修改的本机设置，例如 `D:\D&D包材资料\`，但该示例不得作为默认值写死在代码或业务数据中。运行时由集中路径服务把“资料根目录 + 相对路径”解析为实际路径，并拒绝 `..`、盘符注入、UNC 注入或符号链接逃逸等越出资料根目录的路径。

数据库中的业务文件路径不得保存盘符、用户名或当前电脑的绝对路径。资料库迁移到其他磁盘或映射盘时，只修改资料根目录设置，不修改图号、BOM 或文件记录。

默认目录建议为 `{品牌}\{产品类别}\{型号}\...`，但目录生成规则必须集中在单一目录策略模块中。图号、BOM 和文件关联以数据库为准，扫描和匹配不得依赖文件必须位于固定层级。

只有文件名包含唯一、完整图号时才自动匹配；匹配不到或存在歧义时不自动关联。

### 4.6 操作历史

- 重命名批次保存每项原路径、新路径、执行状态和撤销状态。
- 外发记录保存日期、初次/更新、型号、图号清单、实际文件名、压缩包名、缺失项和操作人。
- 新型号参考复制保存来源型号、来源图号和目标图号，但来源信息不进入外发文件名。

业务记录原则上不硬删除，通过停用或作废保持审计链。

## 5. 页面结构

整体沿用已批准的左侧导航、中央工作区和右侧详情栏方向，保持高密度但清晰的内部工具风格。

### 5.1 图号库

提供关键词搜索和品牌、型号、类别、项目、颜色、状态组合筛选。结果表右侧显示图号详情、前后版本、关联 PDF 和 BOM 使用情况。正式记录不能原地修改，可从当前记录发起新版本。

### 5.2 图号规划

选择产品信息后，在批量项目表中添加多个主类别、项目和颜色。系统实时显示预计图号和推荐流水号，统一查重，确认后一次性占号。任一行冲突时整批不提交。

### 5.3 BOM 管理

按型号和颜色显示当前 BOM。允许新增项目、替换图号和引用白色图号。保存时生成新 BOM 版本，并展示与上一版本的增加、替换和移除差异。

### 5.4 PDF 文件中心

扫描指定目录，展示已匹配、无法确定图号和冲突文件。同一图号分别显示转曲前/后 PDF。批量重命名和新型号参考复制必须先显示完整预览。

### 5.5 外发打包

选择型号、颜色和初次/更新，从当前 BOM 生成候选清单，只选择转曲后 PDF。缺失文件明确警告；用户确认最终清单后生成固定命名 ZIP。

### 5.6 外发历史

按型号、日期和初次/更新检索外发快照。当前 BOM 变化不影响历史记录。

### 5.7 编码字典

提供新增、停用和引用检查；不提供删除已使用编码的入口。

### 5.8 设置与备份

仅维护应用数据目录、备份目录、资料根目录、默认导出目录、操作人、备份恢复和 Excel 迁移检查。资料根目录与应用数据目录相互独立。

## 6. 文件工作流与故障处理

### 6.1 批量重命名

固定流程：扫描 → 预览 → 重名/非法字符/匹配检查 → 用户确认 → 执行前再次检查 → 逐项执行并记录。

中途失败时立即停止后续项目，批次标记为部分完成。用户可以在重新校验后撤销已完成项或继续未完成项。文件已被外部移动或目标路径冲突时禁止强制覆盖。

### 6.2 新型号参考复制

先在一个数据库事务中为新型号占用全部目标图号，再复制选中的来源转曲前 PDF。复制使用临时文件，完成后再改为正式名称。若复制失败，图号仍保持已占号，并允许继续复制，不释放号码。

### 6.3 外发打包

ZIP 先在临时位置生成并复核清单，成功后移动至正式导出目录并写入外发历史。缺少转曲后 PDF 时默认阻止继续；用户明确忽略后才允许打包，同时记录缺失项目。

## 7. 数据安全

默认应用数据目录结构如下；它不等同于业务 PDF 的资料根目录：

```text
图号规划器数据/
├─ planner.db
├─ backups/
├─ logs/
└─ exports/
```

- SQLite 启用外键、事务和 WAL。
- 每天首次启动备份数据库。
- 数据库迁移、Excel 导入和恢复前强制备份。
- 默认保留最近 30 个日常备份。
- 恢复前先备份当前数据库。
- 备份失败时禁止继续数据库升级或批量导入。

## 8. 测试与验收

编码生成、流水号分配、BOM 版本、文件匹配、重命名撤销和外发打包使用测试驱动开发。每个阶段结束运行全部测试、构建检查、数据库迁移检查、桌面启动检查和浏览器预览检查。

端到端验收至少覆盖：

1. ZC100 灰色 BOM 引用白色说明书图号，不生成灰色新图号。
2. LOGO `...001` 修改后生成 `...002`，`...001` 永久保留。
3. 同图号的普通 PDF 与 `（转曲）` PDF 识别为转曲前/后。
4. ZC220 参考 ZC100 时只复制来源转曲前 PDF，并生成 ZC220 全新图号。
5. 生成指定格式的初次外发 ZIP 名称。
6. 后续只替换铭牌/说明书时生成更新包，同时保留初次外发历史。

未完成的功能不会以假按钮或假数据标记为完成。阶段内尚未开放的入口必须明确显示状态，且不计入该阶段验收。

## 9. 分阶段交付

1. 基础项目、真实桌面/浏览器启动、数据库基础、字典、产品档案和图号库。
2. 图号规划、查重和批量占号。
3. BOM 与白色图号共用。
4. 资料根目录设置、集中路径解析与目录策略、PDF 扫描、文件匹配和转曲识别。
5. 旧型号底稿到新型号新图号。
6. 批量重命名、日志和撤销。
7. 初次/更新外发打包和外发历史。
8. 端到端回归、数据迁移验证和 UI 收口。

每个 Phase 开始后，阶段内常规实现无需再次确认；阶段完成后必须提供可启动桌面版和浏览器预览供用户验收。编码规则、核心数据结构、主要页面方向或基础设施发生重大变化时，仍须暂停并按总需求说明原因、影响和不变更的后果。

未来若增加“本地资料库 ↔ 公司服务器资料库差异比较”，只比较本地新增、本地修改、服务器独有、文件一致和潜在冲突，并由用户确认后同步。该能力不属于 V1，当前不得为它预先引入同步服务或复杂基础设施。
