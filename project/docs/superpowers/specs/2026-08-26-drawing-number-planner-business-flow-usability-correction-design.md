# 图号规划器：业务流程与可用性修正阶段设计

日期：2026-08-26  
起始稳定基线：`master 55b6af6e49ae4408da593bd07f08393653b23a9f`  
状态：待用户确认，不进入代码实施

## 1. 阶段目标与边界

本阶段位于下一正式 Phase 之前，不重新打开已经验收的 Phase。目标是让三个高频流程真正可用：

1. 更新型号包材；
2. 维护当前 BOM；
3. 准备/外发资料的前置导航与数据关系。

本阶段不实现完整外发资料、二维码、服务器同步、批量重命名或新的“产品工作台”。不修改已经正确工作的完整图号生成、解析、查重和下一流水号算法。

## 2. 调查结论

### 2.1 多模块“停用 → 请求失败”

根因位于共享前端 API 客户端，而不是字典页或产品页。

- 前端在首次写操作时调用 `/api/session` 获取本次后端启动的写入令牌，并把 Promise 永久缓存；
- 后端每次启动会生成新令牌；
- 后端重启但浏览器页面未刷新时，前端继续发送旧令牌；
- 所有 POST/PUT/PATCH/DELETE 均收到 `401 INVALID_TOKEN`，因此停用、保存设置、保存 BOM、扫描等共享写操作都可能失败；
- 现有测试只验证首次取令牌，没有覆盖“后端重启后旧令牌失效”的恢复路径。

设计：共享请求层收到 `401 INVALID_TOKEN` 时，仅对本次请求清空令牌、重新建立安全会话并重放一次。最多重试一次，其他 401/403 不自动重试，防止循环和掩盖真正权限错误。

### 2.2 BOM 候选为空与交互问题

当前候选查询规则是：同一 `product_id`、同一项目明细、状态为 `reserved/active`，并按 BOM 颜色选择同色图号或明确选择白色图号。它没有检查源文件或转曲后文件是否存在。

实际验收数据快照显示：

- 产品 2 个；
- 正式规划图号 3 个；
- 历史扫描已用图号 737 个；
- BOM 候选只来自 3 个正式规划图号，不读取 737 个历史占号；
- 当前正式规划图号只覆盖 T40 的白色 PCB 面板、白色铭牌、黑色大外箱；选择其他项目自然为空；
- 白色 BOM 会禁用“引用白色图号”，但 UI 没有说明原因；
- BOM 当前快照允许保存空项目，验收库已有 5 条快照，当前第 5 条为空；
- 明细备注已保存到 `bom_items.notes`，但当前 BOM 和历史明细表没有展示备注列；
- 数量被强制为正整数并参与差异比较，但不符合当前真实业务。

结论：候选为空主要是候选范围和反馈不透明，不是“必须存在转曲后文件”。历史图号永久占用与“可被当前 BOM 引用”是不同概念。历史图号在未确认产品、项目和业务状态前不得自动变成可引用的正式 BOM 物料。

### 2.3 PDF 幽灵记录

当前全量扫描会先把全部 `pdf_files.is_present` 设为 0，再把本次扫描到的路径更新为 1；未再次扫描到的行永久留在索引表。现有 API/UI 没有清理失效索引的能力。实际验收数据中共有 2761 条索引，其中 95 条已标记缺失。

这不是扫描缓存未刷新，而是当前持久化策略的直接结果。`historical_drawing_numbers` 已独立保存永久占号，因此删除 `is_present = 0` 的 `pdf_files` 行不会释放历史图号。

设计：保留“本次扫描后标记缺失”的可审查步骤，并提供单项/批量“清理失效记录”。只允许删除 `is_present = 0` 的文件索引；历史图号表、正式图号表和占号集合一律不删除。

### 2.4 编码字典的真实关系

Excel 导入实现确认：

- 品牌、品类尺寸、外观、颜色、主类别是独立根字典；
- Excel 中“电子元件类、铭牌类、提示贴纸类、印刷件类、包装类”是项目明细列的主类别标题；
- 导入后每个项目明细通过 `parent_id` 关联其主类别；
- 层数从 Excel 独立列导入为 `layer_count`，不参与正式图号字符串，也不是 `project_item.parent_id` 关系的一部分。

按用户最终修正版，字典页面顶部一级入口只显示：品牌、品类尺寸、外观、颜色、主类别。进入“主类别”后，以“主类别 → 对应项目明细”的两栏/主从方式维护；层数放在该业务区内作为辅助字典入口，不再作为顶部平级入口。此调整只改变信息架构，不改 Excel 导入映射、数据库类型或编码算法。

### 2.5 产品身份关系

`products.id` 已经是正式规划图号和 BOM 的外键；历史图号也可选关联 `product_id`。问题主要在 UI 缺乏以产品为中心的跳转和大量历史目录尚未确认到正式产品，而不是各模块已经维护了多套正式产品表。

本阶段继续以 `products.id` 为唯一产品身份。SKU + 型号用于目录识别和用户检索，不以字符串替代外键。PDF 通过正式图号或历史图号关联产品；未匹配文件不强行猜测产品。

## 4. 图号生命周期与文件维护

### 4.1 状态模型

沿用现有数据库枚举，不新建审批系统：

| 数据状态 | UI 文案 | 含义 |
|---|---|---|
| `reserved` | 已占号 | 正式号码已分配，可被 BOM 引用 |
| `active` | 正式使用 | 已确认进入实际使用 |
| `voided` | 作废 | 不再使用，但永久占号 |
| 历史表记录 | 历史已用 | 扫描可靠识别，永久占号；未确认前不等同于正式可用 BOM 物料 |

源文件和转曲后文件是否存在继续由当前文件索引推导，不能由业务状态代替。作废只改变业务状态，不删除图号或文件索引，不释放流水号。

允许的人工状态变化保持简单：`已占号 → 正式使用`、`已占号/正式使用 → 作废`。作废不可在普通 UI 中恢复；如未来确需恢复，另行定义高风险流程。

### 4.2 图号详情

正式图号详情显示：图号、产品、SKU、项目、业务状态、源文件列表、转曲后文件列表、当前 BOM 使用情况、相对路径。

允许：

- 更新业务状态；
- 将当前资料库索引中可靠存在的 PDF 关联到该图号，并明确选择源文件/转曲后文件；
- 打开文件所在位置；
- 对两个文件类型分别显示“已有/缺失”。

本阶段的“关联/登记”不移动、不重命名历史文件。资料根目录外文件的复制导入需要明确目录落点，留在后续文件整理 Phase，避免本阶段暗中实现文件整理。

### 4.3 打开文件位置

浏览器页面没有本机资源管理器权限。Windows 桌面版通过最小 Electron preload + IPC 能力打开资源管理器并选中文件：

1. 渲染层只提交 `pdf_file_id`，不提交任意绝对路径；
2. 主进程从当前数据库/服务解析相对路径，并再次校验 `is_present = 1`；
3. 使用资料根目录安全解析绝对路径，拒绝越界、缺失和不在索引中的路径；
4. 同一图号有多份源文件/转曲后文件时先让用户选择；
5. 浏览器预览明确显示“请在 Windows 桌面版打开文件位置”，不发起失败请求，不显示 `Failed to fetch`。

## 5. BOM 业务设计与确认门槛

当前可访问的 `C:\Users\Administrator\Desktop\bom.xlsx` 包含 Sheet1/2/3，但三个工作表均为空，且没有嵌入图片。当前会话没有可读取的真实 BOM 截图原图。因此以下只映射用户文字需求和现有系统字段，不能替代真实表字段确认。

| 现有 BOM/已确认业务字段 | 系统字段 | 是否保留 | 数据来源 |
|---|---|---|---|

| 品牌、产品类别、品类尺寸、默认外观 | 产品关联字段 | 保留为上下文，不重复录入 | 产品档案/编码字典 |
| BOM 颜色（当前顶层） | 当前 `bom_versions.color_id` | 不再作为顶层；如何落到明细需真实表确认 | 旧 BOM 数据 |

| 数量 | `bom_items.quantity` | 不作为核心 UI 字段；旧数据暂保留默认 1 | 旧系统兼容 |
| 明细备注 | `bom_items.notes` | 保留且当前/历史均展示 | 用户填写 |

| 变更批次颜色分区 | 不建颜色字段 | 不复制 Excel 表现 | 用结构化变更日期/快照表达 |
| 规格、材质、尺寸、供应商等截图列 | 尚未确认 | 不猜测 | 需要用户重新提供真实截图或非空表格 |

### 5.2 BOM 目标模型原则

- BOM 顶层主体是产品，不是产品 + 颜色；
- 颜色/适用范围属于 BOM 明细；具体字段形态必须由真实 BOM 表确认；
- 图号为 `reserved` 或 `active` 即可被引用，文件完整性只提示，不作为隐式门槛；`voided` 不可新增引用；
- 历史扫描图号若尚未转为正式可维护记录，不直接加入 BOM 候选；
- 不向用户展示独立的 BOM V1/V2/V3 体系，内部继续保留不可变快照以支持变更历史；
- 变更日期是用户填写的业务日期，`created_at` 仅作审计；
- 允许软删除错误/测试快照。删除当前快照时回退到最近一个未删除快照；没有可回退快照时该产品显示“尚无当前 BOM”；
- 当前 BOM 和历史详情均显示明细备注；
- 展开历史通过独立背景、边界、标题和业务日期形成清晰层级。

### 5.3 BOM Schema 决策门槛

在用户补充真实 BOM 截图或非空样表，并确认完整字段映射前：

- 不实施产品级 BOM 表迁移；
- 不删除或改写现有 BOM 数据；
- 不为规格、材质、供应商等字段建表；
- 不按传统制造 BOM 猜测数量、单位或层级。

字段映射确认后再冻结目标 Schema 和数据迁移脚本。

## 6. PDF 文件索引清理

新增单项与批量清理操作：

- 只能选择 `is_present = 0`；
- 二次确认显示将删除的索引数量，并明确“历史图号仍永久占用”；
- 清理事务只删除 `pdf_files` 行；
- 不删除 `historical_drawing_numbers`、`drawing_numbers`、BOM 或磁盘文件；
- 清理后重新查询当前页与统计；
- 再次扫描到同一路径时会作为新索引重新建立。

不采用“扫描即自动删除”，保留一次人工复核机会，避免临时盘符/资料根目录不可用造成误清理。

## 7. 编码字典页面

顶部只保留五个一级维度：品牌、品类尺寸、外观、颜色、主类别。

“主类别”视图采用主从结构：左侧选择电子元件类/铭牌类/提示贴纸类/印刷件类/包装类等主类别，右侧只列出其 `parent_id` 对应的项目明细并在此新增、改名、停用。层数作为该业务区的辅助入口显示，但继续使用独立 `layer_count` 数据，不改为图号编码段或项目明细。

## 8. 历史产品候选与迁移批量操作

P2 可直接按历史表中的 `detected_product_category + detected_sku + detected_model` 分组生成候选，不因扫描自动创建正式产品。用户确认时必须补齐品牌、品类尺寸和默认外观，并检查 SKU 唯一性；确认后才创建产品并把可唯一匹配的历史图号关联到 `products.id`。不要求先建新的候选表，除非实施时证明需要保存人工忽略状态。

迁移检查增加全选、多选、批量确认，沿用现有逐项校验和备份事务；任何有歧义或冲突项仍不得批量绕过。

## 9. Schema 影响概览

| 修改 | 是否需要 migration | 说明 |
|---|---:|---|
| 写令牌自动恢复 | 否 | 共享客户端行为 |
| PDF 失效索引清理 | 否 | 使用现有 `is_present` |
| 图号状态维护 | 否 | 复用 `reserved/active/voided` |
| 图号关联当前 PDF | 否 | 复用 `pdf_files.drawing_id`、`conversion_type` |
| 打开文件位置 | 否 | 桌面 bridge，不存绝对路径 |
| 导航/字典层级 UI | 否 | 不改正式算法 |
| 产品候选确认 | 原则上否 | 优先从历史表聚合 |
| BOM 业务变更日期、软删除、产品级主体、明细适用颜色/真实表字段 | 是 | 必须经过 BOM 字段映射确认门槛 |

所有 Schema migration 在实施前先创建数据库备份，并在复制数据库上验证升级、失败回滚、旧数据数量/外键/当前快照一致性。

## 11. 验收要点

- 后端重启后，无需刷新页面，下一次合法写操作能自动恢复一次；
- 所有现有启用/停用入口共享同一回归覆盖；
- BOM 候选为空时显示具体原因和当前筛选条件，不以文件缺失为默认禁用条件；
- 作废图号仍被查重与流水号推荐视为占用；
- 图号状态与源/转曲后文件完整性分别显示；
- 清理缺失 PDF 索引后，历史图号数量和占号结果不变；
- 浏览器预览点击打开位置得到明确桌面提示，桌面版能打开并选中当前存在文件；
- BOM 以产品为入口、使用业务变更日期，备注在当前和历史中均可见；
- 字典一级入口符合用户修正版，项目明细按主类别过滤；
- 全阶段不改变正式图号生成、解析、查重和流水号算法。
