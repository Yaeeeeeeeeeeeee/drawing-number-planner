# 图号规划器兼容性修正阶段设计

**日期：** 2026-08-26

**状态：** 已获用户方向批准，等待书面确认后实施

**基线：** `master`，设计开始时为 `157a70c`
**需求来源：** `docs/DEVELOPMENT_PAUSE_AND_CONFIRMED_REQUIREMENTS.md`

## 1. 目标与阶段定位

本阶段位于下一正式 Phase 之前，用于修正真实 Excel 编码依据、历史资料库占号来源、SKU 和现有目录兼容性。它不重新打开 Phase 1–4 的验收结论，也不借机扩展下一 Phase 功能。

本阶段完成后：

- 正式图号生成、解析、查重和流水号推荐使用同一套完整编码规则；
- 软件正式占号与可靠识别的历史图号共同组成永久已占号集合；
- 产品档案具有独立 SKU，可按 SKU 检索；
- PDF 扫描能可靠识别未知历史正式图号，并分别汇总源文件和转曲后文件完整性；
- 现有历史目录保持原位，不移动、不重命名；
- BOM 继续使用当前内部快照结构，只简化用户可见表达。

## 2. 不在本阶段实施

- 二维码页面、数据表和二维码扫描；
- 批量重命名、自动整理或移动历史文件；
- 新型号文件复制；
- 外发资料打包；
- 服务器 API、自动上传、同步或差异比较；
- OCR、PDF 内容分析；
- BOM 数据库重构；
- 与本设计无关的 UI 重做或基础架构替换。

## 3. Excel 是正式编码规则依据

只读核验《图号规划.xls》工作表“新版图号”后，正式结构确定为：

`品牌码.品类尺寸码.外观码+颜色码.主类别码+项目明细码+版本流水号`

编码段固定为：

- 品牌码：2 位数字；
- 品类尺寸码：4 位数字；
- 外观码：2 位数字；
- 颜色码：1 位数字；
- 主类别码：2 位数字；
- 项目明细码：2 位数字；
- 版本流水号：3 位数字，范围 `001`–`999`。

完整格式为 `NN.NNNN.NNN.NNNNNNN`。其中第三段由外观码和颜色码组成，第四段由主类别码、项目明细码和流水号组成。

真实验收案例至少包括：

| 含义 | 正式图号 |
|---|---|
| SAMKYO / ZC200 / 1号外观 / 白色 / LOGO | `02.0404.010.0401001` |
| SAMKYO / ZC200 / 1号外观 / 白色 / 面板 | `02.0404.010.0103001` |
| SAMKYO / ZC200 / 1号外观 / 灰色 / 面板 | `02.0404.012.0103001` |
| SAMKYO / ZC200 / 1号外观 / 白色 / 说明书 | `02.0404.010.0402001` |

外观码必须参与生成、解析、完整前缀、查重和下一流水号计算。交互示意图中的任何简化编码不得成为业务算法依据。

## 4. 可靠识别与永久占号

### 4.1 自动永久占号条件

扫描器只检查 PDF 文件名，不读取 PDF 内容。一个文件只有同时满足以下条件，才可自动写入历史已用图号表：

1. 文件名中恰好存在一个不同的完整正式图号；
2. 图号通过固定分段格式校验；
3. 七个必要编码段均可无歧义解析；
4. 流水号在 `001`–`999` 范围内。

字典中暂时不存在某个历史编码，不影响永久占号。历史资料可能使用已经停用或尚未迁入当前字典的旧编码；此时保留解析出的编码快照，并显示“字典待映射”，不得释放号码。

同一文件名多次出现同一个完整图号仍视为一个候选。出现两个或以上不同的合法图号属于歧义，不自动占号。

### 4.2 待确认与未匹配

- 出现近似图号但格式错误、编码段不完整、流水号非法或多个不同合法图号：`pending`（待确认）。
- 文件名没有任何图号候选：`unmatched`（未匹配）。
- 待确认和未匹配文件都不进入永久已占号集合，不允许程序猜测。

### 4.3 永久性

历史图号首次可靠识别后永久保留。后续扫描中对应 PDF 消失时，只更新文件存在状态；不删除历史图号，也不允许重新分配。文件存在状态和图号占用状态是两个独立概念。

## 5. 统一已占号集合

现有 `drawing_numbers` 继续保存软件正式规划的图号。新增 `historical_drawing_numbers` 保存扫描识别的历史图号。两者通过规划领域中的统一只读接口参与查重：

```ts
interface OccupiedNumberSource {
  findMaxSequence(prefix: string): number;
  hasFullCode(fullCode: string): boolean;
}
```

实现使用 SQL `UNION` 查询两个表：

- `reserved`、`active`、`voided` 正式记录全部占号；
- 所有历史图号记录全部占号；
- 同一完整图号同时存在于两个来源时只计算一次；
- 预览和原子确认占号都必须调用同一接口；
- 确认占号仍在 SQLite immediate transaction 内重新计算，保持 `PLAN_STALE` 语义。

不把历史图号伪造为产品、字典或 BOM 记录，也不创建占位产品。

## 6. 最小数据库升级

数据库版本从 4 升级到 5。升级前沿用现有备份机制；任一验证失败时不提交迁移。

### 6.1 产品 SKU

`products` 增加可空 `sku TEXT`。采用可空是为了不猜测现有产品的 SKU；新建产品在 API 和 UI 层必须填写 SKU。建立忽略大小写的非空唯一索引，允许多个旧记录暂时为 `NULL`。

SKU 不属于正式图号编码段。为已有图号的产品补录 SKU 不改变图号含义，因此允许单独补录或修正 SKU；品牌、品类尺寸和已使用的型号仍遵循现有不可随意修改规则。

### 6.2 历史已用图号

新增 `historical_drawing_numbers`：

- `id`；
- 唯一 `full_code`；
- 七个解析后的编码段及整数 `sequence`；
- 可空 `product_id`；
- 可空的 `detected_sku`、`detected_model`、`detected_product_category`；
- `first_seen_at`、`last_seen_at`。

扫描再次发现相同图号时只更新 `last_seen_at` 和可靠的目录上下文，不创建重复记录。文件消失时不删除记录。

### 6.3 PDF 关联

对 `pdf_files` 做一次受控表重建，保留全部现有记录并新增：

- 可空 `historical_drawing_id`；
- `pending` 匹配状态；
- 可空 `classification_warning`。

`matched` 文件必须且只能关联 `drawing_id` 或 `historical_drawing_id` 其中一个。`pending`、`unmatched`、`conflict` 不关联图号，并在 `detected_codes_json` 中保留候选供人工查看。

迁移后执行行数、相对路径唯一性、外键和原有字段逐项校验。失败时回滚并保留升级前备份。

## 7. 目录识别与转曲判定

资料根目录继续可配置，数据库只保存相对路径。产品目录识别和未来新建目录统一为：

`{产品类别}\{SKU}-{型号}`

例如：

`01.洗碗机\SKDWT040JP-T40`

产品类别使用资料根目录中的实际一级目录名称，包括现有数字前缀。目录规则集中在 `directory-policy` 模块。扫描可以从符合规则的路径提取 SKU、型号和产品类别，但目录解析失败不影响文件名中合法正式图号的永久占用。

本阶段扫描只读，不移动、重命名、复制、删除或重排任何文件与文件夹。

转曲状态判定优先级已经确认：

1. 位于 `02.未转曲源文件` 内：记录为源文件；若文件名含 `（转曲）`，同时记录分类警告。
2. 位于 `03.量产后的变更文件（已量产的产品看最新日期）` 内：记录为转曲后文件；文件名无需含 `（转曲）`。
3. 其他位置：文件名含完整 `（转曲）` 为转曲后，否则为源文件。

不使用 OCR 或 PDF 内容判断。

## 8. 图号库与文件完整性

图号库统一显示正式图号和历史图号，并标明来源：`软件规划` 或 `历史扫描`。若同一完整图号已存在正式记录，则只显示正式记录，文件仍可正确聚合。

每个图号通过当前存在的 `pdf_files` 聚合：

- `hasSourceFile`：是否至少有一个当前存在的源文件；
- `hasOutlinedFile`：是否至少有一个当前存在的转曲后文件。

文件删除后这两个状态可变，但号码占用不变。筛选支持：图号/关键词、SKU、型号、品牌、产品类别、颜色、资料类型、状态、源文件是否存在、转曲后文件是否存在。低频项放入“更多筛选”。

历史图号的编码若能对应当前字典则显示名称；不能对应时显示原编码和“字典待映射”，不阻止占号。

## 9. 图号规划与产品档案

图号规划页面继续使用可增加、删除的项目行，并从启用的主类别和项目明细字典选择任意包材组合，不固定为 LOGO、说明书或铭牌。本阶段增加回归测试，只有现有行为不满足时才做最小修复。

产品档案新增 SKU 输入、列表列和搜索。参考旧型号继续可空，不增加逐文件来源追踪。

## 10. BOM 简化

保留现有 `bom_versions`、`bom_items`、`bom_current` 作为内部不可变快照和并发保护，不执行数据库迁移。

用户界面改为：

- 当前 BOM；
- 最近变更记录；
- 某日某项目从旧图号替换为新图号的简单差异。

不突出 V1/V2/V3 编号，不让用户维护第二套正式版本语义。同型号不同颜色共用物料仍明确引用白色正式图号。

## 11. 错误处理与安全

- 扫描遇到单个无法读取的路径时沿用 Phase 4 的全批失败策略，上一次成功索引不改变。
- 待确认文件不占号；用户在本阶段只能查看和筛选，不提供未经设计的人工强制占号入口。
- 所有数据库写入使用事务；迁移前备份。
- 路径继续经过根目录边界、相对路径、盘符、UNC、`..` 和符号链接检查。
- 扫描不修改业务 PDF。

## 12. 测试与验收

必须覆盖：

- Excel 四个真实图号的生成与解析，尤其验证外观码变化会改变完整前缀和流水号组；
- 合法单一图号永久占用，非法、残缺、多图号歧义进入待确认且不占号；
- 正式图号与历史图号共同影响查重和下一流水号；
- 历史文件删除后图号仍占用，文件完整性相应变化；
- SKU 新建、补录、唯一性和搜索；
- `{产品类别}\{SKU}-{型号}` 解析与生成；
- `02`、`03` 和其他目录的转曲优先级及冲突警告；
- 源文件/转曲后文件有缺失的所有组合和筛选；
- 图号规划可选择任意字典项目；
- BOM 数据表不迁移，UI 仅展示当前 BOM 和简单变更历史；
- 数据库 v4→v5 备份、数据保留、失败回滚、外键和路径不变；
- 全量单元、API、渲染、E2E、类型检查、构建、桌面启动和浏览器预览。

## 13. 实施边界

实施必须在独立工作树中进行，按 TDD 小步提交。完成全部 verification 和 code review 后才允许合并回 `master`。阶段结束后启动 Windows 桌面应用供用户预览；在用户验收前不开始下一正式 Phase。
