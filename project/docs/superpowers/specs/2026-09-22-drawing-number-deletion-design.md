# 图号删除与占号释放设计（Schema v13）

## 1. 目标与边界

本轮取消“历史图号永久不可删除”的旧规则，让正式规划图号和历史扫描图号都支持：

1. 作废：记录可见、继续占号；
2. 删除记录并保留占号：默认列表隐藏、继续占号；
3. 彻底删除并释放图号：默认列表隐藏、不再占号，可由后续规划重新使用。

删除只改变图号规划器数据库中的业务状态、关联和占号判断，不移动、改名或删除资料根目录中的任何实际文件。本轮不改图号编码结构、外观码、资料批次顺序、BOM 业务字段或外发快照内容。

## 2. 现状调查

当前 Schema v12 真实数据库包含：

- 正式规划图号 1 条（作废）；
- 历史扫描图号 744 条（使用中）；
- PDF 文件实例 2,330 条；
- 资料批次 135 条；
- BOM 明细 1 条；
- 当前没有外发包明细。

现有旧规则分散在四处：

- `DrawingQueryService` 和 API 明确拒绝历史图号删除；
- 图号详情只对未使用的 `reserved` 正式图号显示删除入口；
- `OccupiedNumberRepository` 无条件把两张图号表中的所有号码视为占用；
- 历史扫描对 `full_code` 直接 upsert，人工删除后重新扫描会自动恢复。

现有外键还表明：PDF、BOM、外发明细均可引用正式或历史图号。Schema v12 已把外发文件和资料批次引用改为可脱离实时索引，但外发明细仍保留图号外键和图号快照。当前完整包材不是独立表，而是由资料批次和 PDF 索引实时计算。

## 3. 方案比较

### 方案 A：物理删除主记录，另建完整归档副本

需要重建 BOM、外发、PDF 等引用并补齐所有历史快照字段，风险最大，不符合“小范围升级”。不采用。

### 方案 B：逻辑删除主记录，保留原图号快照与审计（采用）

主记录保留以维持历史外键和审计，但退出正常业务查询。释放时把数据库内部唯一键改为不可被正式解析的归档键，原完整图号保存在专用快照列。因此新图号可再次使用原号码，而历史 BOM/外发仍能显示当时图号。

优点：不重建现有业务表；迁移只新增列、审计表和索引；历史引用不丢失；释放和恢复均可事务化。

### 方案 C：建立独立占号表，所有图号物理删除

占号查询简单，但仍无法解决 BOM 和外发外键，最终仍需大范围重建引用表。不采用。

## 4. Schema v13 最小升级

`drawing_numbers` 与 `historical_drawing_numbers` 各新增：

- `deleted_at TEXT NULL`；
- `deletion_mode TEXT NULL CHECK (deletion_mode IN ('retain_occupied', 'release'))`；
- `deleted_full_code TEXT NULL`：删除前完整图号快照；
- `deleted_previous_status TEXT NULL`：删除前业务状态；
- `deleted_reason TEXT NULL`；
- `scan_resolution TEXT NULL CHECK (scan_resolution IN ('pending', 'ignore'))`。

新增 `drawing_deletion_events` 作为追加式操作日志：

- 来源、原记录 ID、完整图号；
- 删除方式、删除前状态、删除原因；
- 删除时间；
- 恢复时间；
- 执行时引用摘要 JSON。

不为审计表设置指向图号主表的外键，避免审计记录因后续数据维护失效。

升级时所有现有记录的新增字段均为 `NULL`，业务含义和占号结果不变。迁移前继续执行现有数据库备份；迁移后校验行数、完整图号、状态、PDF/BOM/外发外键和 `foreign_key_check`，失败则整笔回滚并保留 v12。

## 5. 内部归档键

两张图号表当前分别对 `full_code` 有唯一约束。为了在不重建表的情况下释放并复用原号码：

- 删除并保留占号：保留 `full_code`，并把同值写入 `deleted_full_code`；
- 彻底删除并释放：先把原值写入 `deleted_full_code`，再把 `full_code` 改为 `__deleted__:<origin>:<id>:<event-id>`；
- API、删除记录查询、历史 BOM 展示一律用 `coalesce(deleted_full_code, full_code)` 作为业务图号；
- 正常业务查询只读取 `deleted_at is null` 的记录，因此归档键永远不会进入解析、查重、BOM 候选或下拉列表。

归档键仅是数据库内部唯一键，不是正式图号，不参与解析和扫描。

## 6. 占号与流水号推荐

统一规则：

- 未删除的 `reserved / active / voided / inactive`：占号；
- `retain_occupied`：占号，使用 `deleted_full_code` 判断；
- `release`：不占号；
- PDF 是否存在不直接决定占号。

为保持原有“最大流水号 + 1”习惯，同时保证明确释放的号码可复用，推荐算法采用：

1. 优先返回同一前缀下由用户明确 `release` 且尚未被其他正常记录重新占用的最小释放流水号；
2. 没有可复用释放号时，继续使用当前占号集合的最大流水号 + 1；
3. 同一批量规划内对候选号码做内存去重；
4. 最终占号事务再次查重，避免并发复用。

这样不会自动填补历史资料中从未明确释放的普通空洞，只复用用户明确释放过的号码。

## 7. 引用检查与阻塞规则

删除预览统一覆盖正式和历史图号，展示：

- 当前存在/缺失 PDF 数量、源文件和转曲后文件数量；
- 当前 BOM 引用与历史 BOM 引用；
- 当前有效资料批次引用与历史批次引用；
- 当前完整包材引用；
- 前版/后续版本和来源图号关系；
- 外发包明细与邮件草稿历史；
- 二维码相关引用（当前模型无直接图号外键时为 0）。

以下属于当前有效业务引用，阻止两种删除方式：

- 当前 BOM 使用；
- 最新有效资料批次/当前完整包材使用；
- 未删除图号的前版、后续版或来源关系。

以下不作为永久阻塞：

- 历史 BOM 版本；
- 历史资料批次；
- 已完成外发包、外发明细和邮件草稿；
- 非当前批次中的 PDF 文件实例。

历史记录继续通过旧记录 ID 或自身快照展示原图号。删除 API 在同一事务中再次计算阻塞项，避免用户查看预览后引用发生变化。

## 8. PDF 索引与资料扫描

删除图号时绝不删除 `pdf_files` 行或磁盘文件：

- 允许删除的历史 PDF 关联会解除 `drawing_id / historical_drawing_id`；
- `match_status` 改为 `pending`；
- `detected_codes_json` 保留原图号；
- `classification_warning` 标明“图号已人工删除并保留占号”或“图号已人工释放”。

扫描在历史图号 upsert 之前查询两张表的删除快照：

- `retain_occupied`：不恢复记录；文件保持待确认/已忽略；号码继续占用；
- `release + pending`：不重新导入；文件进入待确认并提示曾被人工释放；
- `release + ignore`：不重新导入；文件索引保留但标记为人工忽略；
- 如果同一完整图号已被新的正常图号重新占用，扫描优先匹配新的正常记录。

待确认操作：

- “重新导入”：恢复原记录及删除前状态；若号码已被新的正常记录占用则拒绝并说明冲突；
- “忽略”：把删除记录的 `scan_resolution` 设为 `ignore`，以后扫描不再反复要求确认；
- 恢复后可立即重新关联本次扫描中检测到同一完整图号的 PDF 索引。

## 9. 删除与恢复事务

### 删除记录并保留占号

1. 锁定并重新读取图号；
2. 重新计算阻塞引用；
3. 写入删除字段和审计事件；
4. 解除允许解除的 PDF 实时关联并转为待确认；
5. 保留业务完整图号和占号；
6. 提交事务。

### 彻底删除并释放

步骤相同，但将 `full_code` 改为内部归档键，`deletion_mode='release'`，占号查询立即排除该记录。提交后该完整图号可进入后续推荐。

### 恢复记录

1. 检查该完整图号未被其他正常记录占用；
2. 对释放记录恢复 `full_code=deleted_full_code`；
3. 恢复删除前状态并清空当前删除字段；
4. 标记最近未恢复的删除事件 `restored_at`；
5. 重新关联可可靠识别的待确认 PDF；
6. 提交事务。

## 10. API 与界面

新增/调整 API：

- `GET /api/drawings/:id/deletion-preview`：正式与历史图号统一预览；
- `POST /api/drawings/:id/delete`：提交删除方式、确认文本和可选原因；
- `POST /api/drawings/:id/restore`：恢复删除记录；
- `POST /api/drawings/:id/scan-resolution`：对重新扫描结果选择重新导入或忽略；
- `GET /api/drawings` 增加 `deletionState=normal|deleted-retained|deleted-released|all`。

沿用现有有符号 ID：正式图号为正数，历史图号为负数，避免建立两套界面和 API。

图号详情底部增加独立“危险操作”区域。删除流程为：

1. 点击“删除图号”；
2. 加载并展示引用摘要和阻塞原因；
3. 选择“删除记录并保留占号”或“彻底删除并释放图号”；
4. 可填写原因；
5. 对释放操作再次输入完整图号确认；
6. 显示与方式对应的结果文案。

默认图号库排除已删除记录。“更多筛选”增加已删除/保留占号和已删除/已释放；删除记录详情显示来源、原状态、删除时间、方式、原因和占号状态，并提供恢复入口。

## 11. 兼容性与非目标

- 不删除、移动或修改任何磁盘文件；
- 不改变正式图号编码结构和解析；
- 不改 BOM Schema、二维码 Schema、资料批次 Schema 或外发快照字段；
- 不自动清理旧图号；所有已有记录升级后仍为未删除且占号；
- 不把历史快照重新绑定到新复用图号；旧引用继续指向旧归档记录 ID；
- 不合并 master。

- 删除时 API 二次引用检查；
- 释放候选优先、批量规划去重与并发占号；
- 归档键不会进入解析、筛选、BOM 候选或当前完整包材；
- 扫描 pending / ignore / reimport 三条路径；

- Windows 桌面端二次确认、浏览器端提示和危险操作交互。
