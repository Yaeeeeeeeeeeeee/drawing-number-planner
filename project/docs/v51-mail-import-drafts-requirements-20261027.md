# 图号规划器｜邮件模板导入与外发邮件草稿功能需求 V5.1

**项目：** `Yaeeeeeeeeeeeee/drawing-number-planner`

**参考文件：**《包材资料更新-沟通模版(1).xlsx》

## 一、项目目标

优化现有邮件配置功能，使其符合实际包材外发工作方式。

当前邮件配置需要手动填写模板编码、名称、资料类型、主题、正文及大量变量，操作复杂，不方便维护。

本次改为：

**Excel 导入模板 → 日常管理模板 → 外发 ZIP 成功 → 自动生成邮件草稿 → 人工修改确认。**

不增加独立的邮件发送系统，不自动发送邮件。

保留现有 Windows 本地运行方式，不涉及服务器部署。

---

## 二、模块职责划分

| 模块 | 功能 |
|---|---|
| 迁移检查 | Excel 邮件模板识别、预览、批量导入 |
| 邮件配置 | 模板、联系人、签名的查看、编辑及维护 |
| 外发资料 | 使用本次外发数据生成邮件草稿 |

三个模块共用同一套邮件配置数据，不允许建立互不关联的重复模板库。

---

## 三、迁移检查：新增 Excel 邮件模板导入

### 3.1 入口位置

在现有「数据来源 → 迁移检查」页面增加：

**导入邮件模板**

点击后打开导入窗口。

不要在邮件配置中重复增加相同的 Excel 导入入口。

### 3.2 支持的文件

支持：

- `.xlsx`
- `.xls`（现有解析能力支持时）

优先兼容用户提供的《包材资料更新-沟通模版(1).xlsx》。

该 Excel 不是标准数据库格式，而是按工作表、厂家和邮件场景组织的沟通模板。

不得强制要求用户先将现有 Excel 改成新的固定列格式。

### 3.3 识别工作表

识别文件中实际存在的业务工作表，例如：

- 首批包材资料
- 更新包材资料
- 配件下单
- ITR

本次优先实现「首批包材资料」和「更新包材资料」的完整模板导入。

其他工作表可以识别并展示，但在未实现对应业务场景之前，不得错误映射成包材外发邮件。

### 3.4 识别厂家及场景

优先从 Excel 的实际内容识别：

- 厂家名称
- 联系人称呼
- 收件人
- 抄送人
- 邮件主题
- 邮件正文
- 资料类型
- 邮件场景

厂家示例包括百斯特、捷创（祥丰）、华彩（韩上）、创维、正冠等。

这些名称以 Excel 实际内容为准，不创建未经核实的厂家数据。

首批包材资料应保留实际存在的不同话术场景，例如：

- 缺铭牌
- 补铭牌
- 正铭牌
- 完整交付

更新包材资料应独立作为更新场景。

即使两个场景正文相似，也不能未经用户确认自动合并。

### 3.5 智能识别规则

Excel 中可能包含合并单元格、横向厂家栏目、多段正文和历史发送示例。

导入程序需要正确处理这些结构。

必须区分：

**固定模板信息**

- 厂家称呼
- 邮件固定开场
- 固定结束语
- 常用主题格式

**动态业务信息**

- 品牌
- 产品型号
- 产品类别
- 日期
- 资料批次
- 压缩包名称
- 本次修改内容
- 实际外发文件名及图号

**历史示例信息**

- 旧产品型号
- 旧日期
- 旧 PO 号
- 历史修改原因
- 旧附件清单

历史示例不能直接作为今后每次邮件的固定内容。

不允许将无法确定的历史文字擅自转换成动态变量。

### 3.6 导入前预览

上传 Excel 后，不直接写入数据库。

先展示识别结果，包括：

| 字段 | 用途 |
|---|---|
| 工作表 | 来源 |
| 厂家 | 适用对象 |
| 邮件场景 | 首批、更新等 |
| 邮件主题 | 识别后的主题模板 |
| 邮件正文 | 识别后的正文 |
| 联系人 | 收件人、抄送人 |
| 识别状态 | 成功、需确认、无法识别 |

用户可以在预览中：

- 修改识别错误的内容。
- 选择需要导入的模板。
- 排除不需要的历史案例。
- 确认联系人关联。
- 确认固定话术和动态信息的区别。

无法确定的内容必须显示「待确认」，不要随意猜测。

### 3.7 重复导入处理

再次导入同一份或更新后的 Excel 时：

- 识别已有模板。
- 尽量根据厂家、邮件场景及稳定业务标识匹配。
- 显示新增、相同、可能更新、冲突等结果。
- 允许选择更新或跳过。
- 不得直接覆盖用户在系统内手动修改的模板。
- 不得重复创建完全相同的联系人和模板。

导入操作应具有明确的结果统计和错误信息。

## 四、邮件配置页面优化

### 4.1 功能定位

邮件配置只负责日常维护，不承担批量 Excel 导入。

保留并优化：

1. 邮件模板
2. 联系人
3. 邮件签名

### 4.2 邮件模板管理

每条模板建议包含：

- 模板名称
- 适用厂家
- 资料类型
- 邮件场景
- 邮件主题模板
- 邮件正文模板

模板编码可以由系统内部维护，不需要作为日常使用时必须理解的主要字段。

允许查看、编辑、删除模板。

界面保持简洁，不常驻展示大量变量按钮和说明文字。

### 4.3 变量管理

系统应支持从实际外发资料中填充：

- 品牌
- 产品型号
- 产品类别
- 外发日期
- 资料批次
- ZIP 名称
- ZIP 分包数量
- 本次外发文件清单

变量应使用统一格式。

编辑模板时提供简洁的「插入变量」入口，点击选择变量即可，不必要求用户记忆占位符。

允许在没有具体外发数据时保存模板。

如果实际生成邮件时缺少必要变量，需要明确提示，不能静默生成包含未替换变量的最终邮件。

### 4.4 修复模板保存校验

当前存在已经填写模板内容却提示「邮件模板数据不完整」的问题。

要求检查：

- 表单必填字段。
- 前后端校验条件。
- 隐藏字段是否被错误设为必填。
- 变量格式是否导致保存失败。
- 邮件签名是否被错误认定为正文必填项。

保存失败时应明确显示具体原因和对应字段。

### 4.5 联系人独立管理

联系人配置应负责：

- 厂家
- 联系人姓名及称呼
- 收件人邮箱
- 抄送人邮箱

同一厂家可以关联多个联系人。

邮件生成时根据厂家自动带入联系人配置，但允许生成前手动调整收件人和抄送人。

不得将邮箱固定复制进每份正文模板。

### 4.6 邮件签名独立管理

邮件正文中不填写个人签名，也不需要填写签名变量。

要求：

- 模板只保存正文。
- 邮件签名独立维护。
- 生成邮件时自动组合所选签名。
- 不重复追加签名。
- 最终预览可查看完整落款。
- 模板保存不依赖签名是否已经配置。

## 五、外发资料：生成邮件草稿

### 5.1 入口位置

在「外发资料 → 03 生成外发结果」中，ZIP 成功生成后增加：

**生成邮件草稿**

保留当前 ZIP 文件列表及下载、查看等操作。

不需要跳转到邮件配置页面才能生成邮件。

### 5.2 基础操作流程

1. 用户选择品牌、产品类别、产品型号及资料批次。
2. 选择首批资料或本次变更资料。
3. 确认实际外发文件。
4. 成功生成 ZIP 压缩包。
5. 点击「生成邮件草稿」。
6. 系统匹配厂家及邮件场景。
7. 自动填充主题和正文中的已知业务信息。
8. 根据本次实际外发文件生成变更项目草稿。
9. 用户编辑修改原因。
10. 检查最终邮件并复制使用。

**系统不自动发送邮件。**

### 5.3 模板选择

优先根据：

- 厂家
- 资料类型
- 邮件场景

匹配适合的模板。

同一条件对应多个模板时，允许用户选择。

找不到模板时，应提示选择其他模板或先配置，不得随意使用其他厂家的话术。

---

## 六、根据外发清单生成变更草稿

### 6.1 数据来源

使用**本次确认并实际选入 ZIP 的外发文件清单**作为主要来源。

不能直接读取当前批次全部 PDF 并全部作为变更。

不能直接将 BOM 的全部项目视为本次变更项目。

### 6.2 自动生成内容

对每个确认变更的文件，系统自动提取已有信息：

- 主类别
- 项目明细
- 完整图号
- 文件名
- 对应资料批次

并生成可编辑的变更条目。

例如本次只有铭牌变更：

```text
本次修改的内容为：

1. 铭牌
修改内容：【请填写具体修改原因】
新文件：02.0101.010.0201005-SAMKYO-T40白色-铭牌（转曲）.pdf
```

文件名仅为示例，必须使用实际外发文件名。

### 6.3 修改原因人工编辑

系统不能仅凭 PDF 文件名自动推断：

- 为什么修改铭牌。
- 修改了哪些技术参数。
- 是否涉及法规调整。
- 为什么改变包装尺寸。
- 是否调整装柜数量。
- 是否涉及成本或物料变更。

这些信息应由用户填写或修改。

系统可以提供草稿结构，但不能编造业务事实。

### 6.4 变更编辑界面

每个变更项目独立显示：

- 项目名称
- 图号
- 新文件名
- 具体修改内容输入框
- 是否在邮件中显示文件名

用户可以：

- 修改变更说明。
- 调整条目顺序。
- 合并重复的说明。
- 删除不需要写入邮件的描述。
- 查看对应文件名。

删除邮件中的某条说明，不应删除外发 ZIP 内的实际文件。

### 6.5 变更文件准确性

必须特别检查此前发现的异常：

用户只修改铭牌，却在「本次变更资料」下看到全部文件，而且铭牌显示待确认、无法勾选。

这一问题必须与邮件草稿功能联动处理。

要求：

- 可靠识别真正发生变化的文件。
- 不把未变化文件列入变更邮件。
- 待确认文件不得被当成已经确认外发。
- 缺失文件不得被描述为已经交付。
- 与实际 ZIP 清单保持一致。
- 用户修改邮件说明不会改变文件本身。

若变更识别不可靠，应阻止自动宣称某文件已经变更，提示用户核对后再生成。

## 七、邮件草稿预览

### 7.1 预览内容

统一展示：

- 收件人
- 抄送人
- 邮件主题
- 邮件正文
- 变更项目说明
- 本次 ZIP 信息
- 邮件签名

### 7.2 编辑能力

预览阶段允许编辑主题及正文。

用户在「本次变更内容」区域修改后，正文预览应同步更新。

同时保留最终正文直接编辑能力，但要避免自动重新生成时覆盖用户已经修改的文字。

### 7.3 复制功能

提供：

- 复制主题
- 复制正文
- 复制邮件内容

正文复制结果应包含已经确认的修改内容，以及按配置追加的签名。

不自动发送邮件。

### 7.4 草稿数据保护

生成草稿不应：

- 修改 BOM。
- 修改图号状态。
- 修改外发 ZIP。
- 修改 PDF 索引。
- 修改历史外发快照。
- 自动覆盖已保存的邮件模板。

草稿只是针对本次外发生成的可编辑文本。

## 八、首批资料邮件处理

首批资料与更新资料应使用不同场景。

首批资料优先使用 Excel 中对应的固定话术，例如：

- 缺铭牌
- 补铭牌
- 正铭牌
- 完整交付

系统根据实际选择的模板生成邮件，不强制生成「本次修改的内容为」段落。

对于首批完整资料，不要错误地把所有文件逐条描述为发生变更。

---

## 九、UI 设计要求

保持图号规划器现有简洁风格。

具体要求：

1. Excel 导入采用独立弹窗或页面内导入区域，不新增侧边栏一级菜单。
2. 导入前有清晰的识别预览。
3. 邮件配置以模板管理为主，不长期展示复杂变量面板。
4. 外发结果中「生成邮件草稿」作为明确操作按钮。
5. 邮件预览保持清晰的主题、收件人、正文和修改内容层级。
6. 修改原因使用可编辑输入区。
7. 不增加重复的小字说明。
8. 不使用大面积无意义空白。
9. 保留完整长文件名查看能力，但日常界面可适当截断。
10. 错误和缺失信息必须明确显示。

---

## 十、数据安全与兼容要求

- 不改变图号编码规则。
- 不修改历史占号。
- 不删除原始 PDF 或图片。
- 不覆盖历史 BOM。
- 不修改已生成的外发 ZIP 内容。
- 不删除现有邮件模板及联系人。
- Excel 重复导入不得未经确认覆盖已有编辑。
- 不将历史邮件中的旧型号、旧日期和旧修改原因固定为当前模板内容。
- 不在日志中泄露邮箱凭据或其他敏感配置。
- 不新增服务器部署或在线登录功能。

---

## 十一、验收标准

请至少验证以下场景：

1. 可以在迁移检查中导入用户现有 Excel。
2. 能识别主要工作表、厂家和对应话术。
3. 导入前可以预览及修正。
4. 能识别重复模板并选择更新或跳过。
5. 邮件模板可以正常保存。
6. 未填写签名不影响模板保存。
7. 邮件配置中可以编辑已导入模板。
8. ZIP 生成成功后可以生成邮件草稿。
9. 生成时正确带入品牌、型号、日期及压缩包信息。
10. 只修改一个铭牌时，邮件草稿只产生对应的变更条目。
11. 修改原因可以手动编辑。
12. 邮件正文中的变更内容随编辑同步更新。
13. 不会将未变化、待确认或缺失文件误写为已交付。
14. 首批资料与更新资料使用正确的话术。
15. 邮件签名由独立配置自动组合。
16. 可以复制最终主题和正文。
17. 不发生自动邮件发送。
18. 导入、编辑、生成草稿均不影响图号、BOM、PDF 和外发历史。

---

## 十二、Codex 执行与交付

请先检查现有：

- 邮件模板数据结构
- 联系人配置
- 邮件签名配置
- 外发结果数据
- 本次变更文件识别
- Excel 解析能力

优先复用已有功能，不重复建立模板表、联系人表或附件管理体系。

建议分三个阶段实施：

**第一阶段：** 邮件模板保存校验修复及迁移检查 Excel 导入。

**第二阶段：** 邮件配置管理、厂家和场景匹配、变量填充及签名组合。

**第三阶段：** 外发 ZIP 后生成邮件草稿、变更项目编辑与最终预览。

完成后报告：

- 修改的主要文件和组件。
- Excel 实际识别的工作表、厂家和模板数量。
- 哪些模板需要人工确认。
- 数据库是否需要迁移。
- 外发清单与邮件草稿如何关联。
- 自动填充和人工编辑的边界。
- 测试结果及未解决的问题。

**最终目标：** 用户继续使用现有 Excel 中的邮件话术，通过一次导入建立模板；以后每次外发包材，系统自动生成符合原有邮件风格的草稿，用户只需检查并补充本次具体修改内容，即可复制使用。
