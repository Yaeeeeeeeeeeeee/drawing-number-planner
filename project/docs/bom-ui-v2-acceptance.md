# BOM UI 第二版验收记录

日期：2026-10-03。范围仅 BOM renderer 展示，不重设计顶部、不修改正式业务语义。

## 收口内容

- 连续工作表：主类别、项目、图号、生效批次、材质、尺寸为第一层；图片、位置、位置示意图、修改明细、备注为第二层。
- 两种附件保留独立角色，选择/替换、文件名、沿用开关合并为轻量控件；上传与沿用处理不变。
- 已选图号以标识符为主，资格信息在下方显示一次，并通过 aria-describedby 关联；未选候选仍保留来源和状态。
- 修改明细优先于备注；标题仅提示已有图号异常、无候选、批次缺失和附件预览失败。合法空附件保持中性。
- 查询使用静态字段而非 disabled 表单，保持一致阅读顺序、完整附件路径及所选记录语义。

## 实测

四种编辑场景 normal / long / attachments / references 均为 8 项目；1080、1200、1280 下页面和记录网格均无横向溢出。

正常编辑记录高度：1080 为 229–246px，1200 为 229–232px，1280 为 229px；长内容局部为 268px，作废引用局部为 290–304px，未强行截断异常说明。

查询明细同样检查三个宽度，均无横向溢出。1200/1280 所选异常记录为 167–246px；1080 为 185–263px。完整路径可能使查询行比编辑行稍高，未以截断信息换取更低行高。

键盘 Tab 可从图号进入引用白色图号控件；图号资格说明有明确描述关联。Mock 上传、保存、删除、归档、文件位置继续隔离或禁用。

验证：90 个测试文件、835 条测试通过（含 Mock 隔离回归）；renderer typecheck、renderer build、main TypeScript build、git diff --check 均通过。Git 仅提示现有 LF/CRLF 转换警告。

## BOM 设计基准冻结

最终轻量收口：编辑参考普通值使用可读中性深灰；查询焦点仅保留标题与细蓝线，普通内容列不铺蓝底；有效修改明细继续浅蓝、空值不强调；连续项目增加 3px 视觉断点。BOM UI 设计基准正式冻结，不再自行开启视觉优化轮次。全部原 BUG/TODO 与字段级 Diff TODO 继续保留。

本轮仅完成颜色与展示收口：左蓝焦点、右灰参考及分隔；修改明细按各侧实际有无内容强调；项目细状态线固定蓝/橙/红；查询 Compare Header 对称展示记录日期，日期不参与关系推断；加载提示明确为“正在加载 BOM…”。布局、字段顺序和业务规则保持不变。空值、无查询结果、加载失败、保存冲突及产品无 BOM 场景继续保留。设计基准冻结，不自行继续视觉优化；上述全部 BUG/TODO 不因 UI 验收关闭。

- 字段级变更高亮：现有实现仅为 renderer 值比较，缺少经确认的字段级 Diff（含附件沿用/替换与保存时文本规范化）。本轮撤下推断高亮，保留左右原值对照；可靠字段级比较留作后续 TODO。

- 历史录入最终更新 current BOM pointer 的语义。
- 主类别是否参与正式查询过滤。
- 作废引用提示与实际保存条件不一致。
- BOM 加载仍请求二维码候选：本轮保留依赖，不因 UI 无二维码而删除。
- 旧 BOM 可编辑与历史快照保护的业务关系。
- 图号库既有 Mock TODO。

本轮未修改 Schema/migration、正式 API/查询规则、历史快照语义；不合并 master，不继续第三版或其他页面。
