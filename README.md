# 图号规划器

面向单人长期使用的 Windows 公司内部工具。当前版本已把真实 Excel 编码规则、SKU、历史资料只读扫描、永久占号、文件完整性、外发资料和桌面安全恢复接入同一套本地工作流，并可用同一套真实数据在 Windows 桌面窗口或浏览器中运行。

## 启动

首次使用先安装依赖：

```powershell
pnpm install
```

浏览器开发预览：

```powershell
pnpm dev:web
```

随后打开 `http://127.0.0.1:5173`。本机 API 只监听 `127.0.0.1:4317`。

Windows 桌面窗口：

```powershell
pnpm dev:desktop
```

桌面窗口与浏览器使用相同 React 页面和本机 API，不维护两套业务逻辑。

验证构建后的独立窗口（不依赖 Vite 开发服务器）：

```powershell
pnpm build
pnpm exec electron .
```

## 数据位置与备份

- Windows 桌面模式：数据库、备份、日志和导出目录位于 Electron 的当前用户应用数据目录。
- 开发浏览器模式：默认使用项目下被忽略的 `work/runtime-data`。
- 可通过服务启动参数或开发环境变量 `PLANNER_DATA_DIR` 改变应用数据目录；代码中不写死盘符、用户名或当前电脑绝对路径。
- 已存在数据库在每天第一次启动时生成一次经过完整性校验的备份，默认只保留最近 30 份日常备份；迁移和导入备份不受这项清理影响。
- 数据库迁移和 Excel 确认导入前会强制备份；备份失败时不会继续升级或导入。
- 资料根目录保存在应用数据目录的 `settings.json`，用于定位当前电脑上的日常工作主库；它不写入 SQLite 业务表。
- 外发输出目录与资料根目录独立配置，同样保存在 `settings.json`。外发 ZIP 不能写入资料根目录，数据库只保存相对于外发输出目录的路径。
- PDF 文件记录只保存相对于资料根目录的路径。资料库迁移到其他磁盘或映射盘后，只需重新设置资料根目录，不需要修改图号、BOM 或 PDF 索引记录。

“应用数据目录”和“资料根目录”不是同一个概念。前者保存软件自身的数据，后者是用户日常整理 PDF 的本地资料库。代码不写死盘符、用户名或当前电脑的绝对文件路径。

## 图号规划与批量占号

1. 在“图号规划”选择启用中的产品和外观。
2. 添加一个或多个项目，逐行选择主类别、项目明细和颜色。
3. 点击“查重并预览”，核对预计图号、显示名称和推荐流水号。
4. 点击“确认批量占号”后，整批图号在一个数据库事务中永久占用。

预览不会写入数据库。确认时系统会重新查重；若推荐号码已经变化，整批拒绝并要求重新查重，不会静默换号或只写入部分行。已占号、已生效和已作废的号码都不会再次分配。

## BOM 管理

1. 选择“当前 BOM”或“历史 BOM”，再选择产品、业务变更日期以及主类别 → 项目明细。
2. 当前 BOM 可选择正式规划图号；历史 BOM 还可选择已确认归属于该产品的历史已用图号。历史图号停用后仍永久占号。
3. 二维码是可选业务引用，只能选择二维码管理中已有且启用的同产品记录；BOM 不创建或识别二维码文件。
4. 每次保存生成不可变快照。删除单条当前记录会安全回退到上一条未删除快照；“删除整个型号 BOM”是独立高风险入口，需要输入型号确认，数据采用软删除保留审计链。

## PDF 文件中心

1. 在“PDF 文件中心”输入本机资料库的完整根目录并保存。
2. 点击“扫描资料库”，软件只读扫描根目录内的 PDF，不改名、不复制也不删除原文件。
3. 文件名中恰好出现一个符合完整编码结构的图号时才可靠登记。残缺、格式异常或包含多个不同图号的文件进入“待确认”，不会自动占号，也不会猜测。
4. 未知但可靠的完整图号会登记为历史已用图号，并永久参与查重和下一流水号推荐；以后文件消失也不会释放号码。
5. `02.未转曲源文件` 优先识别为源文件；`03.量产后的变更文件（已量产的产品看最新日期）` 优先识别为转曲后；其他目录按文件名是否包含完整 `（转曲）` 判断。
6. 图号库分别显示源文件和转曲后文件是否存在，并支持按 SKU、型号、产品类别、编码字典和两类文件完整性组合筛选。
7. 扫描后消失的文件索引只标记为缺失，不删除历史图号；扫描不会移动、重命名、复制、改写或删除任何 PDF。

扫描只依据文件名建立图号索引，不解析 PDF 页面内容。目录规则集中为 `{产品类别}\{SKU}-{型号}`，用于识别上下文和未来新建目录；即使历史文件不完全符合该层级，可靠图号仍可登记。

## 二维码管理

1. 二维码用途、产品二维码名称、网址和业务状态均可维护，不写死为固定枚举。
2. 自动识别只接受型号根目录中的 `{型号}-{用途英文}（{非空标识}）.{扩展名}`；用途忽略大小写并压缩连续空格后精确匹配。
3. 文件中的括号标识只作为识别标识保存，不进行二维码图片解码，也不把标识猜成网址。
4. 业务状态、文件存在状态和扫描匹配状态相互独立。歧义或未知产品/用途保留为待确认，不自动创建产品或猜测关系。
5. 有文件实例或 BOM 引用的二维码不能删除，界面会显示具体引用原因；可停用的业务记录仍保留历史关系。

## 外发资料

1. 在 Windows 桌面版进入“外发资料”，选择本次变更或当前完整包材、首批或更新、品牌、产品和资料批次。
2. 预览会显示项目、图号、来源批次、文件名以及正常、沿用、缺失、冲突或待确认状态。缺失、冲突和待确认项目会阻止生成。
3. 只打包当前存在、可靠匹配的转曲后文件；源文件不会进入 ZIP。同一实际路径在一个包中只出现一次。
4. ZIP 先写同目录临时文件，完成并核对条目后原子发布；取消或失败不会留下半成品，也不会移动、改名、删除或改写资料根目录中的源文件。
5. 联系人、模板、可选段落和签名均可维护；邮件正文和文件清单可编辑、复制并保存快照，但软件不连接邮箱，也不发送邮件。

浏览器预览可查看打包预览、维护邮件资料并生成/复制邮件文本，但选择本机输出目录、生成 ZIP、打开文件位置和安全恢复操作仅在 Windows 桌面版可用。浏览器会显示明确限制，不会伪装成功。

## 长任务与安全恢复

- 扫描、清理索引、Excel 导入和外发打包进入本地任务中心，显示阶段与进度，并可在进入最终提交前协作取消。
- 任务进入 `finalizing` 后不再允许取消，避免产生半提交数据库或半发布 ZIP。
- 左下角显示“系统正常 / 正在处理 / 本地服务异常”。“安全恢复”提供终止当前任务、重新加载界面、重启本地服务和完整恢复应用。
- Renderer 无响应时仍可使用 Windows 原生菜单“应用 → 安全恢复”。重新加载界面不清库；重启服务会刷新写入令牌；完整恢复会先安全处理活动任务，再重启服务和应用。
- 本地服务由 Electron 主进程管理的独立子进程承载；它仍只监听本机，不是服务器同步功能。

## Excel 迁移检查

1. 在“迁移检查”选择现有命名规则工作簿。
2. 点击“开始检查”，查看候选字典项、来源单元格和冲突。
3. 冲突项不能勾选；只会导入用户明确勾选且无冲突的记录。
4. 检查结果会同时显示工作簿内部冲突和与当前数据库的冲突。
5. 点击“确认导入”后，软件先备份数据库，再把所选记录放在同一个事务中写入。

软件不会覆盖或改写源工作簿。当前只读取 `.xlsx`；旧版 `.xls` 会提示先在 Excel 中“另存为 `.xlsx`”。源表中的重复编码不会被自动更正。
