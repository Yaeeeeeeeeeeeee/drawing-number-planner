# Drawing Number Planner

A dated report, branch name, test count or current implementation is evidence, not a permanent business rule. Latest explicit user instructions take precedence.

## Current rules

- Product identity is the internal product ID. SKU/model may repeat, including within a brand. Do not automatically merge products by text. One product can reference multiple appearance codes; default appearance is a planning default. Independent initial/current appearance management is deprecated in daily UI. Retain old version/binding/usage/merge records and historical FKs.
- Planning reserves the complete code and explicit product/appearance ownership atomically. Check formal, reliable historical, retained-deleted and inactive occupation. Reservation does not add a BOM item. Explicit reuse preserves original code and ownership.
- Drawing navigation is product category → model → dictionary main category. The list uses **颜色**, parsed from separate appearance/color codes and the actual dictionary; unknown is 未识别, never guessed from filenames. Main category and project share one line with a stable pastel category label.
- Drawing business status names are **使用中 / 已停用**, reversible for formal and historical records. Do not display 历史版本 as a third drawing status. Keep reserved as an internal unactivated state with explicit activation; a business label never decides release eligibility.
- Normal release: a historical scan, formally used drawing, unproven old voided record, or protected PDF/BOM/outbound/lineage/audit reference blocks release. Both business states can enter the same qualification flow. Only proven unused, unreferenced mistaken reservations may release after exact code confirmation. Retained deletion remains distinct from release.
- V5 independent force release is explicitly authorized: show all affected identities/PDF/BOM/outbound references, then one explicit confirmation. Archive original identity and immutable snapshots, detach current links transactionally, release occupation, and audit. Never delete original files. Rescans of previously force-released codes stay pending; an explicit new-generation file association survives only while its indexed identity and SHA256 remain unchanged. This does not weaken normal release eligibility.
- PDF product ownership, drawing match, conversion role, disk presence and current business usage are independent. Manual per-index classification survives rescans; do not overwrite conflicting explicit facts. Unique trustworthy candidates may be classified through the authorized explicit operation with backup/transaction/audit; ambiguity remains visible and correctable.
- V5.2 drawing file detail observes the exact full code in known product directories read-only: source only in the exact 02 directory, outlined files in all exact 03 business batches, sorted by business date. Show one row per batch, current/history by existing business rules rather than mtime; conflicting content remains explicit. Missing index is not physical absence; inaccessible or incomplete ancestors stay unverified. Re-observe identity/scope/quarantine before opening an unindexed file through the existing desktop bridge. Never create indices/reservations in this read path or rediscover released old files as new-generation associations. Preserve all underlying instances/history; no batch selector or duplicate history cards.
- PDF batch left-click selects; right-click offers only rename/delete, without selecting. Rename changes display name only. Delete only an empty unreferenced internal batch after confirmation and transactional recheck; a fresh successful disk observation may allow cleanup of unprotected stale indices, but unreadable/symlink/nonempty directories cannot be treated as empty; protect all FKs, BOM/outbound/manual-assignment snapshots and product-merge history. A table-tagged merge reference to `material_batches` protects that batch even if empty. Do not infer reference identity from an unrelated numeric ID.
- PDF toolbar groups remain on one row: 全选 / 取消选择 / 人工归纳; 排除所选文件 / 恢复所选文件 / 移除文件记录. Selection scope stays loaded/explicit scope, not all database rows. Narrow width scrolls the toolbar internally. Removing indices, exclusion and restoration retain existing safety semantics.
- Mail templates, contacts and signatures share existing tables. V5.1 Excel import belongs only in migration checks: read-only editable preview, preserve unknown/history text for explicit review, backup then fingerprint-checked transactional confirmation; never silently overwrite manual edits or duplicate contacts. Daily keys are internal. Drafts use successful ZIP snapshot facts only; update descriptions exclude unchanged files and require reliable comparison or explicit hash-bound confirmation, while original PDFs/ZIP/BOM/history stay untouched. Manufacturer/type/scenario selection is explicit when unknown; reasons are human input, direct body edits need confirmation before replacement, signatures append once, no automatic sending. See docs/v51-mail-delivery-20261027.md.
- V5.2 permits explicit business-date correction on the exact selected BOM record with valid ISO input; omission preserves a legacy NULL. Record ID, original creation time, version/predecessor/current-pointer identities, other records and immutable correction/outbound snapshots remain protected. A date-only correction must not rearchive unchanged attachments. Explicit attachment reuse resolves the actual predecessor same project/role; ordinary edits keep the current attachment. Outbound uses the explicitly selected batch and package scope; BOM provides auxiliary evidence, without implicitly mixing older batches. QR is independent of formal numbering; manual PDF association and QR business status remain separate.
- V5.2 fresh package scans enter only `02.未转曲源文件` and `03.量产后的变更文件（已量产的产品看最新日期）` directly under each product. Older directory aliases are historical paths whose rows/references remain unchanged. Use the shared bounded name list and identical SQL/scanner scope; never treat excluded, unobserved paths as physical absence. Source PDFs have a product source node, not a production batch; their table batch display is 未转曲源文件 and batch status is —. Do not automatically clean out-of-scope indices or rewrite unobserved management states. Incomplete traversal rejects the scan before persistence; excluded and unobserved paths cannot become physical absence. Keep configured local paths unchanged; do not apply this scope to QR manual association.
- Shared tables allow direct header reorder (no six-dot icon), obvious edge resize, local persistence and visible reset; the overall table fits the available container, resizing redistributes internal widths and saved preferences adapt across windows (overflow only at actual minima), actions center in the whole cell and long-list headers stay visible. Product/PDF/drawing/QR long lists use bounded/chunk/virtual scrolling. PDF navigation is product/batch; pending entries follow the tree in the same scrolling region. Filtering never rewrites catalog membership.
- Windows installation is Chinese with editable paths and a Windows Shell folder picker. Each successful installation has its own marker and asks existing/new DB once; normal restarts reuse the selection. Fresh creates a separate empty data directory without a file chooser; existing DB is checked read-only before atomic profile persistence. Cancel/failure preserves the previous profile and all original data. Preserve a selected Desktop child exactly; selecting the physical Desktop root normalizes to its dedicated `DrawingNumberPlanner` child, including silent `/DIR`. Refuse old sample-bearing targets without deleting them. Installation never resets user data; no sample business DB/PDF is bundled.

## Safety and references

Never move, rename, overwrite or delete original user PDFs during scanning, classification, cleanup or acceptance. Back up and verify before migrations; use transactions and test rollback, foreign keys, preserved historical rows and immutable snapshots. No startup product merge or automatic historical number release. Test destructive paths only in isolated fixtures. User real data and physical Windows DPI require separate evidence.
