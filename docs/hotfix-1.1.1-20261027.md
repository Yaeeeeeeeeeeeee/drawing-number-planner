# v1.1.1 修复与验证记录

范围：用户反馈的包材扫描漏识别、表格列宽超出容器，以及每次安装后的数据库选择。沿用 v1.1.0 / Schema22 增量修复，不增加数据库迁移。

## 扫描根因与修复

用户根目录 `E:\包材资料`。原样路径测试覆盖：

- `冰柜\SKDZU070JP-ZU70SD\02.未转曲源文件\02.0305.010.0201001-SAMKYO-ZU70SD白色-铭牌.pdf`
- `冰柜\SKDZU070JP-ZU70SD\03.量产后的变更文件（已量产的产品看最新日期）\00.首批大货\02.0305.010.0201001-SAMKYO-ZU70SD白色-铭牌（转曲）.pdf`

v1.1.0 对生产目录名称作完全相等比较，括号说明被当成另一个目录而排除。扫描层、批次层和 SQL 列表还有各自的名称判断。范围缩小后，旧索引未进入本次扫描仍被统一设为缺失，造成大量“删除/缺失”误报。

现在扫描、分类、批次解析与查询共享受限的已知目录名称：源文件目录不变，生产“变更文件 / 变更明细”兼容现有的括号说明（全角和半角）。不扫描产品根目录、备份近似目录或无关目录，不根据 PDF 文件名绕过目录规则，不改磁盘目录名。

缺失对比和标记仅针对本轮实际覆盖的目录。未观察到的范围外历史索引不会被新扫描认定物理缺失。受保护引用保留；可安全清理的范围外误扫索引沿用原校验，不释放图号。重扫原路径更新原索引 ID 和批次 ID，不按显示名称合并不同真实路径。

未转曲路径本身符合原规则，隔离复现中已能识别。本次将它和带说明的转曲路径一起验证：两条文件分别显示在“未转曲源文件”和“首批大货”，来源/转曲角色/关联/存在状态保持独立；不把源文件当生产批次。

## 表格宽度

旧实现只增加单列绝对宽度并填充尾列，没有约束列宽合计。共享表格改为按可用容器拟合；拖动只分配内部宽度，窗口变化保持用户偏好比例，旧超宽设置也会拟合。保留最小宽度、换序、记忆、恢复默认及冻结表头。只有各列最小宽度之和已超过容器时保留必要横滚。操作按钮限制在实际单元格内，窄列可换行。

已用真实 Chromium 检查 720 / 1366 / 1920 / 2560 / 3840 CSS px，包含极端拖动、旧超宽缓存、窗口反复缩放和按钮可见性；另验证 240px 容器的真实最小宽度边界。

## 每次安装选择数据库

成功安装时生成独立安装标识。同版本重装也换标识；该安装首次启动询问“使用旧数据库 / 创建新数据库”，普通重启使用已选库。

旧库从已有 `planner.db` 选择；新库自动创建到独立 `data` 或 `data-*` 目录，不要求文件选择，不覆盖旧库、设置、备份或原始资料。只有有效选择/初始化成功后才原子保存配置和安装标识；取消或失败保留原配置。免安装版没有安装标识时继续使用稳定已选配置。

独立审查发现 SQLite 魔数检查不足以排除损坏文件，已增加只读原生SQLite quick_check；损坏页/截断/只有魔数的文件均在保存配置前阻止，并保留原配置和原库。相关24项测试通过。
