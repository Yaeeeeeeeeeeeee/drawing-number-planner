# 安装、升级与恢复

## 安装

1. 从 v1.3.1 Release 下载 `DrawingNumberPlanner-1.3.1-Windows-x64-Setup.exe`，可对照同页 `SHA256SUMS.txt` 核验。
2. 关闭正在运行的旧版。中文安装向导中选择安装路径；“浏览”可选择桌面、中文子文件夹及 Windows 已重定向的桌面位置。直接选桌面根时使用其中独立的 `DrawingNumberPlanner` 子目录。
3. 每次安装/升级后的首次启动，先选择旧库或新库。旧库选择原数据目录内的 `planner.db`；新库自动创建独立空数据库，无需选择已有文件。日常重启不再询问。不要通过创建空库解决旧库兼容问题。
4. 核对本地资料根目录及外发输出目录。安装程序目录、数据目录和资料目录彼此独立。

稳定配置位于 `%APPDATA%\DrawingNumberPlanner\profile.json`，保存数据目录及已完成选择的安装标识；业务数据及 `settings.json` 保留在已选目录。通过应用安全恢复入口可以重新选择数据目录。安装和卸载均不清除业务目录。

## 升级

升级前关闭程序，完整备份数据目录，包括 `planner.db`、存在时的 WAL/SHM、`settings.json`、`backups` 和托管附件；原始资料及外发文件另按原位置保留。不要只复制仍在写入中的单一数据库文件。

新版读取并升级原库至 Schema23。Schema23 给既有邮件模板增加已确认收抄送人关系、明确无联系人的标志及原始导入案例来源历史；保留原联系人、模板正文、签名和草稿。Schema21 增加强制释放审计和旧文件隔离记录，保留原图号身份及所有历史外键；Schema22 仅给邮件模板增加可空的厂家、场景字段。Schema20 的正式图号正常启停修正仍保留。更早的数据库依次执行原有兼容迁移。迁移先生成并校验备份，在事务内检查历史行、外键和 schema 对象；备份失败或迁移失败时不继续启动业务。

升级不会自动执行 ZC100 或其他真实产品归并，不自动清理 PDF 或释放图号。需要纠正归属时使用图号库既有关联诊断/改变产品所属、PDF 人工归纳；存在歧义时核对真实产品 ID 和文件。归并由用户在本地独立确认。

## 恢复

迁移失败会回滚，先保留错误信息和原目录，勿反复新建空库。若需恢复备份：关闭程序，另外保存失败后的完整目录；在独立目录恢复迁移前已校验的备份及对应设置/附件，再通过安全恢复入口选择该 `planner.db`。

上一版 v1.2.0 最高支持 Schema22，不能直接打开升级后的 Schema23；更早版本同样不得直接打开超出其支持范围的库。回退程序必须配套使用升级前备份；保留新版数据库，避免丢失升级后新增的业务。回退代码 Tag 不代替数据库备份。

## V5.2 首次使用

- 沿用原有本地资料根目录（例如现用的 `E:\包材资料`），不切换服务器共享路径。新扫描只进入产品下 `02.未转曲源文件` 与 `03.量产后的变更文件（已量产的产品看最新日期）`；保留其他既存索引及历史引用，不因排除或扫描失败批量标缺失。首次升级后核对根目录，再执行一次扫描。
- 正常删除仍保留原保护规则。仅在确需释放时使用独立「强制取消占号并删除图号」，逐项核对影响后确认。强制操作不改写原 BOM/外发快照，不删除原 PDF；旧同号文件重扫后需要人工确认，不能默认属于后来新建的同号记录。
- ZC100 等真实产品归并、生产数据归属纠正及任何强制释放均由用户本地明确执行；启动升级不自动执行这些操作。

## v1.1.1 补充

v1.1.1继续使用Schema22，无新增迁移。生产目录兼容现有括号说明及历史“变更明细”；范围外未被观察的记录不再作为本次磁盘缺失。安装器每次成功安装生成新标识；创建新库使用独立data/data-*目录，旧库、设置和备份保留。选择数据库先进行只读SQLite检查，取消或失败不会覆盖上次配置。v1.1.0可读取Schema22，但存在本次修复的扫描问题，不建议退回后继续扫描。

v1.1.2补充纠正源文件的表格位置：资料批次列显示「未转曲源文件」，批次状态显示「—」，不把源文件显示为未归入批次或生产批次。数据和Schema不变。

## v1.2.0 邮件模板与草稿

1. 在迁移检查点击「导入邮件模板」，选 `.xlsx` 文件；现有解析器不支持旧二进制 `.xls`，需先另存为 `.xlsx`。
2. 预览实际工作表、厂家、场景、主题正文和联系人，修正不确定内容，排除历史案例中的旧型号/日期/PO/原因。只勾选需要的模板并确认联系人和话术；导入前自动备份，重复导入不会静默覆盖。
3. 在外发资料的邮件配置日常维护模板、独立联系人和签名。内部编码系统维护；模板保存不要求实际外发数据或签名。
4. 确认实际文件并生成 ZIP 后，在03结果点击「生成邮件草稿」。选择正确厂家/类型/场景，逐项填写修改原因。编辑或删除邮件说明不改变 ZIP。直接编辑正文后不会被自动覆盖；重新生成须确认。
5. 核对收件人、抄送、主题、正文及落款，复制到原有邮件工具使用，程序不自动发送。

本版未新增数据库迁移，保持 Schema22。旧库通过已有备份与升级机制兼容，原模板、联系人、签名和外发快照保留。仍由用户在本地执行参考Excel导入和实际产品归并，启动不自动归并或释放号码。

## v1.3.0 / V5.2 操作变化

- 图号详情直接显示源文件和全部对应转曲后批次；找不到索引不等于原始文件缺失。无法访问或同批次存在冲突时按实际提示处理，不能随意选最新文件。首次 BOM 名称可跳转到原始记录；日期更正仍保留原 ID 与追溯。
- PDF 六个批量按钮改为图标，悬停查看原操作名称；批次右键重命名/删除仅影响内部记录，不删除真实目录。缩列释放空间交给最右列，顶部操作区域随滚动保持可见。
- 在迁移检查重新预览实际 XLSX。先核对每个供应商/场景的收件、抄送、主题、建议正文和原始案例，再勾选导入；更新案例中的旧型号、订单和原因不直接作为未来默认。共享联系人复用原记录，原字段不覆盖。签名单独选择新增、复用或跳过，不自动设默认；原始案例在邮件模板编辑区折叠查看。
- 切换厂家时重新采用该厂家的收抄送配置；同厂家内的手动地址/正文调整继续受保护。程序不自动发送邮件。
- ZC100 等实际产品归并仍需用户在本地明确确认；不要为升级清空旧库。实际业务库和物理显示器 DPI 未在开发环境，升级后请核对原数据与本地文件。

## v1.3.1 邮件导入修复

修复跨公司共享抄送被拒绝的问题，联系人公司可以保留DD等实际公司，无需改成供应商。导入结果在底部按钮旁显示，失败保留编辑，可修正后重试。保持Schema23，无新增迁移；使用原数据库即可，无需清空或新建库。
