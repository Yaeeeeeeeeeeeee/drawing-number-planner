## 2. 数据来源与历史已用图号

### 2.1 数据来源必须分开

- 《图号规划.xls》用于迁移和校验编码规则、编码字典及图号生成逻辑。
- Excel 不包含全部历史已使用图号，不能作为已用图号的唯一来源。
- 本地历史包材资料库是历史已使用图号的来源。未来需要递归扫描整个资料根目录，从 PDF 文件名识别完整正式图号。

### 2.2 历史图号永久占用

只要从历史 PDF 文件名中可靠识别出完整正式图号，该图号即视为已经使用，并永久参与：

- 图号查重；
- 下一流水号推荐；
- 已占用编码判断。

即使图号不在 Excel、不在当前 BOM、属于旧版本，或只有转曲前/转曲后其中一种文件，也不得重新分配。

恢复开发时，Phase 2 的占号与推荐算法必须使用统一的“已占号集合”接口。该集合应同时容纳软件正式占号记录和历史资料扫描识别记录，不能只查询 Excel 导入记录或当前业务表中的人工占号。历史扫描的完整实现仍属于文件相关工作，不因此提前跨 Phase 开发。

## 3. 正式图号结构与外观码

正式图号必须以原《图号规划.xls》的真实规则为唯一依据，完整编码维度为：

`品牌码 + 品类尺寸码 + 外观码 + 颜色码 + 主类别码 + 项目明细码 + 版本流水号`

外观码必须实际参与：

- 图号生成；
- 查重；
- 下一流水号推荐；
- 编码组合判断。

外观码不能只作为产品档案中的显示文字。恢复开发后，在继续正式图号规划前，必须先核对 Excel 公式和真实案例，并增加自动化测试，证明生成结果与 Excel 一致。

## 4. 历史 PDF 扫描与文件完整性

### 4.1 首次全量扫描

未来应支持对资料根目录执行递归全量扫描，从 PDF 文件名中提取能够可靠解析的正式图号、品牌、型号、颜色、资料项目等信息，并建立历史已用图号记录。不使用 OCR 或 PDF 内容分析判断转曲状态。

### 4.2 每个图号分别记录文件状态

每个正式图号至少分别显示：

- 转曲前/源文件：有或缺失；
- 转曲后/外发文件：有或缺失。

允许“源文件缺失、转曲后已有”等组合。文件缺失只表示历史资料完整性问题，不代表图号无效。图号库未来应支持筛选“缺少源文件”和“缺少转曲后文件”。

### 4.3 转曲状态识别

新文件继续使用：

- 文件名包含完整 `（转曲）`：转曲后/外发文件；
- 文件名不包含 `（转曲）`：转曲前/内部修改文件。

首次历史扫描还必须兼容现有目录语义：

- `02.未转曲源文件` 明确属于转曲前/源文件区域；
- `03.量产后的变更文件（已量产的产品看最新日期）` 及其批次/日期子目录属于历史量产和变更资料区域；
- 历史目录语义与文件名规则冲突时，必须在恢复开发后的设计中明确可审计的判定优先级，不得静默猜测。

二维码 PDF 扫描与正式图号 PDF 扫描是两套独立逻辑。

## 5. 本地资料目录与路径规则

### 5.1 已确认目录结构

软件必须适应用户现有目录，不要求用户为了软件重整全部历史文件：

```text
包材资料\{产品类别}\{SKU}-{型号}\
  02.未转曲源文件\
  03.量产后的变更文件（已量产的产品看最新日期）\
    00.首批大货\
    01.YYYYMMDD\
    02.YYYYMMDD\
    03.YYYYMMDD\
    ...
```

示例：

```text
包材资料\01.洗碗机\SKDWT040JP-T40\
包材资料\03.冰柜\SKDZU070JP-ZU70SD\
```

正式术语：`SKDWT040JP` 是 **SKU**，`T40` 是 **型号**。后续需求、数据库字段和 UI 不得再使用“内部型号代码”指代 SKU。

后续新建目录、文件复制、资料整理、批量重命名和外发资料整理必须遵循此目录规格。目录解析与生成规则集中在单一目录策略模块中，禁止在多个页面或业务模块散落硬编码。历史扫描不能依赖文件必须完全符合目录层级才承认图号。

### 5.2 资料根目录与相对路径

- 本地资料库是日常工作主库；公司服务器由用户不定期人工同步/备份。
- V1 不开发服务器 API、自动上传或自动双向同步。
- 软件使用可配置的资料根目录。
- 数据库中的业务文件路径原则上只保存相对路径，不写死盘符、Windows 用户名或当前电脑绝对路径。
- 迁移到其他磁盘、NAS 或映射盘时，只修改资料根目录，不修改图号、BOM 或文件业务记录。

## 6. 产品档案与图号库检索

### 6.1 产品档案

产品档案未来增加独立 `SKU` 字段，并将 SKU 与型号分开保存、显示和检索。产品目录名采用 `{SKU}-{型号}`。

新型号可以：

- 从零建立，不参考旧型号；
- 选择旧型号作为修改底稿。

只保留“基于旧型号创建”的操作能力，不建设复杂来源追溯系统，也不永久追踪每个文件来自哪个旧型号或旧图号。

### 6.2 图号库组合筛选

图号库未来支持以下组合条件：

- 图号/关键词；
- SKU；
- 型号；
- 品牌；
- 产品类别；
- 颜色；
- 资料类型；
- 状态；
- 源文件是否存在；
- 转曲后文件是否存在。

UI 可使用“更多筛选”收纳低频条件，保持页面清晰。

## 7. 图号规划页面

保留现有 UI 方向。用户应能自行添加或勾选本次需要规划的包材项目，不能固定为 LOGO、说明书和铭牌。

项目来自可维护的编码字典，可一次选择任意组合，例如面板、铭牌、顶部贴纸、压缩机标签、LOGO、说明书、售后卡、礼品卡和大外箱等。批量规划仍应统一预览、查重，并原子占号。

## 8. BOM 简化

BOM 的核心职责是表示“某个型号/颜色当前实际使用哪些正式图号”。不继续发展独立且复杂的 `BOM V1/V2/V3/V4` 版本体系。

- 包材正式版本由图号末尾流水号管理。
- BOM 只维护当前使用关系。
- 如需追溯，只保留简单变更历史或历史快照，例如：`2026-08-25 铭牌：...003 → ...004`。
- 同型号不同颜色共用物料时，继续引用白色对应正式图号。

恢复开发后应先评估现有 BOM 实现，采用最小兼容改动，不为本项进行无必要的大规模重构。

## 9. 二维码管理 Backlog

二维码功能只登记为后续 Backlog，当前不开发页面、数据库或扫描功能。

### 9.1 位置与命名

二维码 PDF 位于 `{SKU}-{型号}` 产品目录根层级，与 `02.未转曲源文件`、`03.量产后的变更文件（已量产的产品看最新日期）` 同级。

命名规则：

`{型号}-{用途英文}（二维码网址编码）.pdf`

示例：`ZU70SD-User Manual（网址编码）.pdf`

### 9.2 用途与状态

常规用途至少包括：

- `User Manual`：说明书二维码；
- `Warranty`：售后/保修二维码；
- `Recipe`：空气炸锅菜谱二维码。

用途必须可扩展，不能永久写死为三种。

二维码需要将两类状态分开：

- 业务状态：启用或未启用；
- 文件状态：文件已有或文件缺失。

二维码启用/停用不会产生新的包材图号，也不强制进入 BOM。
