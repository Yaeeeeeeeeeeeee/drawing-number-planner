# 第二轮实际使用验收修正：调查与设计提案

日期：2026-09-22。代码基线：`9aa377c`，Schema v13。状态：调查完成第一轮，数据升级与产品集中清理方案待确认；尚未修改业务代码或真实数据。

## 目标与范围

依据用户本轮 30 项要求，完成图号双向状态与批量删除、BOM 原记录编辑和附件归档、产品集中清理、BOM 到外发邮件联动、50MB 分包及统一信息层级。保留当前编码、外观码、查重和 v13 人工释放规则。二维码本轮只调整显示，BOM 隐藏二维码操作但保留旧关系。原始 PDF 不移动、不修改、不删除；不合并 master。

## 方案

### 图号与批次（需求 1、2、6、14、15）

允许未删除正式图号 voided→active，历史图号沿用 active/inactive 双向状态。状态变更不释放号码。批量删除复用 v13 单条预检和删除服务：仅勾选当前页，全选当前页，切换筛选清空选择；汇总可删/阻塞/存在文件数量，保留两种删除方式与释放警告。执行时每项独立事务再次核查，返回成功、跳过、失败明细；不因一项阻塞回滚已成功项。可取消尚未开始的项。重复提交不得造成重复释放或影响重用后的号码。

集中提供批次显示格式：已识别排序前缀 `06.20260309`→`20260309`、`00.首批大货`→`首批大货`；原始 name、顺序和路径继续保留，未知名称不猜测裁剪。BOM、图号库、外发统一调用。

图号按产品/目录上下文取得当前有效物料中的转曲后实例；历史实例折叠。不把其他产品的文件充当当前文件。当前批次同图号多份候选存在歧义时显示选择提示，不擅自挑一份。缺失当前文件不能静默用旧版替换；历史文件可查看。当前/历史/停用/异常统一标签、文字与样式。

### BOM 编辑和展示（需求 3—13）

保留添加/查询分离。列表为业务日期、提交时间、最后修改时间、型号、独立操作区；查看详情与删除拉开距离。型号全历史删除折叠在危险操作菜单，普通删除只作用本次记录。去掉所有面向用户的 Vn，包括图号详情中的 BOM 引用文字。

编辑打开所选记录全部内容，保持记录 ID、created_at；保存更新 updated_at，使用整数 edit_revision 做并发校验。保留内部 version_number。明细按 ID 更新，删除明细须检查后续附件沿用关系；被沿用的附件及关系节点不能硬删除，保留兼容记录。编辑当前记录不新建完整 BOM；编辑历史记录不自动改变 bom_current。日期编辑后的查询顺序按业务日期/提交时间，当前指针不因排序变化自动切换。

字段：项目、图号、生效批次、材质、尺寸、图片、位置、位置示意图、修改明细。新增 change_details 存独立修改明细；旧 notes 作为兼容备注保留并在编辑时可见，不自动发送给供应商。新页面不维护二维码；保存时保留已有二维码关联，不因为字段隐藏清空数据。

详情四层：项目/图号/批次；材质/尺寸/位置；两种图片各自缩略图、归档名和打开位置；全宽修改明细。路径换行，危险操作独立。

### 附件归档

新附件保存为 `BOM附件/{型号}/{YYYYMMDD}/{项目}-{YYYYMMDD}[-位置示意图][-序号].扩展名`，相对资料根目录存储，UI 与落盘名称一致。保留格式、不转换图片；同名采用独占创建和序号，不覆盖已有文件。跨产品同型号也不能覆盖。

上传使用暂存区；保存 BOM 时依项目、业务日期和角色归档。日期改动或替换图片生成新的受管附件，旧文件保留以供历史/沿用引用。旧附件迁移使用“复制→校验哈希→更新关联”，不直接移动原文件；每个 BOM 引用按自己的型号/日期建立目标路径。记录迁移映射，失败可重试，旧路径继续可打开；缺失附件标记缺失，不清空记录。数据库迁移本身不做文件搬运，归档是独立可取消任务。

### 产品集中清理（需求 16—18）

建议采用最小风险方案：产品软删除退出当前业务，保留身份行供旧外键读取；用户在一个向导完成关联清理，无需逐模块操作。不进行大范围外键重建或级联硬删。

向导分类：当前业务、已删除记录、缺失索引、历史快照、跨产品引用。展示每一类处理结果并二次确认型号。当前 BOM 移除当前指针并软删除记录；所属图号默认删除保留占号，释放仍须显式选择并遵守 v13 检查；二维码退出当前业务；本产品实时文件/批次关联解除，索引清理不影响磁盘。存在其他产品有效 BOM/共享资料引用时列为明确阻塞，不连带删除其他产品数据。

外发、草稿和历史 BOM/附件快照保留。产品 deleted_at 使其退出新业务候选；保留删除审计和扫描抑制身份信息，重扫原目录不得静默重建该产品。清理在同一数据库事务内执行，执行前重检引用，失败完整回滚。已存在后台扫描/打包时不与清理并发，提示等待或取消任务。

### 外发单页流程与邮件（需求 19—23）

单页分步骤：产品→本次变更/当前完整→批次→变更项目与文件预览→确认打包→邮件编辑复制。联系人与模板仍复用现有管理资料。检查和打包保留一次明确用户确认。

按产品 ID 与生效批次 ID 匹配未删除 BOM 明细，旧数据仅在可唯一解析时用原始批次路径关联。读取 change_details，匹配同项目且相同正式图号的转曲文件；不能按文件时间取“最新”。存在多份 BOM 记录对同项目冲突时让用户选择对应记录，不猜测；缺失明细/文件明确显示，允许补录正文但不编造变更。

邮件按用户提供称呼、附件说明、编号修改内容、缩进新文件名、确认件要求、联系说明和签名生成。新文件去末尾 .pdf，不带路径、来源批次、ID 等内部字段。颜色有多个时不擅自写白色。生成后可编辑，重新生成前保护用户改动。保存邮件/外发时冻结产品身份、修改明细、图号与文件信息，后续 BOM 编辑不改历史邮件。

当前附件只有文字，没有所述截图；先以本次正文示例和现有视觉为准，不能声称已核对截图。

### 50MB 分包（需求 24、25）

以十进制 50,000,000 字节为硬上限，目标 49,000,000 字节留余量。单原文件超过硬上限时预检阻塞并显示实际大小；不切割 PDF。按稳定清单顺序以完整文件分组，生成后检查 ZIP 实际字节数，超过目标则重新分组；单文件 ZIP 超硬上限必须报错。介于安全目标和硬上限的单文件单独试打包并验实际大小。

单包保持现有名字，多包追加 -1/-2。新增 package_parts 记录一个外发业务包的多个文件，条目记录所属分包，邮件一次列全。旧单 ZIP 迁移为第 1 份但不重命名。每份先临时生成、全部校验后发布；取消/失败清理仅本任务新建文件。扩展现有 claim 恢复机制，崩溃后不得把半套 ZIP 标成完成；同名已存在输出不覆盖。

### 统一布局（需求 26—28）

共享状态样式与标签：当前/启用主色，历史弱化，停用/作废警示，缺失/异常错误。文字必须可区分，不只依赖颜色。产品二维码分行排列用途与状态，给列宽/折行留空间，不新增二维码模型。长路径弱化换行，按钮间距和危险区统一。

## 最小 Schema v14 提案及门禁

- bom_versions：updated_at、edit_revision；bom_items：change_details，以及必要的明细软删除标记以保留附件沿用节点。
- products：deleted_at、deletion_reason；二维码业务记录仅在确认现有字段不足时补 deleted_at，用于产品退出而保留历史关联。
- 产品集中清理审计表：确认范围、占号处理方式、时间和结果。
- outbound_package_parts：多 ZIP 路径、序号、字节数；条目所属分包字段。
- 外发包/邮件上下文：补产品身份与 BOM 修改明细快照字段；旧数据只从仍存在的关联行可靠回填，未知信息留空并标记，不能猜测。
- 受管附件归档映射：支持旧引用迁移的检查点与回滚，避免改一条共享 asset 路径影响全部历史记录。

实施前备份数据库并校验备份可读；测试 v13 副本升级、故障回滚、外键完整性及所有业务表数量/关键字段。以上为增量升级，无需重构正式/历史图号模型。产品退出方案和附件迁移属于需用户确认的具体数据边界。

## 实施顺序与验收

1. 固定 v13 基线，增加状态恢复、软删除计数和批次显示回归；修复不需 Schema 的明确问题。
2. v14 增量迁移与故障回滚测试；保留 v13 行与旧快照。
3. 批量图号预检/逐项执行/结果与取消；保留/释放、重扫抑制和号码重用回归。
4. BOM 原记录编辑、明细字段、附件归档和旧附件迁移；验证沿用链、冲突编辑和历史快照不变。
5. 产品清理向导、跨产品阻塞、软删除退出及重扫防恢复；在数据库副本上验证，真实清理由用户操作。
6. BOM→外发预览→邮件自动读取；多记录歧义与缺失明确提示。
7. ZIP 分包、大小边界、重复路径、取消/崩溃恢复、多包历史读取。
8. 单页外发动线、统一状态及布局；浏览器/桌面真实流程验证。
9. 单元、集成、E2E、类型检查、生产/桌面构建、code review。使用副本和临时文件测破坏性行为，不删除用户真实产品或资料作验收。
10. 启动预览，报告提交、分支、Schema、测试和限制；不合并 master。
