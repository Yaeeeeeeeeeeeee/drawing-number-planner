# 图号规划器——真实使用验收修正 Design Document

**日期：** 2026-08-31

**状态：** 待用户确认，禁止据此直接实施

**调查基线：** `codex/material-batch-usability` / `6a0db0f`
**当前数据库：** Schema v6

## 1. 目标与边界

本轮修正聚焦真实资料库验收中暴露的状态混淆与操作阻塞：扫描历史和当前磁盘状态没有分开、无法查看单次扫描差异、缺少安全的索引清库、历史图号没有独立业务状态、字典名称和启停规则不符合使用习惯、图号库批次明细过重，以及 BOM 仍缺少已确认的正式字段。

本轮保持以下既有事实不变：

- 正式图号格式、外观码、解析、查重、流水号推荐算法不变；
- 可靠解析并登记的历史图号永久占号，文件消失、清索引或停用均不释放号码；
- 数据库继续只保存资料根目录内的相对路径；
- 扫描和索引管理不移动、不删除、不重命名、不修改原始 PDF；
- 同一图号在不同资料批次出现是合法历史快照，不是重复错误；
- 本轮不开发二维码、服务器同步、完整外发、自动 BOM 或批量重命名。

## 2. 现状调查结果

### 2.1 代码与数据库基线

- 当前功能分支为 `codex/material-batch-usability`，HEAD 为 `6a0db0f`，工作区干净；该分支尚未合并回 `master`。
- Schema v6 已包含 `material_batches`、`pdf_files.path_key` 和 `pdf_files.material_batch_id`。
- `path_key` 是按 Windows 规则归一化的相对路径并有唯一索引；当前真实数据库没有同一路径重复索引。
- 数据库没有扫描运行表，也没有扫描差异表。`pdf_files.scanned_at` 只是每条索引最后一次被看到的时间，不能表示一次完整扫描。

### 2.2 2026-08-31 只读数据快照

| 项目 | 数量 |
|---|---:|
| `pdf_files` 累计索引 | 2,669 |
| 当前存在 (`is_present = 1`) | 2,360 |
| 旧扫描后已缺失 | 309 |
| 同一 `path_key` 重复 | 0 |
| `material_batches` | 134（133 已识别、1 待确认） |
| 历史永久占号 | 738 |
| 历史图号仍有当前文件 | 735 |
| 历史图号只剩缺失索引 | 3 |
| 跨多个资料批次复用的逻辑图号 | 428 |
| 正式规划图号 | 1 |
| BOM 版本 / 明细 | 1 / 1 |

结论：页面中的 2,669 是累计索引，不是当前磁盘文件数；当前资料库状态应显示 2,360。309 条旧记录可以作为缺失索引存在或被清理，但不得据此删除 738 个历史占号。

### 2.3 当前概念边界

| 概念 | 当前存储 | 发现的问题 |
|---|---|---|
| 字典编码 | `dictionary_items` | 名称修改错误地被“已引用”整体禁止；只有停用，没有重新启用入口 |
| 正式规划图号 | `drawing_numbers` | 生命周期已有 `reserved/active/voided`，保持不变 |
| 历史曾用图号 | `historical_drawing_numbers` | 永久占号正确，但没有“使用中/已停用”业务状态 |
| 当前 PDF 索引 | `pdf_files` | 有 `is_present`，但与扫描历史混在同一表的时间字段中 |
| 资料批次 | `material_batches` | 可判断当前/历史批次，但没有扫描运行归属 |
| 扫描历史 | 无独立实体 | 无法回答“这次新增、删除、变化了什么” |
| BOM | `bom_versions/bom_items/bom_current` | 仍按产品+颜色管理；无业务变更日期、批次、规格字段或图片能力 |

### 2.4 已确认的根因

1. **字典名称不能修改：** `DictionaryService.updateName()` 在写名称前调用 `isReferenced()`，把编码不可变和名称不可变混成一个限制。实际 API 只接收 `name`，本来就不会修改编码。
2. **停用后不能启用：** 表中已经有 `active/inactive`，但仓储、服务、路由和 UI 只实现 `deactivate`。
3. **层数重复入口：** `layer_count` 是 Excel 独立列和内部兼容字典，不参与正式图号字符串；当前 UI 又在主类别右侧加了“层数”Tab。可以完全只删 UI 入口，不动底层数据和算法。
4. **扫描累计与当前状态混淆：** 扫描先把所有 `pdf_files.is_present` 置 0，再按路径 upsert；旧行保留，汇总页面同时显示当前扫描数量和累计缺失数量，但没有保存“上一轮快照”或差异事件。
5. **历史图号与文件删除混淆：** `historical_drawing_numbers` 是永久占号表，`pdf_files` 才是可清理的文件索引。字典删除检查历史编码段是为了继续解释永久占号，不是因为磁盘文件仍存在。
6. **BOM 能力不足：** `bom_versions` 只有产品、颜色、内部版本、备注和 `created_at`；`bom_items` 只有项目、正式图号、数量、备注和白色共用标记；没有任何图片/图示资产表。

## 3. 核心领域模型

```text
字典编码（编码不可变，名称可改，支持启停）
        │
        ├── 正式规划图号 drawing_numbers ── 永久参与占号
        └── 历史曾用图号 historical_drawing_numbers ── 永久参与占号
                                      │
                                      └── 0..N PDF 文件实例 pdf_files
                                                   │
产品 ── 0..N 资料批次 material_batches ────────────┘

一次扫描 file_scan_runs
        └── 0..N 本次差异 file_scan_changes

BOM 产品级快照 bom_versions
        └── 1..N BOM 项目 bom_items
                    └── 0..2 图片/图示引用 bom_item_assets
```

关键约束：

- 占号状态由 `drawing_numbers` 和 `historical_drawing_numbers` 决定，不由 `pdf_files` 决定；
- 文件是否存在由最新成功扫描后的 `pdf_files.is_present` 决定；
- 扫描历史由不可变的扫描运行和差异快照决定，不反向冒充当前状态；
- BOM 的“生效批次”需要保存相对路径快照，不能只依赖可被清库的扫描批次外键。

## 4. Schema 分段方案

为避免 P0 文件索引修正与 P2 BOM 改造绑在同一次迁移中，采用两个窄版本。

### 4.1 Schema v7：扫描、索引与历史状态

#### `file_scan_runs`

| 字段 | 含义 |
|---|---|
| `id` | 扫描运行 ID |
| `started_at` / `completed_at` | 开始和完成时间 |
| `total_current` | 本轮实际扫描到的 PDF 数量 |
| `added_count` | 新增 |
| `missing_count` | 本轮删除/缺失 |
| `moved_count` | 路径变化 |
| `changed_count` | 同一路径内容变化 |
| `unchanged_count` | 无变化 |

只保存成功提交的扫描运行。扫描器、解析器或持久化失败时整批回滚，上一次当前状态和扫描历史均不改变。

#### `file_scan_changes`

| 字段 | 含义 |
|---|---|
| `scan_run_id` | 所属扫描 |
| `change_type` | `added/missing/moved/changed/unchanged` |
| `pdf_file_id` | 可空的当前索引引用，删除索引后可置空 |
| `relative_path` | 本轮相对路径快照 |
| `previous_relative_path` | 路径变化前的相对路径 |
| `file_name` | 文件名快照 |
| `full_code` | 当时可靠识别的图号快照，可空 |

差异明细保存快照字段，避免用户清理单个缺失索引后历史页面完全失去解释能力；“清空资料库索引”会按用户明确要求同时删除全部扫描历史。

#### `pdf_files` 增量字段

- `content_sha256 TEXT NULL`：用于可靠识别内容变化和唯一的路径移动配对；
- `last_seen_scan_run_id INTEGER NULL`：明确该文件最后在哪次成功扫描中存在；
- 保留 `path_key` 唯一约束和 `is_present`；不按图号、文件名或内容去重。

哈希采用增量策略：同路径且大小、修改时间未变化时复用已有哈希；新文件或元数据变化时只读计算 SHA-256。v7 后第一次扫描作为基线，避免把历史 309 条缺失索引错误统计成“本次删除”。

#### `material_batches` 增量字段

- `last_seen_scan_run_id INTEGER NULL`：标识批次最后一次实际存在的成功扫描。

#### `historical_drawing_numbers` 增量字段

- `status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','inactive'))`。

“使用中/已停用”只影响业务展示和默认筛选。占号仓储查询必须继续读取全部历史行，不加 `status = active` 条件。

### 4.2 Schema v8：BOM 正式字段与图片资产

Schema v8 独立于 v7，只有 v7 完成、备份和回滚验证通过后才执行。

#### BOM 版本（产品级快照）

`bom_versions` 目标字段：

- `product_id`：BOM 主体；
- `version_number` / `previous_version_id`：继续仅作为内部快照链，不在 UI 建复杂版本体系；
- `business_change_date TEXT NULL`：业务变更日期；迁移旧记录保持 `NULL` 并显示“未补录”，不得用 `created_at` 猜测；新记录服务层强制填写 ISO 日期；
- `notes`；
- `created_at`：变更提交时间，保留原时间；
- `legacy_color_id NULL`：只保存旧数据迁移前的顶层颜色语义，后续新 BOM 不再按颜色建立顶层主体。

`bom_current` 改为每个 `product_id` 一个当前版本。若升级前同一产品存在多个颜色各自指向不同当前 BOM，迁移不得猜测选择，必须失败回滚并先由用户处理冲突。当前真实库只有一个 BOM 版本，现状不构成冲突，但迁移测试必须覆盖冲突回滚。

#### BOM 项目

`bom_items` 增加：

- `effective_batch_relative_path TEXT NULL`：生效批次相对路径快照；
- `effective_batch_name TEXT NULL`；
- `effective_material_batch_id INTEGER NULL REFERENCES material_batches(id) ON DELETE SET NULL`：当前索引可选关联；清空索引后只断开外键，批次文字快照保留；
- `material TEXT NULL`：材质；
- `dimensions TEXT NULL`：尺寸；
- `position TEXT NULL`：位置；
- `notes`：备注。

现有 `quantity` 仅为旧数据兼容保留，固定为 1，不再作为 UI 或业务必填字段。项目、正式图号、白色共用规则保持现有校验；本轮不允许历史图号自动进入 BOM 候选。

#### BOM 图片和图示

新增：

- `bom_assets`：一条受管文件资产，保存相对于资料根目录的路径、原文件名、MIME、大小、SHA-256 和创建时间；不在数据库保存绝对路径或二进制 Blob；
- `bom_item_assets`：把一个 BOM 项目与 `image`（图片）或 `diagram`（图示）角色关联；同一项目每种角色最多一个；
- `inherited_from_bom_item_asset_id`：选择“沿用上一版”时指向来源关系。

新上传资产复制到集中管理的 `{资料根目录}\_图号规划器\BOM附件\{SKU}-{型号}\...`。不会移动或修改用户原文件。选择“沿用上一版”时，新 BOM 项目复用同一 `asset_id`，同时记录来源关系；不复制来源不明的新文件。若上一版对应项目没有该资产，保存前明确阻止并提示。

## 5. 扫描差异规则

成功扫描前先读取上一成功状态，扫描和哈希完成后在一个数据库事务中提交。

| 情况 | 分类 |
|---|---|
| 新 `path_key`，无法与唯一缺失旧文件哈希配对 | 新增 |
| 上轮存在，本轮没有，且未被移动配对 | 删除/缺失 |
| 新路径与唯一缺失旧路径 SHA-256 相同 | 路径变化 |
| 同 `path_key`，SHA-256 变化 | 内容变化 |
| 同 `path_key`，内容和显示路径均未变化 | 无变化 |
| 仅路径大小写/显示形式变化但 `path_key` 相同 | 路径变化 |

只有“一个新增 + 一个缺失”能够通过同一 SHA-256 唯一配对时才判断为路径变化；存在歧义时不猜测，分别显示新增和缺失。

扫描完成页同时显示：

- 当前资料库：当前 PDF、匹配、待确认、源文件、转曲后；
- 与上次相比：新增、删除/缺失、路径变化、内容变化、无变化；
- “查看本次变化”：`新增｜删除/缺失｜变化` 三个紧凑视图。

当前统计只使用本轮实际扫描到的文件，不把旧缺失索引计入当前 PDF。

## 6. 清空资料库索引

PDF 文件中心增加两段式确认：

1. 点击“清空资料库索引”后显示当前资料根目录和将删除的索引/批次/扫描历史数量；
2. 用户输入或确认固定短语“清空资料库索引”，再执行最终按钮。

事务内删除：

- `file_scan_changes`；
- `file_scan_runs`；
- `pdf_files`；
- `material_batches`；
- 扫描产生且只存在于上述表内的待确认结果。

绝不删除：

- 资料根目录中的任何文件；
- `historical_drawing_numbers` 永久占号；
- `drawing_numbers` 正式规划图号；
- 字典、产品、BOM；
- 工作区根目录设置。

清库服务不能调用文件删除 API。执行前后返回各表数量，并在事务后执行外键检查。重新扫描会从空索引建立当前状态；历史号码不会新增第二条或变为可用。

## 7. 历史图号、文件索引和删除语义

### 7.1 历史图号状态

- `使用中`：默认状态；
- `已停用`：不再作为当前业务使用提示，但仍永久占号；
- 状态可在历史图号详情切换；状态与源文件/转曲后文件存在状态分开显示。

### 7.2 删除规则

- **PDF 索引：** 当前缺失时可以单条、批量或全库清理；清理不释放图号。
- **历史永久占号：** 可靠解析并登记后不提供物理删除；文件后来删除不改变“曾使用”事实。若未来需要处理误识别，应另建有审计的“误识别纠正”流程，本轮不以普通删除绕过永久占号规则。
- **字典编码：** 若被正式图号、历史图号、产品、BOM 或父子字典引用，不能删除。即使原 PDF 已不存在，历史图号仍需要该编码名称解释；UI 应提示具体引用类型，而不是暗示磁盘文件仍存在。

## 8. 编码字典交互

### 8.1 名称修改

- 编辑接口继续只接受 `name`；编码字段只读并显示“已被业务使用，编码锁定”或“编码不可修改”；
- 删除 `updateName()` 对 `isReferenced()` 的阻止；
- 名称更新不修改字典 ID、编码快照或任何完整图号；
- 后续下拉、筛选和历史展示通过 ID 或编码关联读取新名称。

### 8.2 启停

- 新增 `activate` 仓储、服务和 API；启用时清空 `deactivated_at`；
- 启用中显示“修改｜停用｜删除”，已停用显示“修改｜启用｜删除”；
- 新建业务只加载 active，历史查询仍可加载 inactive。

### 8.3 层数入口

删除主类别右侧独立“层数”Tab及其新增/编辑入口，只保留“主类别 → 项目明细”。底层 `layer_count` 类型、已有 5 条数据、Excel 导入和相关测试夹具继续保留，不迁移、不删除、不加入正式图号字符串。

## 9. 图号库批次视图

“按资料批次”继续保留左侧批次列表和当前/历史判断。右侧默认不再展示完整路径和所有源文件，而是展示本批次的逻辑包材行：

```text
转曲后文件名                                打开位置
```

- 默认行以“本批次中的转曲后文件实例”建立；同一图号在该批次有多个实例时在展开区全部保留；
- 点击文件名展开该逻辑图号的“转曲后文件”和“转曲前源文件”；
- 展开区显示文件名、相对路径或“已缺失”、打开位置；
- 源文件优先按同一完整图号和同一 `{产品类别}\{SKU}-{型号}` 产品目录关联，可位于 `02.未转曲源文件`，不要求属于量产批次；
- 无法可靠识别图号的转曲后文件按单独文件实例显示，不擅自与源文件配对；
- 仍保留每一个实际 PDF 的索引 ID 和相对路径，不做跨批次去重。

图号库常用筛选压缩为一至两行：关键词/型号、SKU、产品类别、品牌、颜色、资料类型/项目、状态、检索。源文件/转曲后存在状态继续放入紧凑的高级筛选。

## 10. BOM 正式业务模型

### 10.1 页面职责

- `添加 BOM`：选择产品、业务变更日期，维护项目字段并保存产品级当前快照；
- `查询 BOM`：按型号、业务变更日期、生效批次、项目和图号查询，查看历史快照；
- `created_at` 在 UI 标为“变更提交时间”，不得冒充业务变更日期。

### 10.2 字段映射

| 用户字段 | 系统字段 | 数据来源 / 规则 |
|---|---|---|
| 产品型号 | `bom_versions.product_id` | 产品档案 |
| 业务变更日期 | `business_change_date` | 用户填写，新记录必填 |
| 变更提交时间 | `created_at` | 系统自动记录 |
| 项目 | `bom_items.project_item_id` | 编码字典项目明细 |
| 正式图号 | `bom_items.drawing_id` | 正式规划图号；现有状态/颜色规则不放宽 |
| 生效批次 | 批次相对路径快照 + 可选批次 ID | 当前资料批次选择；清索引后文字仍保留 |
| 材质 | `material` | 用户填写 |
| 尺寸 | `dimensions` | 用户填写 |
| 图片 | `bom_item_assets(role=image)` | 新上传或沿用上一版 |
| 位置 | `position` | 用户填写 |
| 图示 | `bom_item_assets(role=diagram)` | 单独的图示资产 |
| 备注 | `notes` | 用户填写，当前与历史均展示 |
| 数量 | 兼容列固定 1 | 不再显示或要求填写 |

### 10.3 兼容与迁移

- 旧 BOM 数据全部保留；旧记录业务日期显示“未补录”，顶层颜色作为 `legacy_color_id` 只读展示；
- 不把旧 `created_at` 回填为业务日期；
- 若同一产品迁移前存在多个颜色当前 BOM，v8 迁移失败并回滚，不自动合并；
- 新 BOM 以产品为主体，同颜色差异通过正式图号颜色和白色共用标记表达；
- 清空 PDF 索引不删除 BOM，生效批次外键可清空但路径快照保留；
- BOM 附件只保存相对路径，资料根目录迁移不改数据库业务记录。

## 11. API 与错误边界

新增或调整的 API 统一使用现有共享 request 层：

- `POST /api/dictionaries/items/:id/activate`；
- `POST /api/historical-drawings/:id/activate|deactivate`；
- `GET /api/files/scans/latest`、`GET /api/files/scans/:id/changes`；
- `POST /api/files/index/clear`，请求体必须包含明确确认值；
- 批次逻辑包材聚合查询；
- BOM v8 保存、查询和附件导入。

成功空响应仍可由共享 client 正常处理；非 2xx、非 JSON、204 和令牌刷新继续使用现有统一兼容层，不在页面散加 try/catch。

## 13. 安全与验收条件

1. v7、v8 均必须升级前备份；任一复制行数、唯一键、外键或业务冲突校验失败则整批回滚。
2. 用现有数据库副本验证 2,669 条累计索引、738 个历史占号、134 个批次、1 个 BOM 版本均不丢失。
3. 扫描 `E:\包材资料` 只读；当前统计必须等于本轮实际扫描数，跨批次文件全部保留。
4. 清库测试必须证明磁盘文件数量和哈希不变，历史占号数量不变。
5. 历史图号停用后，查重和下一流水号结果不变。
6. 字典改名后完整图号字符串逐条不变；停用、启用和受保护删除均有真实 API 回归。
7. BOM v8 迁移不伪造业务日期；图片沿用保留明确来源；索引清库后 BOM 仍可读取。
8. 完整测试、类型检查、浏览器构建、桌面构建、浏览器流程、Windows 桌面真实操作和 code review 全部通过后才报告完成。

## 14. 明确不实施

- 不删除或重新解释可靠历史占号；
- 不自动修复、移动或重命名历史目录；
- 不自动把最新资料批次写入或覆盖 BOM；
- 不让历史图号自动进入 BOM 候选；
- 不开发二维码、服务器同步、完整外发或多人权限；
- 不自动合并到 master，不自动开始下一正式 Phase。
