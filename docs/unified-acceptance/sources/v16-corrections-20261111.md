## 3. 跨模块数据与安全不变量

1. 产品内部 ID 是真实身份。SKU、品牌、型号文本不能代替主键；不能因文字相同自动合并产品。
2. 正式图号、占号状态、产品、BOM、PDF索引、实际文件、二维码记录、制图任务和外发快照是不同实体。
3. 停用不等于释放图号；删除 PDF 索引不等于删除实际 PDF；删除任务不等于删除正式 PDF、BOM或图号。
4. 扫描失败、目录不可访问、文件正在写入、读取超时或索引不完整，不能直接解释为文件已删除。
5. 正式文件和原始模板不得因失败重试、预览、索引更新或 UI 操作被覆盖或移动。
6. 重要文件操作先预检，再执行；必须有明确结果、失败项和恢复路径。
7. 数据库写入与文件写入不能出现“数据库已更新、文件只完成一半但 UI 显示成功”。
8. 历史关系、业务日期、不可变快照、外发记录和人工归属必须保留。
9. UI 状态不得冒充后端状态。任务完成、PDF已索引、图号已关联、文件已归档必须分别有真实依据。
10. 恢复入口只能恢复其明确支持的对象，不能承诺恢复已永久删除的任意物理文件。

## 4. P0｜T40 制图任务阻断性 Bug

**需求编号：BUG-T40-001**

### 4.1 用户报告现象

SAMKYO · T40 曾发生：
- 制图任务引用图号 `02.0101.010.0201005`；
- 用户删除图号后，任务仍然残留；
- 提示“旧PDF已强制脱钩，不能自动关联到重分配图号”；
- 相同错误重复显示；
- 任务状态显示“等待索引”，对应 PDF 却显示已确认；
- 任务无法删除或安全结束；
- 残留任务持续占用该型号，导致无法创建新任务。

以上是用户报告的现象。根因必须通过当前 V1.6 代码、任务记录、关联状态和隔离测试核查，不能凭猜测认定。

### 4.2 目标行为

1. 图号被删除、PDF 强制脱钩、文件索引失败或图号关联失败，不得让任务失去安全结束能力。
2. 任务安全结束/清理不得依赖 PDF 自动索引成功、旧图号重新关联、Illustrator 再次启动、文件重新生成或归档成功。
3. 结束/删除任务时，绝不自动重新关联已强制脱钩的旧 PDF。
4. 只有确认任务不再运行、没有未完成危险文件操作后，才释放该任务对型号的有效占用。
5. 外部进程仍运行、停止失败或状态未知时，不得强行释放锁；应保留异常状态和继续处理入口。
6. 任务执行状态与文件索引状态分别展示，不得用“等待索引”覆盖整个任务的可结束状态。
7. 同一错误不能循环刷屏，也不能阻断无关型号正常操作。
8. 结束任务不删除原始 PDF、AIT、BOM、正式图号、PDF索引或其他业务资料。
9. 保留“同一实际产品同一时间只有一个未完成任务”的保护，不得通过取消唯一性校验绕过 T40。
10. 处理结果必须明确：已安全结束 / 仍有运行风险、不能释放占用 / 需要人工处理。不得假报成功。

### 4.3 必测状态组合

图号仍存在/已删除/已释放；PDF已索引/等待索引/索引失败/不可访问/已强制脱钩；任务运行中/暂停/失败/待归档/完成/残留异常；Illustrator未启动/已启动/状态未知；任务正常停止/超时/失败。

### 4.4 验收

- 稳定复现原 T40 案例并证明修复；
- 图号删除后仍可安全结束任务；
- 强制脱钩 PDF 不会被重新关联；
- 安全结束后型号占用解除，可创建新任务；
- 停止失败时锁仍保留；
- 不删除实际文件、BOM、历史图号和索引；
- 相同错误不再重复出现；
- 报告真实根因、修改文件、数据库影响和回归结果。

## 5. 全局 UI、工作现场与交互

### 5.1 页面工作现场

**需求编号：UI-STATE-001**

用户反馈：在一个界面操作到一半，切换其他板块后，之前的操作消失。

要求：
- 每个模块分别保留自己的工作现场，不得互相覆盖。
- 模块切换、打开/关闭抽屉、返回列表、返回任务历史、刷新后，按模块规则恢复离开前状态。
- 尚未提交的表单、草稿和选择项不得静默丢弃。
- 至少考虑：当前模块/子页、搜索词、筛选、排序、滚动位置、展开项、当前产品/型号、勾选行、当前步骤、编辑值、已选文件、右侧详情对象、抽屉状态。
- 不同模块状态独立，不能把 BOM 草稿恢复到 PDF 页面或把一个产品草稿恢复到另一个产品。
- 对不适合跨重启保留的临时状态明确说明，不得声称全部自动保存。

验收：在 PDF 搜索/筛选/勾选/滚动后切到 BOM 再返回，现场仍在；图号工作台填到一半切换后返回，草稿仍在；BOM 编辑返回后内容仍在；各模块状态不串用。

## 6. 图号规划工作台

### 6.1 模式和流程

**需求编号：PLAN-MODE-001 / PLAN-FLOW-001**

只保留两种模式：
1. **新建图号：** 一个型号，可规划多个项目。
2. **批量规划：** 多个型号，每个型号独立选择项目，统一检查和占号。

统一四步：
1. 产品资料；
2. 选择项目；
3. 图号检查；
4. 确认占号。

布局：
- 当前步骤和状态清楚；
- 中间显示当前步骤表单或项目列表；
- 右侧显示完整图号、中文字段拆解、最后使用流水号、推荐流水号、查重结果及原因；
- 右侧不能只显示数字，每个数字必须有字段名称；
- 右侧调宽不能造成主表错位；
- 底部操作位置稳定；
- 不重复显示多套标题、相同图号或重复状态。

### 6.2 草稿与型号切换

**需求编号：PLAN-DRAFT-001**

- 新建模式和批量模式草稿独立。
- 每个型号各自保存项目、颜色、备注和步骤状态。
- 批量模式切换型号时，不得把上一型号项目选择带到下一型号。
- 切换模式不清空另一模式草稿。
- 离开页面、切换模块、返回工作台时保留未提交草稿。
- 用户明确删除草稿时才清除；删除草稿不能释放正式占用图号。
- 正式占号前重新核对产品启停状态、资料完整性和字典状态。
- 缺失字段明确指出，不得绕过档案校验。

### 6.3 图号唯一性和占号

**需求编号：PLAN-UNIQUE-001 / PLAN-CHECK-001**

- 不同项目不得产生相同完整图号。
- 不同产品型号不得共用正式图号。
- 不新增未经确认的流水号规则、占号批次编号或独立批次档案。
- 正式占号前必须查重；输入条件变化后旧查重结果失效。
- 查重结果失效后不得继续占号。
- 并发占号、重复点击、请求超时后重新核对真实占用结果。
- 占号成功显示正式结果；失败逐项显示原因。
- 删除 PDF 索引、结束任务、停用产品不能自动释放正式图号。

### 6.4 白色共用

**需求编号：PLAN-WHITE-001**

用户明确认为“白色共用”选项重复且多余，因为白色基本默认共用。

- 白色作为默认共用基准。
- 不在每个项目明细中重复显示“白色共用”开关。
- 同一项目明细出现非白色情况时，才体现该项目需要独立处理、不再沿用白色共用。
- 白色基准必须来自该产品真实存在的白色记录，不得凭空创建虚假记录。
- 不跨产品型号共用。
- 不得因隐藏选项而改变真实图号、BOM、颜色关联或历史引用。
- UI只显示用户需要判断的颜色与共用结果，不展示无业务意义的内部数字。
- 当前数据无法确定白色基准时提示缺少真实记录，不能自动创建。


## 7. 包材模板与 AIT 自动制图

### 7.1 模块职责与页面结构

**需求编号：AIT-STRUCT-001**

包材模板只负责模板、匹配规则和项目生成方式，不负责创建实际制图任务。

页面分为三个职责清楚的区域：
1. **AIT 模板管理：** 管理 AIT 模板记录、原始文件路径、适用范围和启用状态。
2. **模板匹配规则：** 维护项目、尺寸范围、品牌限制和冲突处理。
3. **项目生成设置：** 每个包材项目选择 AIT / 现成文件 / 人工制作方式。

制图任务必须独立成模块，放在“图号规划 / 更新包材”下面。模块拆分是入口和职责调整，不是创建第二套任务数据库；现有任务记录、状态和文件关联必须沿用。

### 7.2 AIT 原始文件与路径

**需求编号：AIT-FILE-001**

- 只有 AIT 模板概念，不增加 ALT 独立模块或菜单。
- AIT 原文件直接引用用户指定的原始路径。
- 不复制 AIT 到软件数据目录，不移动原始模板。
- 新增/编辑记录保存路径及模板元数据。
- 原始 AIT 在生成过程中必须保持不变。
- 路径失效时保留模板配置、匹配规则和历史关联，显示路径失效并提供重新定位。
- 重新定位后更新引用路径，不创建重复模板记录。
- 不因路径暂时不可访问而删除模板或规则。
- 模板替换不能静默改写旧任务的模板快照；历史任务应能说明实际使用的模板记录/路径。

### 7.3 项目生成方式

**需求编号：AIT-PROJECT-001**

- 每个包材项目独立设置制作方式：AIT 自动生成 / 使用现成文件 / 人工制作。
- 设置完成后长期生效；新建任务时自动读取，不要求每次重新选择。
- 不同项目可以使用不同方式。
- 非 AIT 项目仍纳入制图任务和 PDF 文件中心统一跟踪。
- 非 AIT 项目扫描 02/03 目录，准确关联完整图号后自动完成。
- 不得因项目是人工制作或现成文件而将其排除出任务、归档和索引。
- 不得把“人工制作”误判为无需文件；具体交付仍按项目要求处理。
- 不新增未经本轮明确确认的第四种方式；如果当前系统已有“无需生成”旧选项，先报告其历史用途和数据影响，不得直接删除旧记录。

### 7.4 AIT 自动匹配

**需求编号：AIT-MATCH-001**

用户已确认的选择：
- 根据产品已录入尺寸与包材项目自动选择 AIT；
- 默认跨品牌匹配，必要时增加品牌限制；
- 多重匹配先品牌限定，再比较尺寸精确度，仍不能唯一确定时提示冲突；
- 每个项目独立设置制作方式。

具体规则：
1. 匹配输入来自产品档案已经录入的真实尺寸和项目配置。
2. 尺寸只用于筛选/选择模板，不写入 AIT，不修改 Illustrator 内容。
3. AIT 模板的尺寸范围在新增模板时设置一次，不要求每次制图重新输入。
4. 默认允许长宽互换，高度不互换。
5. 缺少匹配所需尺寸时停止匹配，并明确指出缺少哪一项；不得按“最接近”猜选。
6. 默认跨品牌；只有规则明确设置品牌限制时才按品牌过滤。
7. 多个候选先应用品牌限制，再比较尺寸匹配精度。
8. 最终仍有多个同等候选时显示冲突列表，包含模板名称、尺寸范围、品牌限制和匹配原因。
9. 无匹配时明确提示没有符合条件的 AIT，不创建临时模板。
10. 生成前展示选中的 AIT 名称、可读文件名/路径、匹配尺寸范围、包材项目和完整图号。
11. 如果当前尺寸来源不完整或同一产品存在冲突尺寸，不得自行挑选；列出来源和冲突。

禁止：
- 自动使用“最接近”的模板；
- 默认按文件名、创建时间或上传顺序选模板；
- 把高度当作可互换维度；
- 自动补齐缺失尺寸；
- 修改 AIT 画板或缩放设计来适配尺寸。

### 7.5 图号对象识别与替换

**需求编号：AIT-REPLACE-001**

- 自动识别 AIT 中的完整图号替换对象，优先识别对象名 `DRAWING_NO`。
- 自动识别结果必须在生成前展示和校验。
- 无法唯一识别时，由用户人工指定一次并保存该模板映射；后续复用。
- 替换范围：所有文字内容完全等于原完整图号的对象。
- 同一模板存在多处完全相同的原完整图号时，全部统一替换。
- 只替换完整图号，不替换包含图号片段的其他文字。
- 不替换品牌、型号、颜色、尺寸、产品名称、日期、说明文字或其他字段。
- 不改变字体、字号、颜色、位置、旋转、段落、图层、对象层级和排版。
- 对象含额外前后缀或文本不是完全匹配时，不得擅自部分替换；提示用户确认映射。
- 替换后复查：目标完整图号已写入、原完整图号对象没有遗漏、其他对象未被修改。

### 7.6 PDF 输出

**需求编号：AIT-OUTPUT-001**

- 唯一生成成果为保留 Illustrator 编辑能力的 PDF。
- 不生成独立 AI 文件。
- 不把整页栅格化。
- 不改变画板、刀模、尺寸、设计和排版。
- 原始 AIT 不得被修改。
- 输出先写入当前任务临时目录。
- 目标 PDF 已存在时停止生成，提示用户查看已有文件；不覆盖、不自动重命名、不删除。
- 不增加逐次生成追溯日志；任务自身已有状态/结果记录仍应保留。
- 导出失败时保留原始模板和已有目标文件，显示失败原因。
- 只有实际使用 Adobe Illustrator、真实 AIT 和真实 PDF 验证后，才能宣称编辑能力保留。
- 不能用 Mock、脚本模拟或仅检查文件存在作为成功证据。

### 7.7 AIT UI

**需求编号：AIT-UI-001**

- 新增/编辑采用右侧抽屉。
- 列表密度为舒适型。
- 列表显示帮助用户判断模板的业务字段：模板名称、包材项目、适用范围/品牌限制、尺寸范围、启用状态、原始文件状态。
- 不能只显示内部数字 ID；任何编码数字必须配中文字段名或说明。
- 项目生成设置独立呈现，不藏在匹配规则页面下方。
- 普通配置使用中文、选项式交互；复杂内部参数键和尺寸轴不暴露给普通用户。
- 不增加复杂尺寸参数编辑器作为日常必经流程。
- 抽屉关闭后返回原列表位置和筛选条件。

## 8. 制图任务模块

### 8.1 模块入口与数据

**需求编号：TASK-STRUCT-001**

- 制图任务独立于包材模板。
- 放在左侧“日常工作”中，紧跟“图号规划 / 更新包材”。
- 从图号工作台已占号项目创建任务时，自动带入产品、完整图号、项目和生成方式，不要求重复选择。
- 迁移的是入口和页面职责，不是新建另一套任务数据。
- 保留既有任务记录、状态、历史、文件路径和索引关联。

### 8.2 任务唯一性和生命周期

**需求编号：TASK-LIFE-001**

- 每个实际产品/型号同一时间只允许一个未完成任务。
- 不同产品可并行拥有各自任务。
- 未完成任务应可继续，不得重复创建第二个任务。
- 运行、等待、暂停、失败、待归档等状态与真实任务阶段一致。
- 完成或安全终止后才释放有效型号占用。
- 停止失败、外部进程仍运行或状态未知时，不得强行释放占用。
- 任务执行状态与 PDF 索引状态分开。
- 任务恢复不能盲目重新启动 Illustrator 或重复生成已完成项目。
- 某项目失败不能阻止其他项目继续；批量结果逐项呈现。
- 单项目可独立重试；已完成项目不重复生成。

### 8.3 创建任务、文件夹和人工文件

**需求编号：TASK-CREATE-001**

- 从已占号项目创建任务时自动带入图号和产品。
- 任务内列出包材项目、制作方式、AIT匹配状态/现成文件状态/人工制作状态。
- 创建临时文件夹是制图任务的文件操作，不放在包材模板配置页。
- 创建前检查目标目录是否存在、可写、是否有同名任务。
- 已有任务优先继续，不创建重复任务。
- 支持人工提供 PDF 并将文件准确关联到项目和完整图号。
- 无法唯一匹配文件时必须人工指定，不能按相似文件名自动认领。
- 不覆盖用户已经人工修改的成果。

### 8.4 正式 PDF 修改

**需求编号：TASK-EDIT-PDF-001**

- 修改已归档正式 PDF，必须创建独立制图任务。
- 先将正式 PDF 复制到当前任务临时目录；不得直接修改正式文件。
- 用户在临时副本上修改。
- 归档前检查原正式文件是否发生变化。
- 替换前备份原正式文件。
- 验证新 PDF 可读取、图号正确、文件完整后才允许正式替换。
- 替换失败时原正式 PDF 保持不变，临时成果保留。
- 不生成独立 AI 文件。
- “保存”不能直接写入正式 PDF 路径。

### 8.5 归档与结束

**需求编号：TASK-ARCHIVE-001**

- 新生成且检查通过的 PDF 归档到 `02.未转曲源文件`。
- 量产后的变更文件按现有目录规则归档到 `03.量产后的变更文件` 对应批次。
- 归档前检查产品、项目、完整图号、文件可读性、目标路径、同名冲突、未完成项目。
- 归档按项目逐项处理，不能因一项失败而将其他项假报成功。
- 部分归档失败时保留成功项和失败项，支持失败项重试。
- 若当前系统已有准确状态，优先复用，不擅自另造一套状态机。
- 删除/结束任务不删除实际文件、图号、BOM或正式 PDF 索引。
- 任务历史可查看，但已安全结束的历史任务不得继续错误占用型号。

## 9. PDF 文件中心

### 9.1 扫描范围和入口

**需求编号：PDF-SCAN-001**

- 所有启用产品自动监听 `02.未转曲源文件` 和 `03.量产后的变更文件`。
- 保留当前型号扫描和全库扫描。
- 增加“扫描当前类别”入口。
- 左侧产品/型号选择决定实际扫描范围；右侧文件类型、批次、状态、日期只过滤扫描后的结果，不能缩小后台扫描范围。
- `02.未转曲源文件` 按当前约定目录扫描。
- `03.量产后的变更文件` 遍历所有历史日期批次，不遗漏旧批次。
- `00.临时文件` 不进入正式 PDF 索引。
- 保留自动监听、增量扫描、手动扫描和启动补充检查。
- 扫描目录以当前 V1.6 已配置的真实资料根为准，不擅自切换服务器路径或新增扫描根。
- 目录之外的 PDF 不得因文件名相似而自动归入正式索引。

### 9.2 扫描状态与进度

**需求编号：PDF-PROGRESS-001**

- 列表显示上次扫描状态。
- 详情显示实时检查结果。
- 扫描过程显示真实阶段、处理数量、失败/跳过数量。
- 超过500条自动分批执行。
- 每批结果成功后再继续下一批；某批失败不得让全库状态被误报为完成。
- 总量准确可得时显示百分比；总量未知时显示已处理数量和阶段，不伪造总量。
- 扫描完成明确显示完成、部分完成或失败。
- 目录暂时不可访问与文件真实缺失分开。
- 扫描未完整覆盖的目录不得批量触发缺失判定。
- 返回页面后能看到最新扫描状态，不得永远停留在“正在扫描”。

### 9.3 列表、筛选和选择

**需求编号：PDF-LIST-001**

- 筛选默认关闭，从右侧打开；已有条件保留，筛选条件即时生效。
- 关闭筛选浮层保留条件；条件可见、可清除。
- 修改筛选时清空原勾选，避免批量操作隐藏文件。
- 只有有选择时才显示批量工具栏。
- 普通单型号切换清除旧选择并回列表顶部；明确开启多型号模式后才允许跨型号选择。
- 选择型号不等于自动勾选全部文件。
- 显示文件数、型号数，并能查看已选文件。
- 开关浮层、调整列宽、勾选不丢当前浏览位置。
- 扫描更新尽量保持当前文件仍可见。
- 图号 + 文件类别分组；02源文件和03量产变更文件不混组。
- 多版本默认收起；单文件直接显示，不额外增加展开步骤。
- 搜索命中历史文件时自动展开并定位。
- 汇总行不是实际 PDF，不能当作文件执行打开/删除/归档操作。
- 折叠不清除已选实际文件；缺失提示不得因折叠而隐藏。

### 9.4 文件点击和内置阅读器

**需求编号：PDF-VIEW-001**

用户反馈文件只能查看路径和“打开位置”，不能直接打开查看。必须提供直接查看能力。

交互：
- 单击行：选中该行。
- 单击文件名：打开/切换文件详情。
- 双击文件行：打开完整内置 PDF 阅读器。
- 勾选框和操作按钮只执行自身动作，不顺带打开详情。
- 保留 Windows 默认程序打开入口。
- 文件不存在或不可访问时不执行虚假打开，并显示准确原因。

阅读器：
- 独立阅读工作区，不塞入狭小浮层。
- 支持页码跳转、上一页/下一页、缩放、适合页面、适合宽度、旋转。
- 支持可收起缩略图。
- 支持可识别文字搜索。
- 支持全屏、打印、Windows 默认程序打开。
- 关联/文件信息区可收起。
- 只读查看，不修改原 PDF。
- 打开失败时显示错误，不改变原始文件。

### 9.5 文件日期、归属和删除

**需求编号：PDF-META-001**

- PDF 业务批次日期以业务批次规则为准，不以磁盘修改时间代替。
- 允许人工调整 PDF 所属产品和业务批次，但必须有明确目标、预检和结果。
- 人工调整归属不自动改写文件内容或图号。
- 删除索引不删除物理文件。
- 删除空文件夹前必须真实扫描确认为空；目录不可访问/扫描失败时不能当作空目录。
- 文件缺失、不可访问、读取失败、索引缺失、扫描未完成必须分别显示。
- 不得通过清空数据库、重建全部索引或把缺失数归零掩盖问题。


## 10. BOM 管理

### 10.1 编辑态残留

**需求编号：BOM-EDIT-001**

用户反馈：在查询 BOM 中编辑现有 BOM 并保存，再次点击编辑，仍然出现上一次修改，而不是最新已保存内容。

目标：
- 每次打开编辑时，根据真实 BOM 记录 ID 从持久化数据重新加载当前已保存版本。
- 保存成功后清除旧的临时编辑态、dirty 状态和缓存草稿。
- 再次打开必须显示数据库中最新已保存数据。
- 不能把上一次编辑的 React 状态或旧查询缓存当作正式数据。
- 保存失败时保留当前输入，显示具体错误。
- 重新打开另一条 BOM 时不能带入上一条 BOM 的字段、附件、项目或图号。
- 并发版本/修订校验继续生效；不得为了修复缓存而取消并发保护。

验收：
1. 打开记录A，修改字段并保存；
2. 关闭编辑，再次打开记录A，显示最新保存值；
3. 打开记录B，不得显示记录A的临时值；
4. 保存失败后输入仍在；
5. 刷新页面后仍显示数据库中的最新值。

### 10.2 新增入口与表单重置

**需求编号：BOM-CREATE-001**

- 新增 BOM 入口必须明显，不能藏在不易发现的次级操作或数字图标中。
- 新增字段按业务分组，标签和输入框一一对应。
- 新增成功后清空本次临时项目行、图片选择、位置示意图选择和待提交状态。
- 保留成功提示和当前业务上下文。
- 新增失败时保留输入。
- 不删除已保存记录。
- 不擅自增加 BOM 数量字段、额外版本管理系统或用户未确认字段。
- 类别、型号、项目、图号、业务日期、材质、尺寸、位置、图片、示意图、修改明细和备注等既有字段按现有业务规则保留。

### 10.3 查询和历史

**需求编号：BOM-QUERY-001**

- 继承已确认筛选：型号、主类别、项目明细；另保留时间范围和图号搜索。
- 产品类别显示在产品型号前。
- 查询表格项目明细列清楚可见；型号和项目明细按既有居中规则呈现。
- 图号关联使用精确记录 ID；记录删除或不可访问时明确提示，不跳转相似记录。
- 首次 BOM 与当前 BOM 必须区分。
- 修改业务变更日期不能覆盖其他历史记录。
- 保留附件、图片、位置示意图和历史快照。
- 图片内容比较采用已确认的解码像素比较；若格式/透明通道处理方式在现有实现中不明确，先提交技术说明，不得擅自改为视觉近似判断。

## 11. 产品档案、二维码和菜谱

### 11.1 产品档案

**需求编号：PRODUCT-001**

- 产品档案型号显示统一为“品牌 · 型号”，不显示 `#17` 等内部数据库编号。
- 仅改变显示，不改变产品主键和业务关联。

- 表单标签、必填提示和输入框关系清楚。
- 用户已确认产品允许按安全规则停用/删除，并有相应恢复/处理入口；执行时必须遵守现有产品清理预检和受保护引用规则。

- 删除失败必须解释具体阻止原因，而不是按钮无反应。

### 11.2 二维码管理

**需求编号：QR-001**

- QR 文件由用户直接上传/选择，不要求自动生成二维码图片。
- 业务核心是对应网址能够正常打开；二维码文件本身是否能被独立 PDF 阅读器打开，不是核心验收标准。
- 用户必须主动点击“启用”后才启用；上传或保存不能自动启用。
- 产品档案“未配置”点击后跳转二维码管理，并自动带入当前产品信息。
- 列表能够显示没有二维码记录的产品，方便用户新增用途。
- QR/图片相同的比较采用解码后的像素比较，不只比较文件名或路径；不能把视觉近似算法擅自作为等价规则。
- 网址必须来自真实 QR 记录，不能从文件名拼接。
- QR 历史关联和产品身份保留；解除关联不等于删除原文件或删除 QR 历史。
- 停用/删除及恢复规则按用户已确认的安全边界执行；不能删除有受保护历史的记录。
- **二维码管理是否完全合并到产品档案尚未批准为本轮删除独立入口的要求。** 本轮先实现“未配置”跳转、产品上下文带入和现有流程修复；不得删除独立二维码管理入口。

### 11.3 菜谱用途

**需求编号：QR-RECIPE-001**

- 只有部分产品类别允许配置。
- 具体允许类别名单尚未明确，不得由 Codex 自行猜测。
- 不得把菜谱配置项展示在所有类别。
- 在类别名单未配置或未确认时，不得向所有类别开放菜谱；应按现有真实业务配置显示，缺少配置时提交待确认清单。
- 其他二维码用途不受影响。

### 12.2 迁移检查与邮件模板导入

## 13. 外发资料与邮件草稿

### 13.1 外发选择和批次

**需求编号：OUT-001**

- 保留原四步外发工作台。
- 外发以用户明确选择的产品、批次和文件范围为准。
- 不强制 BOM 必须先存在。
- 不自动从历史批次补齐未选择的文件。

- 不覆盖旧 ZIP；输出路径存在同名文件时停止并提示。
- 失败时只能清理本次任务自己的临时输出，不删除无关 ZIP、原始 PDF 或包材文件。

### 13.2 50MB 规则

**需求编号：OUT-50MB-001**

用户最新确认：
- 原始 PDF 单文件超过 50MB，允许进入外发清单。
- 必须提示该文件需要独立传输。
- 超过 50MB 的原始 PDF 不纳入 ZIP。
- 不拆分 PDF，不修改原始 PDF 内容来规避限制。
- ZIP 最终文件大小不得超过 50MB。
- ZIP 以完整 PDF 为单位组织，不允许将一个 PDF 拆成多个片段。
- 如果某个 ZIP 仍超过上限，应重新按完整文件分包；若单个文件本身超过上限，提示独立传输。
- 外发清单中仍保留该大文件记录和独立传输提示，不能静默排除。
- 生成结果列明进入 ZIP 的文件、独立传输文件、未纳入文件及原因。
- “原始文件允许进入外发清单”不等于“原始文件允许进入 ZIP”。

### 13.3 邮件草稿恢复

**需求编号：OUT-DRAFT-001**

- 邮件只生成可编辑草稿，不自动发送。
- 邮件草稿必须在软件关闭并重新打开后能够恢复。
- 草稿与本次外发任务/产品/批次/文件范围正确关联。
- 用户手动修改过的主题、收件人、抄送和正文不得被异步刷新或重新生成静默覆盖。
- 恢复时显示草稿保存时间及关联外发任务；无法确认关联时提示用户，不自动拼接。
- 保存失败保留当前编辑内容并明确提示。
- 草稿恢复不等于重新生成 ZIP，也不自动发送邮件。
- 不得因旧草稿表存在就宣称当前邮件编辑器已经实现重启恢复；必须真实关闭程序再启动验证。

## 14. 数据库重新选择与安全回退

**需求编号：DB-SWITCH-001**

用户已确认增加正式数据库重新选择入口。

目标流程：
1. 用户在正式数据库选择入口选择数据库文件。
2. 选择完成后直接开始兼容性检查，不再跳转文件管理器要求第二次选择。
3. 检查至少包括：文件可读、SQLite 格式可识别、完整性检查、Schema 版本支持情况、关键表/迁移状态、必要业务结构检查。
4. 检查通过后显示将切换到的数据库信息并执行切换。
5. 切换成功后验证应用真实读取新数据库，核心页面可以正常加载。
6. 检查失败或切换失败，继续使用原数据库并回退原配置，不得留下半切换状态。
7. 不自动合并两套数据库，不复制一套数据覆盖另一套。
8. 不因数据库文件选择错误而删除原数据库或备份。
9. 切换前必须完成一致性备份和必要校验；备份失败时停止切换并提示。
10. 保留现有自动备份机制；不新增独立完整备份/恢复中心 UI。完整资料备份/恢复继续由用户按既有方式人工操作。
11. 不把“切换数据库”包装成“迁移合并数据库”；未来如需合并，必须另立需求。

验收：
- 健康兼容数据库可检查并成功切换；
- 损坏数据库失败后仍可使用原数据库；
- 更高版本/不支持 Schema 明确拒绝并保留原库；
- 中途失败或程序重启后原数据库仍可恢复使用；
- 不发生自动合并、覆盖或数据清理。
