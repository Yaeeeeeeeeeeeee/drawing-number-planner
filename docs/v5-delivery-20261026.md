## 原因及关键修复

- 大 PDF：旧预检把大于 50MB 的原始文件排除，并将无法读取的事实统称为缺失；ZIP 校验还限制了单项解压尺寸。现在按真实路径/存在/读取结果检查，校验大小取实际源文件事实。不可压缩且单个实际 ZIP 超限会明确阻止生成，不拆改 PDF、不默默丢文件或放宽上限。
- 图片假差异：原比较只看附件 ID/路径等关联身份。现在可信 SHA256 相同即认定内容相同，缺少哈希时保留不确定。不同字节但视觉相同尚不能可靠确认，不将感知近似当业务相同，不声称已实现视觉语义判同。
- 外发类别：产品类别与编码字典的 productSizeId 没有一一对应约束；旧分组会将同 ID 的不同类别覆盖。现按真实类别分组、产品 ID 选择，回归覆盖同字典 ID 不同类别。
- BOM 查询按钮遮挡：旧 CSS 将查询与新增重置按钮固定到同一网格格子。现使用可换行的弹性布局；实际点击回归保留，不以强制点击绕过。
- 开发预览启动：浏览器目录判断间接导入 Node path。拆出共用纯函数模块，浏览器和服务共享同一规则，保留服务路径构建逻辑。
- BOM 查不到：重置可见筛选后，查询仍携带编辑上下文的隐藏外观 ID。现七项查询仅提交可见查询条件，不改编辑归属或旧记录。
- 强制释放：保留旧图号行作为不可恢复的历史身份，原 BOM/外发快照不改写；实时 PDF 关系解除并进入待确认。保存原索引/外发快照中旧路径，且对曾强制释放的完整图号禁用自动重扫绑定。后来显式关联到新身份的文件，只有索引身份和 SHA256 未变时才保留确认；换内容或丢失索引重新待确认。旧图号 ID 不复用，重新占用使用新身份。

## 数据库兼容与恢复

Schema21 新增强制释放事件及文件隔离表，并更新相应占号保护触发器；Schema22 仅增加 email_templates 的 manufacturer/scenario 可空字段。迁移在事务外先备份并验证，事务内核对旧列、每行历史数据及外键；任何失败回滚。真实磁盘 Schema20 首次启动升级及重启幂等、两个新增迁移故障回滚已验证；较早 Schema 升级回归保留。

不自动执行 ZC100 归并，不清空数据库，不删除磁盘 PDF/图片，不通过停用释放号码。普通删除保护与强制释放入口明确分开。回退使用 v1.0.0 程序及配套 Schema20 升级前备份，不能用旧程序直接打开 Schema22。
