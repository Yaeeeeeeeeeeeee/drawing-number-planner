## 检查及方案

原产品档案分开SKU/型号/品牌/类别，附加动态用途列，行内展开详情/编辑/删除；QR入口只传记录ID，无法进入未配置用途，返回卸载列表导致筛选/滚动丢失。

沿用DataTable及现有查询、编辑、状态和受保护清理接口：八列为SKU / 型号、品牌 / 类别、产品规格、状态、说明书、售后卡、菜谱、操作。产品规格用现有品类尺寸与外观。只有编辑操作，不提供详情按钮或展开行；编辑是同模块内独立工作区，原字段、参考来源、启停和完整清理预检/型号确认保留。

QR业务状态直接读取记录status，不用文件存在性推断。零条是未配置，一条依真实状态；防御性支持多条时，有任一active显示已启用，否则已停用，同时显示总条数，提示已启用数量，点击显示全部对应记录，不选任意一条。当前Schema仍唯一(product_id,purpose_id)，多条仅作为容错导航测试，不改业务定义或制造数据库记录。

跳转携带productId、sku、model、productCategory、purposeKey、中文及英文用途。英文为User Manual / Warranty / Recipe，查询按现有稳定key与用途ID定位，不凭名称相似猜测。单条核对产品/用途后打开详情；多条展开目标产品列表；未配置预选产品和用途，仅显示配置表单，不发创建或启用请求。用途缺失/停用明确提示，不回退到第一个用途。产品停用时新建保存禁用并说明原因，沿用现有服务仅允许启用产品新建的规则；已有记录仍可管理，不自动改变产品状态。

AppShell仅在首次访问后保留产品页面挂载，切换时hidden，避免丢失筛选草稿/已提交查询/列表内部状态。QR返回有明确入口；产品页重新加载已提交查询与最新QR状态，并恢复表格双向及主工作区滚动。通用二维码导航会重置到通用页面，不意外保留产品用途上下文。原产品表没有分页，仍展示完整结果，不新增截断/结果上限，未来表格分页状态亦不会因这个跳转卸载。
