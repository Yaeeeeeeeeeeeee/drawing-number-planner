# P4 BOM 查询历史对照（2026-10-16）

本轮仅调整「BOM管理 → 查询BOM → 所选记录详情」，基线5d55e48，独立分支 `codex/p4-bom-history-comparison-20261016`。用户本轮明确授权先检查、明确匹配方案后实施；不合并master，不进入P5，不修改业务数据。此前各阶段验收记录保留。

## 检查与实施方案

实施前检查了本地drawing-number-planner Skill、Schema/迁移、BOM repository/service、查询组件、附件预览及已有测试，并在聊天说明以下方案后实施：

- 仅根据记录自身 `previousVersionId` 读取上一条；核对记录ID和productId，拒绝自引用、直接循环和错误关系。读取失败与无读取能力显示原因，绝不按日期/列表顺序猜测，也不当作首次记录。
- 当前Schema在每版内保证 `projectItemId` 唯一。对同产品前后版本以该业务身份匹配，不使用bomItemId、图号、名称或列表位置。重复/无效身份保留各侧原资料，显示待确认，不臆造新增/删除。删除项目从上一条项目集合补入。
- 差异为查询专用纯函数，比较实际字段和引用：图号来源/ID/完整图号，批次ID/原路径/原名称，已有数量、白色引用、材质、尺寸、位置、修改明细、备注、排序后的二维码关联ID。新版本生成的行ID、附件关联行ID和继承记账信息不是业务内容变化。
- 主类别/项目名称、图号业务状态及二维码名称是当前关联查询值，并非完整历史名称快照；界面明确说明，不将这些实时标签变化伪装为历史修改。未增加Schema或接口来推断历史名称。
- 附件按原role与assetId展示；双方有效SHA-256不同才标内容替换，一致只称「记录内容摘要一致」，不等同于磁盘内容已验证。仅关联元数据变化单独说明。缺失摘要/重复role显示待确认，不以同名文件推断内容一致。

## Windows本机待验收

使用已经存在的真实库或明确标记的旧样例，以只读查看器浏览，关闭正式应用并保留原库；不要新建记录来满足本轮验收。真实资料不足的场景记录为未验证。

1. 有前版且有字段修改：摘要与实际项目核对，默认只看到变化字段；全部字段完整，前版在左、所选在右。
2. 完全相同：未变化数量正确、默认折叠；展开后可查看全部字段，无假高亮。
3. 首次记录：完整单侧资料，明确首次提示，没有虚假修改数；前版读取失败则显示失败而非首次。
4. 新增、删除：数量及各侧资料正确；删除项目仍能查看旧资料和旧附件。
5. 项目顺序调整：原业务身份对应不变，不计新增/删除；不明确身份显示待确认。
6. 附件缺失、校验或预览失败：状态真实，重试有效，失败不阻断资料；打开位置仅指向正确的历史原关联。
7. 长图号/文件名/修改明细：全文可读，复制图标内容准确，路径按需展开不撑破页面。
8. 多项目全部展开/收起，单项模式切换；快速切换记录/刷新同条记录不混入前一次异步结果。
9. 3840×2160、2560×1440、1920×1080、1366×768及非最大化窗口；再检查Windows125%/150%/200%实际可用CSS尺寸，按钮/滚动均可访问。
10. 比较只读前后业务计数/摘要，确认历史快照、占号、PDF及外发历史不变。不执行保存、扫描、清理、打包或迁移。
