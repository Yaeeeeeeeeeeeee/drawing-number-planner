# 图号规划器｜新一轮全系统修改需求 V5.0

项目：`Yaeeeeeeeeeeeee/drawing-number-planner`

## 一、总体执行要求

本次是对现有图号规划器进行功能修复、交互优化和界面精简，不是重新开发系统。

请先读取项目 Skill 及必要的业务规则、Schema 和相关代码，再实施修改。

总体原则：

1. 本轮所有问题都要检查全系统是否存在同类问题，不能只修截图对应的页面。
2. 优先修复共用组件及共用逻辑，避免各页面重复打补丁。
3. 界面保持简洁、紧凑、清晰，减少说明文字和无意义留白。
4. 保留现有图号编码、产品 ID、历史 BOM、外发历史等核心业务规则。
5. 不得因为 UI 调整而破坏数据关联。
6. 修改过程中分阶段提交和测试，保留可回退节点。
7. 没有明确要求删除的业务功能不要擅自删除。
8. 无法确认的数据逻辑问题应先定位原因，不允许简单掩盖错误。

## 二、全系统表格交互与布局统一

### 2.1 删除表头拖动手柄

所有支持拖动列顺序的表格，移除表头前面的六点拖动图标。

要求：

- 直接拖动表头名称或表头空白区域即可改变列顺序。
- 列宽调整仍通过列边界进行。
- 保留列顺序、列宽记忆及恢复默认布局功能。
- 拖动过程中应有明确的位置反馈。
- 不允许拖动排序与列宽调整互相冲突。

### 2.2 删除表格操作提示

全系统删除类似以下说明：

「拖动表头换序 · 列边调宽」

不需要替换成其他小字。

删除后收紧上下间距。

### 2.3 表格宽度自适应

当前问题：缩小某一列后，表格右侧会出现大面积空白。

要求：

- 表格整体至少占满所在容器的可用宽度。
- 缩小某列时，剩余宽度优先由最右侧实际列自动填充。
- 最右列根据当前列顺序确定，不固定为某个字段。
- 内容不因列宽拉长而改变对齐位置。
- 所有列达到最小宽度仍无法容纳时，允许横向滚动。
- 不允许文字重叠、列边界错乱或强行逐字换行。
- 窗口缩放、侧边栏展开收起后重新正确计算布局。

### 2.4 全系统列内容对齐

统一规则：

| 内容类型 | 对齐方式 |
|---|---|
| SKU、型号、品牌、名称、文件名 | 左对齐 |
| 状态、数量、日期、颜色 | 居中 |
| 关联文件状态 | 居中 |
| 操作按钮 | 整组居中 |
| 复选框 | 居中 |
| 图号 | 按所在表格的既定规范统一 |

特别修复：

- 编码字典「操作」列拉宽后，按钮仍靠左。
- 「关联文件」表头及「未配置」内容未居中。
- 其他状态标签或操作按钮随列宽变化而偏移。

居中必须相对于整个单元格，而不是某个固定宽度的内部容器。

### 2.5 冻结表头

以下页面必须支持向下滚动时表头固定可见：

- 产品档案
- 二维码管理
- PDF 文件中心

其他使用相同长列表组件的页面，也要检查是否需要沿用相同机制。

要求：

- 只冻结表头，不冻结数据行。
- 冻结后仍可调整列宽和列顺序。
- 表头与数据列始终对齐。
- 横向滚动时表头和数据同步移动。
- 不遮挡上方筛选栏或工具栏。
- 冻结位置以实际表格滚动容器为准。

### 2.6 修复窗口缩放后的左侧空白

图号库在窗口缩小或侧边栏收起时，左侧出现异常空白。

要求：

- 顶部菜单按钮与页面标题放在同一行。
- 页面标题紧跟菜单按钮。
- 页面内容不再为菜单按钮单独预留一条宽区域。
- 筛选区、表格和正文使用统一左边界。
- 侧边栏收起后，主内容自动利用释放的空间。
- 不通过负边距等临时手段掩盖布局问题。
- 全系统检查采用相同顶部菜单结构的页面。

3. 重要错误原因、操作风险、必填校验仍需清晰显示。

5. 避免出现大面积空白卡片、过宽字段列和不必要的嵌套面板。
6. 文本优先单行展示，空间不足时合理截断或局部换行，不允许字符逐个竖排。

## 五、PDF 文件中心

### 5.1 修复文件筛选区域

当前「筛选 PDF」按钮显示异常，文字和背景几乎融为一体。

要求：

- 按钮正常显示，启用、禁用状态均清晰可辨。
- 不被容器底部或滚动条裁切。
- 点击筛选功能正常。
- 缩小筛选面板整体宽度。
- 减小不必要的横向占用，让 PDF 列表获得更多空间。
- 保留现有筛选条件。

### 5.2 空批次删除与索引清理

重点案例：

产品 IM12，批次 `20260211`，左侧显示 0 个 PDF，但系统提示仍被约 10 条 PDF 索引引用，无法删除。

要求：

1. 对扫描确认没有 PDF 的空批次，允许删除。
2. 不得仅凭失效索引的存在就禁止删除。
3. 删除时同步清理属于该批次的失效 PDF 索引及目录关联。
4. 不误删其他产品、其他批次的文件索引。
5. 对仍被图号、BOM、外发历史引用的数据，保留必要历史记录。
6. 删除成功后立即刷新目录树及文件数量。
7. 文件夹无法访问、扫描失败时，不得直接视为零文件。
8. 不删除磁盘真实文件夹或原始 PDF。

检查现有的引用统计和删除校验，区分有效引用与残留索引。

### 5.3 PDF 扫描目录范围

产品目录内，只识别以下两个指定目录及其有效子目录：

- `02.未转曲源文件`
- `03.量产后的变更文件`

要求：

- `02.未转曲源文件` 下的 PDF 归入所属产品的「未转曲源文件」节点。
- 该节点不作为生产批次，也不显示当前批次或历史批次标签。
- `03.量产后的变更文件` 下的 PDF 按实际资料批次归类。
- 产品根目录及其他非指定目录中的 PDF 不纳入该包材资料扫描索引。
- 即使文件名包含图号、型号，也不能绕过目录规则。
- 已误扫描的范围外索引应安全清理。
- 不能因此释放正式或历史图号。
- 不移动、不重命名、不修改任何原始文件。

例如产品根目录直接存放的 `ZC200（WB55）-User Manual...pdf`，不应纳入本套 PDF 文件中心扫描。

注意：此目录限制只适用于对应包材资料扫描流程，不能错误应用于二维码管理等具有独立文件来源规则的模块。

### 5.4 未转曲 PDF 归类

对于位于 `02.未转曲源文件` 目录的 PDF：

- 不再显示为「未归入批次」。
- 显示在所属产品的「未转曲源文件」分类下。
- 保留转曲前后文件的图号关联。
- 不计为新的生产批次。
- 不重复计数。
- 不改动磁盘目录。

### 5.5 文件存在性判断

全系统统一检查：

- PDF 文件中心
- 图号库
- 外发资料

不得出现同一文件在磁盘存在、PDF 索引可查，但其他模块显示「缺失」的情况。

必须区分：

- 磁盘文件不存在
- 索引未更新
- 文件路径失效
- 文件关联错误
- 文件读取失败

不能全部笼统显示为缺失。

## 六、BOM 管理

### 6.1 添加 BOM 增加产品类别

原字段：

`录入类型 → 产品型号 → 业务变更日期`

改为：

`录入类型 → 产品类别 → 产品型号 → 业务变更日期`

要求：

- 产品类别读取现有产品档案。
- 产品型号根据产品类别联动筛选。
- 切换类别时清除不匹配的型号。
- 仍使用内部产品 ID 建立关联。
- 同 SKU、型号重复的产品不得自动合并。

### 6.2 查询 BOM 精简筛选项

「查询 BOM」只保留：

- 产品类别：下拉
- 产品型号：下拉
- 主类别：下拉
- 项目明细：下拉
- 开始日期：日期选择
- 结束日期：日期选择
- 图号：文字搜索

原先已确定的查询条件中，这次补充「产品类别」，放在产品型号前。

要求：

- 产品类别与型号联动。
- 主类别与项目明细联动。
- 图号支持完整或部分搜索。
- 多个条件可组合查询。
- 日期使用系统现有 BOM 业务日期口径。
- 保留查询及重置功能。
- 删除其他非必要筛选项。

### 6.3 BOM 编辑页面重新布局

取消目前「本次编辑 / 修改前数据」左右逐行强制对齐的布局。

改为：

**左侧或主体：本次编辑**

- 采用紧凑表单。
- 短字段可两列排列。
- 图号、长文字等按实际宽度合理展示。
- 图片及位置示意图使用独立附件卡片。
- 避免每个字段独占大面积空白。

**右侧：修改前数据**

- 改成按需打开的只读抽屉。
- 默认不占据编辑表单宽度。
- 短字段采用紧凑网格。
- 长字段自然换行。
- 原图片使用缩略图。
- 不要求与编辑区逐行等高。

修改前数据必须表示本次加载时的原值，不得错误解释为上一条 BOM 记录。

左侧编辑过程不得实时修改右侧原值。

### 6.4 BOM 附件来源逻辑优化

取消含义不清楚的「沿用上一 BOM」复选框。

每张附件独立选择：

- 使用上一版图片
- 更换图片

要求：

1. 两种选择互斥。
2. 选择新图片后，自动取消沿用状态。
3. 选择沿用时，必须引用上一版对应项目的真实附件。
4. 首次 BOM 或上一版没有可用附件时，不能选择沿用。
5. 图片和位置示意图独立决定是否沿用。
6. 修复当前选择新图片但沿用复选框仍勾选，导致保存失败的问题。
7. 保持原历史附件关系不变。
8. 检查 BOM 新建、复制、编辑和历史数据关联是否存在同类问题。

### 6.5 BOM 详情字段资料与附件资料

目前两列表格的左侧字段列可以被拉得很宽，产生大面积空白。

要求：

- 详情信息不再使用自由列宽表格。
- 左侧字段名称采用约 20%–25% 的宽度，并设置合理最大宽度。
- 右侧内容自动填充。
- 移除这些详情表中的列拖动图标、列宽调节线和恢复布局按钮。
- 图片附件不被过宽的字段列挤压。
- 全系统检查类似双列详情信息布局。

### 6.6 BOM 历史对比顺序

统一调整为：

**左侧：所选记录**

**右侧：上一条记录**

适用于：

- 字段差异
- 附件对比
- 批次详情等相关对比区域

要求：

- 表头、日期、字段、图片全部同步调整。
- 不改变实际记录时间和历史数据。
- 首次记录没有上一条记录时，只显示所选记录。

### 6.7 BOM 附件差异误判

当前出现图片画面相同，但仍被认定为变化项的问题。

要求：

- 不只根据附件 ID、文件名或路径判断图片变化。
- 文件二进制完全相同时，应通过内容哈希准确识别。
- 对文件内容不同但视觉相同的情况，研究可靠的图片内容比较方案，不能随意认定为相同。
- 不应仅因文件名或批次不同而将完全相同的图片标记为变化。
- 「仅变化项」的数量与实际显示内容一致。
- 差异计算不影响历史图片文件及其关联。

### 6.8 BOM 历史对比图片展示

取消：

- 图片文件名的常驻展示
- 打开位置
- 查看完整路径

保留：

- 图片类型名称
- 图片缩略图
- 点击缩略图放大

上一条记录与所选记录的图片尺寸统一、对齐清晰。

图片无法读取时保留必要错误提示。

### 6.9 BOM 历史详情精简

移除顶部冗余内容：

- BOM 变更摘要区
- 新增 0 项、删除 0 项等汇总统计行
- 重复解释对照关系的说明小字

保留：

- BOM 记录基本信息
- 项目列表
- 字段差异
- 批次详情
- 附件对比

不得删除用于识别历史记录差异的底层逻辑。

### 6.10 旧 BOM 附件归档

检查「旧 BOM 附件归档」是否仍然有实际使用价值。

如果已经不需要作为日常操作，则：

- 从普通业务页面移除入口。
- 保留仍用于迁移、恢复和历史关联的底层代码。
- 核实不存在迁移依赖后，再删除真正废弃的实现。
- 不破坏已有图片和历史附件。

### 6.11 明确不修改的功能

此前提出过「同一图号不能重复记录 BOM」的问题，已经确认原逻辑正常。

**撤回该项，不修改原有图号引用及重复使用规则。**

## 八、图号库强制取消占号并删除

### 8.1 当前问题

即使已经删除相关历史 BOM，图号详情仍然显示历史 BOM 引用数量，并且不允许取消占号。

重点检查：

- 已删除 BOM 是否仍保留历史快照。
- 历史引用数量是否正确。
- 是否存在残余关联。
- 删除后统计是否及时刷新。

### 8.2 增加独立强制删除操作

在现有功能之外，增加：

**强制取消占号并删除图号**

普通删除保留原有安全校验。

强制删除允许用户在查看影响并明确确认后，主动解除相关业务关联并释放图号。

具体要求：

1. 明确显示实际受影响的 PDF、BOM、外发和其他引用数量。
2. 告知可能失去的历史追溯关系。
3. 用户明确确认后可以执行，不增加不必要的重复确认流程。
4. 释放相应完整图号的当前占用。
5. 删除对应当前图号管理记录。
6. 不删除磁盘 PDF、图片或原始文件夹。
7. 不直接改写已生成的外发历史快照。
8. 对必须保留的历史事实保存必要的脱钩快照或原始标识，防止产生错误关联。
9. 不留下无效外键或指向已删除记录的悬空关联。
10. 后续该图号重新分配时，旧历史记录不能自动挂到新图号上。
11. 操作完成后刷新图号库及相关统计。

如底层现有结构无法安全实现强制释放，应先说明需要调整的关联策略并补足测试，再开放该操作。

### 8.3 保留现有状态名称

图号库状态仍然只有：

- 使用中
- 已停用

不得擅自新增「历史版本」状态。

## 十、外发资料

### 10.1 外发范围选择

原字段：

`品牌 → 产品 → 资料批次`

修改为：

`品牌 → 产品类别 → 产品型号 → 资料批次`

要求：

- 「产品」正式改名为「产品型号」。
- 品牌、类别、型号联动筛选。

## 十一、邮件配置

### 11.1 邮件模板保存问题

当前模板已经填写：

- 模板编码
- 模板名称
- 资料类型
- 主题模板
- 正文模板

但保存时显示「邮件模板数据不完整」。

要求：

3. 不允许只显示模糊的「数据不完整」。

6. 模板保存不应要求正文必须含有签名。

### 11.2 邮件模板分类管理

建议邮件模板支持：

- 模板编码
- 模板名称
- 资料类型
- 适用厂家
- 邮件场景
- 主题模板
- 正文模板

邮件场景可以覆盖：

- 首批资料
- 铭牌待更新
- 补充铭牌
- 正式铭牌
- 完整资料交付
- 更新资料

应参考已有《包材资料更新-沟通模版.xlsx》的业务分类，不凭空替换用户现有邮件内容。

相同厂家的多个业务场景应可以分别维护模板。

### 11.3 邮件变量引用

提供可选择、可插入的变量功能。

至少考虑：

- 品牌
- 产品型号
- 产品类别
- 日期
- 资料批次
- 压缩包名称
- 压缩包数量

要求：

- 使用一套统一的变量格式。
- 插入时不需要用户记忆占位符。
- 保存时校验变量格式。
- 明确区分未知变量与暂时无业务数据。
- 没有外发数据时可以保存模板。
- 实际生成邮件时再替换变量。
- 提供替换结果预览。
- 不允许将未替换的关键变量静默发送。

### 11.4 邮件签名单独管理

**邮件正文不填写签名。**

要求：

- 邮件模板只负责主题及正文。
- 邮件签名由现有「邮件签名」模块独立管理。
- 生成邮件时将选定签名追加在正文末尾。
- 不重复追加。
- 邮件预览中能看到完整正文和签名。
- 正文不需要填写 `{发件人签名}`。
- 模板保存不能因缺少签名而失败。

### 11.5 联系人管理

联系人继续独立维护收件人和抄送人。

模板负责内容，联系人负责发送对象，签名负责落款。

三者在生成邮件时组合，不要求每份模板重复填写邮箱和签名。

### 11.6 邮件配置 UI

要求：

- 简化模板表单和字段排版。
- 不需要重复的说明小字。
- 编辑区不要占据无意义的大面积空白。
- 模板列表、编辑状态与保存提示清晰。
- 错误字段应直接定位并显示原因。
- 不额外创建另一套独立的邮件配置页面。
