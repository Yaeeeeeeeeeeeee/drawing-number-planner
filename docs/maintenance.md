# 维护与发布

1. 在现有源码分支增量修改，更新相关业务/安全测试和项目 Skill；不得把演示夹具装入正式包。
2. 修改 `package.json` 与中文 Inno 安装脚本的版本，同时更新固定运行库复用检查中明确许可的应用版本及原生验收断言。运行库或依赖升级另行核验，不用放宽保护来打包。
3. 运行类型检查、完整测试及前端/Main 构建。推送后 `comprehensive-windows-delivery.yml` 构建 Windows 安装器并实际验证安装、桌面路径、旧库升级、备份/WAL/回滚、二维码原生选择和业务交互。只有成功运行才能用于发布。
4. 发布流程固定已成功运行的完整源码 SHA、运行 ID 和工件摘要；下载同次安装器与验证报告，核验所属源码后，由已授权开发身份创建指向该源码的不可变 Tag。发布器先核对既有 Tag 与源码一致，再以 --verify-tag 创建 Release，不代建或移动 Tag；生成 EXE 校验文件并上传。版本 Tag 不指向未验证的不同应用提交。
5. Release 附安装器、版本/升级说明、SHA256 及运行报告；安装包提供长期 GitHub 下载，不以临时 Actions URL 作为正式入口。更新 README 当前版本链接。
6. 保留至少一个源码与安装器齐全的已验证回退基准及迁移恢复说明。当前保留 v1.0.0（Schema20）及 `rollback-v4-20261023`、原 P4/V3 里程碑及构建所引用的运行库工件。不强制改写 Git 历史，不无依据删 Tag/Release；影响其他使用者的远端删除须先列清单并确认。

目录：`src` 业务源码，`tests` 自动化回归，`scripts` 构建/原生验收，`.agents/skills` 当前规则，`docs` 当前说明与必要历史证据。`work`、依赖、构建缓存和临时交付目录不入库。仍被测试、构建、迁移或 Skill 引用的旧代码/文档继续保留，不按文件名批量清理。
