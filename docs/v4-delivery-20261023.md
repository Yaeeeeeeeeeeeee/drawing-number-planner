# V4 数据关联与表格交互交付记录

需求原文：[V4.0](v4-data-interaction-requirements-20261023.md)。本轮增量修改现有程序，开发环境没有用户正式业务库。以下数量均为隔离回归夹具，不能当成用户本地 ZC100 的实际修复数量。

## 根因及修正

1. 产品表原来对 SKU 及同品牌型号设置唯一性约束；产品服务又把默认外观变更当成已引用身份变更而拒绝。Schema19 仅移除字符串唯一性，产品内部 ID 不变；默认外观可修改，已存在图号、旧外观表及业务引用保留。已有明确归并的历史产品 ID 通过规范身份投影显示，逐文件确认和审计仍保留原始 ID；不能把已归并别名当作新的归纳目标。
2. 图号诊断优先采用旧扫描产品 ID，导致同 SKU/型号的其他真实产品候选被忽略。现在枚举全部候选；存在歧义时不随机选择。明确确认的产品 ID 优先，外观码与颜色码仍按字典分别校验。
3. PDF 缺少持久的实例级产品确认，目录投影与图号正式归属无法表达人工纠正。新增逐文件确认及审计；列表、目录与统计共用同一规则，扫描保持确认。明确 PDF 归属可成为图号库的可信依据；已有图号绑定冲突时保持原绑定，显示原因，不改占号或历史快照。
4. 人工指定产品后，同一文件原来的批次推导证据不能再覆盖该实例的明确确认；其他文件、BOM、外发的独立证据继续参与冲突检查。独立审查先复现该问题，再以回归修正。

## 已实现交互

- PDF 单条或多选人工归纳：区分重复产品的内部 ID、真实批次 ID/路径，预览原归属及目标，填写原因后确认；批量一次保存。冲突明确披露，仅更改这些 PDF，不静默改图号。已保存后的目录刷新失败会在页面反馈，列表仍独立刷新，不重复保存。
- PDF 去掉右侧详情和所有打开该详情的入口；文件行只保留查看路径、打开位置，异常原因保留在相应状态内。清除索引/暂不纳入/恢复继续在顶部；批次改名仅导航铅笔。根目录、数量、详细信息、恢复布局、扫描合为一行，窄屏合理换行。
- 图号目录第三层改为真实编码字典主类别，按产品 ID 与主类别共同筛选；空主类别不显示。不能映射主类别的历史图号仍在产品全部图号中。标题、数量与归类/诊断紧凑排列。
- 图号库改为分批加载和虚拟滚动，取消分页条；产品、二维码、PDF 保留既有虚拟滚动。加载更多不清空选择，不重复添加 ID，旧响应不能覆盖新查询。加载中拒绝的末尾通知可重试。
- 图号详情保留原四板块和历史释放检查；未增加外观管理或审批。外发仍按实际选定批次、BOM 辅助、转曲 PDF 优先及历史快照规则处理。

## 共享表格组件

`DataTable` 与 `LayoutTable` 共用列布局引擎，覆盖产品、二维码主表/用途子表、PDF、图号、BOM 查询/对比、外发清单/ZIP/联系人、编码字典、迁移检查及产品退出清单。图号规划页使用卡片/表单，未虚构不存在的表格。

- 表头边界拖动实时改宽，设最小值；靠近推荐宽度 6px 吸附，双击适应实际内容。
- 拖动表头或 Alt+左右键重排，插入位置有指示；选择/操作列锁定边界。表头和对应单元格随列一起移动，展开行不拆分。
- 按每张表稳定 ID 在本机保存宽度与顺序，重启恢复。现有恢复默认入口同时重置两者；表头右键可单独重置该表。
- 初始宽屏充分利用容器；开始改宽时先记录真实显示宽度，随后固定精确宽度，避免 4K 下存储值与实际列边界不一致。
- 文件名/批次在本列内至多两行，超出省略并可悬停；SKU/型号/图号按需单行省略。多个独立二维码文件分别限制文件名，所有文件按钮均保留。

## 迁移与历史保护

从旧 Schema 自动备份后升级到19。产品表重建保留所有原列值、内部 ID、自定义索引/触发器、外键和自增高水位；事务内检查所有旧业务表及 FK，失败回滚，最终恢复外键约束。

新增 `pdf_product_assignments` 和 `pdf_product_assignment_audit`，不清空原表，不删除旧外观结构。人工归纳预览有指纹，写入前备份并在事务中重查，审计保留原归属及目标。原文件路径、文件名和内容不变；同名不同目录的批次不合并。启动不自动归并 ZC100，不删除测试产品，不释放任何历史号码。

详细实现与专项证据：[数据库](v4-reports/schema.md)、[匹配](v4-reports/matching.md)、[PDF后端](v4-reports/pdf-backend.md)、[PDF界面](v4-reports/files-ui.md)、[表格组件](v4-reports/tables.md)、[页面接入](v4-reports/page-tables.md)。部分早期报告为任务完成时记录，最终结论以下方最终验证为准。

## 隔离关联统计

| 验证数据 | 修正前 | 修正后 |
|---|---|---|
| ZC100 外观01图号 | 无确认绑定 | 同一目标产品下1条，默认外观改为02后仍1条 |
| ZC100 外观02图号 | 无确认绑定 | 同一目标产品下1条，默认外观改为02后仍1条 |
| 同SKU/型号两个产品、旧扫描ID | 错误地只给1个候选 | 2个候选，保持歧义，不自动写入 |

重复产品且没有可靠产品 ID、未知外观/颜色字典、已有独立业务冲突的记录会保留明确原因。用户真实库的逐产品/逐外观数量没有在云端测量；本轮不虚报为全部已归类。

## 本机安装与核对

1. 完全退出旧版，备份当前完整数据目录，包括 planner.db、相关 WAL/SHM、设置、附件及外发记录。安装目录与业务目录分开。
2. 解压最终中文安装 ZIP，运行 EXE 自选程序路径；启动继续选择原数据库。不要新建空库替代升级。
3. 首次升级前程序自动创建备份；发生升级失败时保留原库并显示错误。需要回退时关闭程序，从升级前完整备份恢复到独立目录，配合对应旧程序打开，不让旧程序直接读取已升级到19的库。
4. 在产品档案创建重复 SKU/型号，核对它们内部 ID 不同；修改默认外观后，旧图号仍可查看。
5. 在 PDF 中选择待归纳文件，点击人工归纳，核对具体产品 ID、批次 ID/路径和冲突再确认；重扫后检查归属保持。冲突图号通过已有改变产品所属功能人工纠正，未确认前不自动覆盖。
6. 图号库展开型号查看主类别，点击过滤；测试传统分页已移除，滚动加载、筛选和选择正常。
7. 拖动列边界、双击适应、拖动表头或 Alt+左右键，关闭重启检查保存；恢复默认布局同时恢复顺序和宽度。
8. 核对原历史 BOM、二维码、外发和占号记录。真实产品归并及数据纠正由用户本地明确执行，本轮不在启动时执行归并。
