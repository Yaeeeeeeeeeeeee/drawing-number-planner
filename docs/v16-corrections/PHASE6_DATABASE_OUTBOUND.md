# 阶段6：外发、草稿与数据库切换

依据OUT-001、OUT-50MB-001、OUT-DRAFT-001、DB-SWITCH-001；记录日期2026-11-17。本记录随整合测试继续更新。

## 数据库切换

修改 `src/main` 现有数据库选择/重新选择/配置及启动逻辑，复用已有备份与兼容检查，不新增备份中心或业务Schema。

一次文件选择后先隔离检查，展示实际规范化路径与Schema摘要；确认前不停止当前服务。候选服务必须启动且实际读取产品、BOM和PDF。将准确原配置写入原子待完成日志，提交新配置后，userData切换及页面加载仍处于同一回退边界。任一环节失败恢复原配置字节、旧目录和旧服务；启动时发现未完成激活，先恢复旧配置再使用。

实际测试：主进程4文件54项串行通过；服务8项通过，含真实隔离SQLite备份/外键检查、候选HTTP核心读、模拟提交配置后页面加载失败、原服务重新启动可读及中断恢复。首轮并发默认5秒出现5次超时，改为串行30秒后54项全过；未隐瞒首轮失败。未来Schema拒绝、旧Schema备份迁移原保护保留。

## 外发与草稿

修改现有 `outbound-package-service.ts`、types、路由/客户端、`PackageBuilder`、`PackageResult`、`EmailComposer` 和 `OutboundPage`。

- 超过50,000,000字节（十进制50MB）的原PDF排除ZIP，保留独立传输事实与原因；已选/未选文件事实进入既有V2快照JSON。压缩目标49,000,000字节，最终ZIP硬上限50,000,000字节，保留整文件分包、独占发布和源摘要校验。
- 全部所选文件都超限时列出完整独立传输清单，明确没有ZIP；不伪造包ID、空ZIP、邮件包或历史记录。现有历史表要求有效ZIP路径，本轮不为此扩展业务Schema；此类结果清单当前只保留在当前会话。
- 显式“保存草稿”和用户主动恢复，复用 `outbound_email_drafts`。准确上下文保存在既有recipients JSON的私有对象中；旧的非该格式行保持原样且不误恢复。保存/恢复均与真实包、产品ID、批次ID、文件ID及创建时间校验，不自动发送或重新生成ZIP。
- 失败保留输入，异步保存不能清除新上下文或后续编辑的dirty。未保存保护继续整合回归，不以专项通过掩盖导航回归。

专项结果：5文件117项通过；超限压缩率高的真实PDF前缀源文件SHA不变且不在ZIP；混合清单/全部独立/精确边界/ZIP硬限通过。SQLite关闭重开及迟到保存保护通过，实际Chromium生成ZIP、保存、重载、恢复1项和原有外发浏览器1项通过。一次旧测试深比较69MB Buffer导致Node堆不足，改为SHA256后完整专项通过；不是生产文件处理失败。

全套回归发现的新dirty保护影响配置导航和未修改草稿采用新包，现已修复。补充手改收件人保护与重新生成推进修订的失败回归；最终完整240文件2075项通过，专项117项不与总量叠加。Windows应用关闭重启仍须实际验证。

## 未验证与数据影响

仅操作隔离测试资料，未访问用户正式数据库，也未切换用户配置。Schema26来自已确认项目制作方式的兼容迁移，数据库切换本身没有另增Schema。原生Windows选择器、应用进程重启/升级、实际故障恢复待Windows验证；Linux服务与浏览器证据不得当作Windows结论。
