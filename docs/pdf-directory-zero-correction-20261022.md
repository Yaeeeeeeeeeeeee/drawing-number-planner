# PDF 产品导航全为0：根因与修正

用户反馈：产品目录数量全部为0，134个资料批次集中出现在“未关联产品批次”。134是导航中未归入产品分支的批次数，不是PDF数量；同名首批大货不等于重复记录。

代码根因：V3把PDF列表、统计的产品连接改成了图号有效归属SQL。历史图号没有人工绑定/BOM等可靠确认时，其产品为空；前端又只凭这一计数决定批次所属产品，因此即使PDF处于精确匹配现有产品的SKU-型号目录中，也被全部放入未关联分支。这混淆了单个PDF的目录使用上下文与全局图号正式归属。

修正只改变只读查询：

- 按PDF相对路径的产品目录，查找现有产品档案中完整 `SKU-型号` 组合的唯一匹配，规范化原有canonical产品ID；兼容斜杠方向及Windows大小写。
- 确有唯一目录匹配时，PDF在该产品下浏览和统计；无目录匹配时继续使用已有可信图号关联。存在多个目录候选时不猜测。
- 产品计数、类别计数、批次计数、待关联筛选与右侧列表使用相同查询条件；文件是否匹配图号保持原状态。
- 相同完整图号在不同产品目录中使用时，PDF文件实例分别归类，图号主记录仍唯一，图号库不会因此自动确认或改写归属。
- 不迁移Schema，不写产品、文件、批次、图号绑定或审计，不改占号，不修改原PDF。
