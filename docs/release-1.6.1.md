# v1.6.1 本地服务启动修复

仅修复本地服务启动、重启及其诊断，不新增 Schema 迁移，不改变数据库选择、占号、BOM、PDF 或 AIT 业务规则。

- 原来从派生进程到完成数据库校验、备份和业务初始化统一只等15秒。现在分阶段等待：依赖/打开/监听30秒，数据库完整性/兼容/备份每阶段最多5分钟，业务初始化/外发临时检查60秒，健康验证15秒；一次启动总上限10分钟。重复同阶段消息不能无限续期，异常仍会停止并报错。
- 就绪前实际请求本机健康接口。停止期间的新启动等待旧进程退出，同期请求共享新进程；超时或停止后的迟到就绪消息不再把失败服务显示为运行中。
- 启动日志在**实际使用的数据目录**的 `logs/service-startup.jsonl`，记录每次启动标识、阶段、耗时、数据库路径、PID、退出码和信号，不记录会话令牌。
- 启动超时提示包含具体阶段和数据库路径；安装后选择数据库的试启动失败时，也明确展示本次验证的文件。验证成功前不覆盖已保存的选择，不自动选择其他数据库。
- 全部现有完整性检查、逐级迁移保护及备份继续保留。没有修改用户电脑上的任何数据库，也没有删除、移动、重命名或覆盖用户原始文件。

## 本机升级与收集结果

1. 退出旧程序，保留两份现有数据目录和原备份。不要删除或只搬运 `planner.db-wal`、`planner.db-shm`。
2. 安装本版本；如安装后询问数据库，选择“使用旧数据库”，明确选择自己确认需要继续使用的那份 `planner.db`。`data`/`data-随机字符` 只代表创建位置，不能单凭名称或文件大小判断业务数据的新旧和完整程度。
3. 大数据库校验和备份需要等待。若失败，将完整弹窗及**弹窗所指数据目录**下启动日志末尾发回，保留原配置，不创建替代空库。
4. 回退时先关闭本版，保留完整现用目录及独立备份，再使用旧安装包。Schema仍为25；回退不会修复旧版15秒启动限制。不要覆盖唯一现用库。

## 验证边界

用户提供的文件信息显示原指定数据库约535MB，已保存配置指向另一份约980MB数据库。两份数据库均未上传到开发环境，无法判断内容差异或确认现场唯一根因。

开发机实际使用约1GB独立Schema25数据库完成服务进程启动和重启，首次约7.3秒、重启约3.9秒，行数及外键保留；该机器上**没有复现真实耗时超过15秒**。超过15秒初始化、阶段/总时限、重复进度、迟到消息和停止竞态另由自动化回归覆盖。最终Windows运行结果和安装包SHA256以正式Release附件为准，不能将开发机测试视为用户原库恢复验收。
