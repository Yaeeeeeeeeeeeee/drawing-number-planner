# 图号规划器｜外发资料模块完整改造需求 V2.0

**文档用途：** 直接交由 Codex 开发实施
**改造范围：** 外发资料页面、批次差异对比、PDF 关联、BOM 辅助核对、ZIP 打包、邮件草稿、外发历史、数据安全及相关测试
**实施方式：** 在现有项目上改造，保留既有功能与历史数据
**优先级：** P0 业务逻辑与数据正确性；P1 页面布局与使用体验

---

# 一、改造目标

目前外发资料模块存在以下问题：

1. 外发文件的选择过度依赖 BOM，而实际业务中 BOM 不一定在外发前完成维护。
2. 完整资料和本次变更资料的筛选逻辑需要与实际文件夹管理方式一致。
3. 当前页面采用左右分栏，左侧文件清单过窄，右侧大量留白。
4. 文件清单存在过多状态、说明和重复信息，部分文字被挤压成竖排。
5. 历史文件、当前批次文件及实际沿用文件之间的关系不够清晰。
6. ZIP 分包生成后缺少准确的分包文件数量及内容明细。
7. 需要明确产品外观版本与外发资料的关联。
8. 需要保证外发历史在后续 BOM、批次和 PDF 索引变化后仍然可追溯。

本次改造的目标是建立一条稳定、清晰的业务流程：

**选择产品及外观 → 选择资料批次 → 选择外发范围 → 扫描并对比文件 → 人工确认 → 生成 ZIP → 保存外发历史 → 生成邮件草稿。**

其中，BOM 用于辅助核对，不作为生成外发资料的强制前置条件。

# 二、实际业务规则

## 2.1 公司实际包材管理方式

首批大货时，会建立一个完整包材资料文件夹。

例如：

```text
GU120S
└── 首批大货资料
    ├── 铭牌A（转曲）.pdf
    ├── 说明书A（转曲）.pdf
    ├── 内胆贴纸A（转曲）.pdf
    └── 侧面贴纸A（转曲）.pdf
```

当包材发生修改时，不会直接覆盖首批资料，而是另外建立一个新的批次文件夹。

新文件夹包含：

- 上一批次未修改的资料。
- 本次已经修改的新资料。

例如：

```text
GU120S
├── 首批大货资料
│   ├── 铭牌A（转曲）.pdf
│   ├── 说明书A（转曲）.pdf
│   ├── 内胆贴纸A（转曲）.pdf
│   └── 侧面贴纸A（转曲）.pdf
│
├── 20260610（铭牌、说明书变更）
│   ├── 铭牌B（转曲）.pdf
│   ├── 说明书B（转曲）.pdf
│   ├── 内胆贴纸A（转曲）.pdf
│   └── 侧面贴纸A（转曲）.pdf
│
└── 20260820（侧面贴纸变更）
    ├── 铭牌B（转曲）.pdf
    ├── 说明书B（转曲）.pdf
    ├── 内胆贴纸A（转曲）.pdf
    └── 侧面贴纸B（转曲）.pdf
```

以上文件名仅为说明业务关系的示例，实际识别应采用系统现有完整图号和文件命名规则。

**核心结论：每个正常完成整理的包材批次文件夹，本身就是该次完整包材资料。**

因此：

- 不需要默认从所有历史批次重新拼凑完整资料。
- 不需要先建立 BOM 才能外发。
- 需要比较新旧批次时，直接比较两套完整资料。
- 历史批次必须保留，不允许被新批次覆盖。
- 同一个图号或相同 PDF 出现在多个批次中是正常现象。

## 2.2 文件夹完整性

虽然正常业务中每个批次都是完整资料，但系统不能仅根据文件夹名称就认定文件齐全。

建议为资料批次提供业务完整性状态：

| 状态 | 含义 |
|---|---|
| 已确认完整 | 用户确认该批次是一套完整包材 |
| 待确认 | 已扫描，但未确认完整性 |
| 部分资料 | 该批次只包含部分资料 |

原有历史批次若没有记录完整性状态，默认保持「待确认」，不能自动认定全部完整。

允许用户确认或调整状态，并记录操作时间。

## 2.3 BOM 的定位

BOM 不再作为外发前置条件。

| BOM 状态 | 外发处理 |
|---|---|
| 已完整维护 | 用于辅助核对文件和图号 |
| 部分维护 | 显示已关联和未关联情况 |
| 未维护 | 正常扫描、选择、打包 |
| BOM 与批次不一致 | 提示差异，允许人工核查 |

未找到 BOM 时，显示：

`未关联 BOM`

不得直接显示为严重错误，也不得因此禁止生成 ZIP。

BOM 与外发清单不一致时，应显示具体差异，而不是简单判定文件错误。

外发历史可以用于后续补录 BOM 的参考，但不能自动认定外发过的全部文件都属于当前 BOM。

# 三、外发资料页面结构

## 3.1 整体布局

取消目前左右两栏的固定布局。

改为全宽纵向四个区域：

```text
┌──────────────────────────────────────────────────────────┐
│ 外发资料                                                  │
├──────────────────────────────────────────────────────────┤
│ 01 选择外发范围                                           │
│ 品牌       产品       外观版本                            │
│ 资料批次   资料类型   打包范围                            │
│                                        [预览外发文件]     │
├──────────────────────────────────────────────────────────┤
│ 02 外发文件清单                                           │
│ 批次信息 / 文件统计 / 异常提示                            │
│                                                          │
│ □  文件名                 图号        状态       操作     │
│ □  文件1                  ...         ...        查看     │
│ □  文件2                  ...         ...        查看     │
│                                                          │
│ 已选择 X 个文件                       [生成外发压缩包]   │
├──────────────────────────────────────────────────────────┤
│ 03 生成外发结果                                           │
│ 压缩包名称                    大小    文件数量    操作     │
│ 压缩包1                       ...     ...         打开     │
│ 压缩包2                       ...     ...         打开     │
├──────────────────────────────────────────────────────────┤
│ 04 邮件草稿                                               │
│ 收件信息 / 邮件主题 / 正文 / 复制                          │
└──────────────────────────────────────────────────────────┘
```

页面按现有项目的设计系统实现，不另建一套独立视觉风格。

整体要求：

- 白色、浅灰为主。
- 少量状态颜色。
- 紧凑但不拥挤。
- 充分利用 4K 横向空间。
- 表格单元格统一约 12px 水平内边距。
- 表格行高约 44–52px。
- 避免多个嵌套滚动条。
- 优先使用页面整体滚动。
- 长文件名省略显示，悬停可查看完整名称。
- 不使用大面积空白占位。
- 数据刷新不得造成页面明显闪烁。

## 3.2 区域一：选择外发范围

采用三列网格。

字段如下：

| 字段 | 要求 |
|---|---|
| 品牌 | 从产品档案读取 |
| 产品 | 显示 SKU、型号，支持搜索 |
| 外观版本 | 默认当前使用版本，允许选择历史外观 |
| 资料批次 | 只显示符合当前产品和外观范围的批次 |
| 资料类型 | 初次资料 / 更新资料 |
| 打包范围 | 本次变更资料 / 当前完整包材资料 |

选择关系：

1. 选择品牌后过滤产品。
2. 选择产品后加载外观版本。
3. 选择外观后加载关联批次。
4. 选择批次后确定当前资料范围。
5. 修改任何影响文件范围的条件，都必须使旧预览失效。
6. 不允许沿用上一个产品或外观的旧勾选状态直接打包。

### 资料类型与打包范围

两者必须独立。

**资料类型：**

- 初次资料
- 更新资料

用于表示外发业务性质，并影响压缩包命名和邮件草稿。

**打包范围：**

- 本次变更资料
- 当前完整包材资料

用于确定实际候选文件。

允许更新资料选择完整打包范围，例如工厂要求重新发送整套最新资料。

# 四、完整包材资料逻辑

选择「当前完整包材资料」时：

1. 获取当前产品及外观版本。
2. 获取用户选择的资料批次。
3. 从 PDF 文件中心读取该批次文件索引。
4. 筛选转曲后 PDF。
5. 排除已明确标记「暂不纳入」的文件。
6. 检查文件实际存在状态。
7. 检查文件图号、产品、外观关联。
8. 识别重复、冲突和异常项目。
9. 显示候选文件清单。
10. 用户确认后生成外发包。

### 4.1 不自动跨批次拼装

完整外发默认仅使用选定批次的文件。

例如选择第三批资料，应优先使用第三批文件夹中的：

- 铭牌 B
- 说明书 B
- 内胆贴纸 A
- 侧面贴纸 B

不需要重新去第一、第二批查找这些文件。

### 4.2 文件缺失

如果选定批次中的某个索引文件已经不存在：

- 显示「文件缺失」。
- 默认不勾选。
- 不得自动使用旧批次同图号文件替代。
- 允许用户重新关联正确文件。
- 允许用户查看历史来源进行人工核查。

如确实需要补充旧批次文件，应通过明确的「添加额外资料」操作完成，并在清单及外发历史中记录其实际来源。

### 4.3 同项目多个版本

如果同一批次出现同一个包材项目的多个有效版本：

- 不得默认全部勾选。
- 不得仅根据文件修改日期选择。
- 显示「版本冲突」。
- 用户必须明确确认采用哪个文件。

确认时不修改或删除原始文件。

# 五、本次变更资料逻辑

## 5.1 对比方式

本次变更资料采用：

**当前选定批次 vs 上一个有效完整批次**

例如：

| 项目 | 上一批 | 当前批 | 对比结果 |
|---|---|---|---|
| 铭牌 | A | B | 已修改 |
| 说明书 | A | B | 已修改 |
| 内胆贴纸 | A | A | 未变化 |
| 侧面贴纸 | A | A | 未变化 |

默认勾选：

- 新增文件
- 已修改文件

默认不勾选：

- 未变化文件

删除或不再使用的项目不应作为普通 PDF 自动打包，但必须在差异结果中明确提示。

## 5.2 上一批次的确定

系统应根据已建立的业务批次顺序查找上一批次。

优先使用明确的批次关联或顺序。

如果没有明确顺序，可参考批次业务日期，但不能仅根据文件修改时间确定。

无法确定时允许用户手动选择对比基准。

对比基准必须与当前产品及外观版本一致；跨外观比较需要明确提示并由用户确认，不允许静默混用。

## 5.3 文件对比依据

不能只看文件名。

需要综合使用：

1. 完整图号。
2. 图号对应的主类别和项目明细。
3. 外观及颜色信息。
4. 文件内容哈希。
5. 文件关联的批次。
6. 已有的明确替换关系。

建议判断规则：

| 情况 | 结果 |
|---|---|
| 同项目、同图号、相同内容 | 未变化 |
| 同项目、新图号、新内容 | 已修改 |
| 新批次出现此前没有的项目 | 新增 |
| 上一批有、当前批没有 | 已移除 / 待确认 |
| 同图号但内容不同 | 异常冲突 |
| 无法确定是否为同一项目 | 待人工确认 |

不同图号但内容相同，不应简单地归类为未变化，应检查图号版本和业务关系。

### 5.4 差异确认

对比结果必须允许人工调整。

用户可以：

- 勾选或取消某个变更文件。
- 查看上一批和当前批的文件信息。
- 查看完整图号。
- 查看实际路径。
- 查看文件内容是否一致。
- 对无法识别的项目进行人工确认。
- 手动添加额外文件。

系统自动识别的是「候选差异」，不能代替用户最终确认。

### 5.5 首批资料

如果当前批次没有上一批：

- 提示「没有可用的上一批次」。
- 可以将本批次全部有效转曲后文件作为初次候选。
- 不允许假装已完成历史差异对比。
- 用户可切换为完整资料外发。

# 六、PDF 文件识别及索引规则

## 6.1 复用现有 PDF 文件中心

外发资料不建立独立的第二套 PDF 文件数据库。

继续使用现有 PDF 文件中心的扫描、索引和关联能力。

需要读取：

- 文件 ID
- 完整文件名
- 实际路径
- 文件大小
- 文件内容哈希
- 文件修改时间
- 文件存在状态
- 转曲状态
- 完整图号
- 所属产品
- 所属外观版本
- 所属资料批次
- 暂不纳入状态

如果缺少内容哈希，应在需要比较时计算并缓存，不得因文件修改时间相同就认定内容相同。

## 6.2 转曲前后

沿用现有规则：

- 文件名包含完整 `（转曲）`：转曲后。
- 不包含 `（转曲）`：转曲前。
- 不通过 PDF 内容猜测是否转曲。
- 转曲前后属于同一个图号。
- 不因转曲生成新的正式图号。

默认只打包转曲后文件。

如果某个项目只有转曲前文件：

显示「缺少转曲后文件」。

允许继续打包其他有效文件，但不得将转曲前文件静默当作转曲后文件。

## 6.3 暂不纳入

被标记为「暂不纳入」的文件：

- 默认不进入外发候选。
- 不参与自动差异替换决策。
- 不得自动进入 ZIP。
- 不删除磁盘原始 PDF。
- 不破坏历史外发记录。
- 不释放图号占用。
- 重新扫描时保持原有排除状态。

如果用户确实需要恢复使用，应先通过现有文件中心解除排除状态，再参与正常外发。

## 6.4 文件重复

必须区分：

**同一文件出现在不同批次：** 正常，不属于图号重复占用。

**同一批次中同图号、同内容：** 可提示重复文件，避免重复打包。

**同一批次中同图号、不同内容：** 异常，要求人工确认。

**不同图号但文件内容相同：** 不自动合并图号，保留业务身份并提示核查。

## 6.5 文件选择优先级

完整资料模式：

1. 用户选择的资料批次。
2. 该批次已确认关联的转曲后 PDF。
3. 文件存在且未被排除。
4. 无冲突的文件默认可勾选。
5. 有异常的文件需要人工确认。

变更资料模式：

1. 当前批次与上一批次比较。
2. 自动推荐新增、修改文件。
3. 未变化文件默认不选。
4. 异常项目需人工确认。
5. 最终以用户确认清单为准。

不得默认使用所有历史扫描结果拼凑当前文件。

# 七、BOM 辅助核对

## 7.1 基本原则

BOM 不作为外发前置条件。

系统必须支持以下三种情况：

**情况 A：已维护 BOM**

可检查：

- BOM 项目是否存在对应转曲后文件。
- 图号是否一致。
- 是否存在遗漏。
- 是否存在版本冲突。
- 是否包含 BOM 以外的资料。

**情况 B：部分维护 BOM**

显示：

- 已关联 BOM
- 未关联 BOM
- BOM 项目缺失

不阻止用户正常外发。

**情况 C：未维护 BOM**

正常使用批次文件生成外发资料。

提示：

`该产品尚未维护 BOM，当前根据资料批次整理外发文件。`

不显示严重错误，不阻止打包。

## 7.2 BOM 不得反向修改外发历史

外发历史生成后：

- 新建 BOM 不得修改旧外发清单。
- 修改 BOM 不得替换旧外发图号。
- 删除当前 BOM 关系不得删除历史外发引用。
- 历史 BOM 修正不得覆盖已生成的外发快照。

## 7.3 外观版本关联

同一个 SKU 可能存在多个外观版本。

外发资料必须明确属于哪个外观版本。

例如：

```text
ZC100
├── 原外观
│   ├── 首批资料
│   └── 后续更新批次
└── WB55 外观
    ├── 首批资料
    └── 后续更新批次
```

选择 WB55 外观时，不得自动混入原外观的旧文件。

如果某个旧文件确实被新外观沿用，需要有明确的版本使用关联，或者由用户人工确认作为额外资料。

不得修改原图号的历史归属来实现沿用。

# 八、外发文件清单 UI

## 8.1 全宽表格

取消原来狭窄的左侧文件清单。

采用全宽表格，建议字段：

| 字段 | 对齐 | 建议宽度 |
|---|---|---|
| 选择 | 居中 | 6% |
| 文件名 | 左对齐 | 35% |
| 完整图号 | 居中 | 20% |
| 来源 | 居中 | 13% |
| 资料状态 | 居中 | 13% |
| 操作 | 居中 | 13% |

如现有布局空间不足，可适度调整宽度，但文件名必须优先获得空间。

## 8.2 文件名显示

- 显示完整可识别的文件名。
- 长文件名单行省略。
- 悬停显示完整文件名。
- 点击可进入文件详情。
- 不因文件名过长而拉高表格行高。
- 保留真实文件名，不因显示省略而修改磁盘文件。

## 8.3 来源字段

来源只表达文件来自哪里。

例如：

- 当前批次
- 额外资料（旧批次）
- 人工关联

不应把「历史沿用」同时放在来源和资料状态中重复表达。

## 8.4 资料状态

建议统一使用：

- 正常
- 未变化
- 已修改
- 新增
- 已确认沿用
- 待确认
- 文件缺失
- 版本冲突
- 缺少转曲后文件

根据当前打包范围显示适用状态，不需要把所有状态同时塞入表格。

## 8.5 移除长说明列

原页面的「说明」列容易出现大段文字竖排。

要求：

- 移除主表格中的长说明列。
- 通过简短状态提示表达主要问题。
- 详细原因放在文件详情抽屉。
- 异常信息也可通过表格上方的汇总区域显示。

例如：

`共 18 个文件｜已选择 14 个｜缺失 1 个｜待确认 2 个｜冲突 1 个`

点击统计项可以筛选对应文件。

## 8.6 文件详情抽屉

点击「查看」打开右侧详情抽屉。

建议宽度 520–600px。

展示：

- 完整文件名
- 完整图号
- 产品型号
- 外观版本
- 所属资料批次
- 文件实际路径
- 文件大小
- 文件内容哈希
- 转曲状态
- 文件存在状态
- BOM 关联状态
- 与上一批次的对比结果
- 异常原因
- 当前选择状态

可提供：

- 打开文件
- 打开所在文件夹
- 查看对比信息
- 重新关联文件

相关操作必须复用现有安全规则。

## 8.7 批量选择

支持：

- 全选可用文件
- 取消全选
- 只选本次变更
- 按状态筛选
- 按文件名或图号搜索

「全选可用文件」不得包含：

- 文件缺失
- 未解决的版本冲突
- 未确认的外观归属
- 暂不纳入文件
- 未确认的额外历史资料

## 8.8 分页与滚动

- 默认每页 50 条。
- 支持 10 / 25 / 50 / 100 条。
- 分页选择状态应保持。
- 不使用固定高度的小表格滚动区。
- 页面整体滚动为主。
- 筛选、勾选和分页时不应造成整个页面闪烁。

# 九、生成前校验

点击「生成外发压缩包」前，必须进行预检。

## 9.1 校验内容

1. 是否已选择产品。
2. 是否已选择外观版本。
3. 是否已选择资料批次。
4. 是否至少选择一个文件。
5. 文件实际路径是否存在。
6. 是否为转曲后 PDF。
7. 是否存在重复打包项。
8. 是否存在同图号不同内容冲突。
9. 是否存在产品或外观归属冲突。
10. 是否存在未确认的额外资料。
11. 是否存在 ZIP 目标文件名冲突。
12. 所选文件是否仍与当前预览版本一致。

## 9.2 异常分级

**必须阻止打包：**

- 已选文件不存在。
- 未解决的文件版本冲突。
- 已选文件归属错误且未经确认。
- 无法读取文件。
- 目标路径不可写。
- 预览与实际文件状态不一致且未重新确认。

**允许确认后继续：**

- BOM 尚未维护。
- BOM 关联不完整。
- 当前批次完整性未确认。
- 有未选择的缺失文件。
- 部分 BOM 项目没有对应文件。
- 额外历史文件已经人工明确确认。

未选中的异常文件不应无条件阻止整个外发包，但需要让用户知道可能存在遗漏。

## 9.3 预检结果

```text
资料批次：20260509（铭牌变更）
资料类型：更新资料
打包范围：当前完整包材资料

已选择：14 个文件
正常：14
警告：2
阻断错误：0

[返回检查] [确认生成]
```

数字必须由实际数据计算，不允许硬编码。

# 十、ZIP 打包逻辑

## 10.1 命名规则

继续沿用原始需求：

`D&D - {品牌} {型号} {产品类别}【{初次/更新}包材资料-{建立压缩包日期}】.zip`

例如：

`D&D - SAMKYO GU120S 冰箱【更新包材资料-2026年10月20日】.zip`

要求：

- `D&D -` 为固定前缀。
- 品牌、型号、产品类别从产品档案读取。
- 初次/更新由资料类型决定。
- 日期使用实际生成 ZIP 的日期。
- 不得使用扫描日期代替生成日期。
- 不得随意修改既定命名规则。

## 10.2 分包处理

当资料总大小超过现有分包限制时，继续使用分包机制。

例如：

```text
D&D - SAMKYO GU120S 冰箱【更新包材资料-2026年10月20日】-1.zip
D&D - SAMKYO GU120S 冰箱【更新包材资料-2026年10月20日】-2.zip
```

具体大小阈值应优先沿用当前项目已经实现的配置，不在本次需求中擅自设定新值。

要求：

- 按文件实际大小合理分包。
- 单个 PDF 不应被静默拆成无法单独使用的片段。
- 每个 ZIP 必须能独立正常解压。
- 每个文件只进入一个分包，除非用户明确要求重复。
- 所有分包文件总数必须与实际选中清单一致。
- 若单个文件超过单包大小限制，应明确提示并采用安全处理方案。
- 文件名相同但来源不同的文件不得在 ZIP 内静默覆盖。

## 10.3 ZIP 内容

默认使用用户确认的文件清单。

保留原始 PDF 文件名。

不得：

- 自动重新编号。
- 自动修改图号。
- 自动修改 PDF 内容。
- 自动替换为其他批次文件。
- 自动把转曲前文件转换成转曲后文件。
- 修改磁盘原始 PDF。

## 10.4 ZIP 生成验证

生成完成后验证：

- ZIP 文件存在。
- ZIP 可以正常读取。
- 压缩包内文件数正确。
- 文件名称正确。
- 无遗漏或重复。
- 每个分包的文件清单准确。
- 压缩包内文件内容与确认时的源文件一致。

如生成过程中源文件发生变化，应终止或重新确认，不能静默继续。

如生成失败，不得保存为成功外发历史。

## 10.5 生成结果区域

改为全宽结果表格：

| 字段 | 要求 |
|---|---|
| 压缩包名称 | 左对齐，完整名称可查看 |
| 大小 | 居中 |
| 文件数量 | 居中，必须为实际数量 |
| 操作 | 居中 |

每个分包支持展开，查看包含的实际文件。

例如：

```text
压缩包已生成

共 14 个文件 / 2 个分包

第1份.zip    44.39 MB    9 个文件    查看路径
第2份.zip    14.98 MB    5 个文件    查看路径
```

上面数量只是示例。

目前页面中分包文件数量显示「未提供」的问题必须修复。

提供：

- 打开输出文件夹
- 打开指定压缩包位置
- 查看分包文件清单
- 查看完整外发记录

- 操作人

- 重新扫描 PDF。
- 文件被标记暂不纳入。
- 重新关联文件。
- 当前资料发生更新。

旧历史必须继续显示当时实际使用的名称、图号和文件清单。

如果原始 ZIP 后续被移动或删除，历史记录仍应保留，并明确显示「压缩包文件不存在」，不能直接删除历史。

- 品牌
- 产品型号
- SKU
- 外观版本
- 资料批次
- 初次/更新
- 生成日期

点击历史记录可查看：

- 当时的外发条件。
- 完整文件清单。
- 实际分包情况。
- 每个文件的来源。
- ZIP 文件状态。
- 当时的警告及人工确认信息。

## 11.5 重新生成

允许基于历史记录发起重新生成，但必须创建新的操作记录。

不得覆盖原始历史。

重新生成时应重新检查原始文件是否存在、内容是否变化。

不能仅根据旧路径找到一个同名文件就认定与历史完全相同。

- PDF 文件索引
- 正式图号

- BOM

不得为同一业务概念建立互相冲突的重复数据来源。

如现有结构不足，可增加：

- 批次完整性状态
- 批次对比基准关系
- 外发文件确认状态
- 文件差异结果
- 文件内容哈希缓存
- 外发历史文件快照
- ZIP 分包明细
- 人工确认审计记录

具体表结构由 Codex 在检查现有 Schema 后决定。

不得为了实现新功能破坏旧表和旧数据。

## 13.3 历史数据迁移

要求：

1. 兼容现有数据库版本。
2. 迁移前进行备份。
3. 迁移可重复执行且不产生重复数据。
4. 不删除原有外发历史。
5. 不重置正式或历史图号占用。
6. 不清空 PDF 索引。
7. 不删除磁盘 PDF。
8. 不覆盖既有批次关联。
9. 无法确认的历史外观关联保持待确认。
10. 不得自动推断并修改历史文件的真实业务归属。

## 13.4 产品与外观关联

一个产品可存在多个外观版本。

所有外发记录必须关联具体外观版本，或明确保留尚未确认的历史归属状态。

新外观可以明确沿用旧外观文件，但不得因此改写旧图号的历史归属。

## 13.5 文件操作安全

外发模块原则上只读取源 PDF。

禁止：

- 删除源文件。
- 覆盖源文件。
- 修改 PDF 内容。
- 自动重命名源文件。
- 因打包失败修改原始目录。
- 因清除索引删除源文件。
- 因移除当前关联破坏旧外发记录。

ZIP 生成应采用临时输出及完成后确认的安全方式，避免留下被误认为成功的半成品。

# 十五、重点验收场景

Codex 必须至少覆盖以下场景。

### 场景 1：未维护 BOM 的完整外发

条件：

- 产品已有首批完整资料。
- 未维护 BOM。
- 文件夹存在转曲后 PDF。

预期：

- 可以正常预览。
- 可以勾选。
- 可以生成 ZIP。
- 显示未关联 BOM 提示，但不阻断。

### 场景 2：完整批次直接外发

条件：

- 首批包含 A、B、C、D。
- 第二批包含 A、B2、C、D。

预期：

- 选择第二批完整资料时，只从第二批读取 A、B2、C、D。
- 不需要从首批拼装。
- 不重复打包 B。

### 场景 3：自动识别本次变更

条件：

- 第一批 A、B、C、D。
- 第二批 A、B2、C、D。

预期：

- 本次变更默认只选 B2。
- 其他未变化文件默认不选。
- 用户可手动调整。

### 场景 4：同图号跨批次复用

条件：

- 同一 PDF 在两个批次均存在。
- 图号和文件内容相同。

预期：

- 判定未变化。
- 不提示重复占号。
- 不删除任何历史记录。

### 场景 5：同图号内容不同

条件：

- 两批次使用同一图号。
- PDF 内容哈希不同。

预期：

- 标记异常。
- 不静默认定为正常更新。
- 要求人工确认。

### 场景 6：文件缺失

条件：

- PDF 索引存在。
- 磁盘文件已经不存在。

预期：

- 显示文件缺失。
- 默认不选。
- 不自动拿旧批次文件替代。

### 场景 7：外观版本隔离

条件：

- ZC100 存在原外观和 WB55 外观。
- 两个外观有不同资料批次。

预期：

- 选择 WB55 只展示其关联资料。
- 不混入原外观文件。
- 明确沿用的资料可以人工加入。

### 场景 8：部分 BOM

条件：

- BOM 只维护部分项目。
- 资料批次存在更多文件。

预期：

- 正常生成候选清单。
- 提示 BOM 未关联项目。
- 不直接阻止打包。

### 场景 9：ZIP 分包

条件：

- 共选择 14 个文件。
- 实际生成 2 个 ZIP。

预期：

- 两个分包显示各自真实文件数。
- 文件数合计为 14。
- 每个 ZIP 均可独立解压。
- 不显示「文件数量未提供」。

### 场景 10：历史不可变

条件：

- 已生成一次完整外发。
- 随后修改 BOM、批次名称及 PDF 索引。

预期：

- 旧外发记录保持原始内容。
- 原始图号、文件名和分包明细不变化。

### 场景 11：暂不纳入

条件：

- 某 PDF 被标记暂不纳入。
- 重新扫描目录。

预期：

- 不自动恢复到外发候选。
- 不删除磁盘文件。
- 不影响已有外发历史。

### 场景 12：生成失败

条件：

- ZIP 生成过程中某源文件发生变化或读取失败。

预期：

- 不记录为成功外发。
- 不留下误导性的成功结果。
- 不修改源文件。
- 显示具体失败原因。

### 场景 13：变更对比中的移除项目

条件：

- 第一批 A、B、C。
- 第二批 A、B，C 已取消使用。

预期：

- 显示 C 为已移除或待确认。
- 不把旧 C 自动加入第二批完整资料。
- 不将 C 当作普通新增 PDF 打包。

### 场景 14：历史批次无明确外观归属

条件：

- 老数据库中存在资料批次，但未记录外观版本。

预期：

- 保留原记录。
- 显示归属待确认。
- 不自动分配到当前外观。
- 允许人工完成关联。

# 十七、Codex 开发要求

1. 先读取项目 Skill 及其指向的必要业务规则和技术文档。
2. 检查当前 Schema、外发资料代码、PDF 文件中心、BOM 和外发历史实现。
3. 以本次确认的业务流程为外发资料模块的新需求基准。
4. 如新需求与旧外发规则冲突，以本次明确确认的规则为准；但不得借此修改图号占用、历史快照等无关的核心安全规则。
5. 可以进行必要的代码修改、数据库迁移、测试和 UI 调整。
6. 不得自动修改或清理用户本机的真实业务资料。
7. 不得在启动时自动执行历史数据合并或无法逆转的归属修正。
8. 数据迁移必须向后兼容，并可通过备份恢复。
9. 保留现有正常功能，不为本次改造重写无关模块。
10. 不能仅修改界面，必须真正完成底层文件筛选、批次对比、打包和历史记录逻辑。
11. 完成后提供实际修改内容、数据库变化、测试结果、尚未解决的问题和本地验证步骤。
12. 代码在隔离开发环境完成，用户后续在本机运行时读取真实数据库；不得假定开发环境具有用户本机全部资料。
13. 对尚无可靠依据的历史归属、批次顺序和文件替换关系，保留人工确认入口，不得擅自猜测。

# 十八、最终验收目标

完成改造后，用户应能够：

**不维护 BOM，也能选择一个完整包材批次，直接生成整套外发资料。**

当需要发送本次更新时：

**选择新批次 → 与上一批次比较 → 自动推荐变化文件 → 人工确认 → 生成更新 ZIP。**

当需要重新发送整套资料时：

**选择指定批次 → 读取该批次完整资料 → 人工确认 → 生成完整 ZIP。**

生成后：

- ZIP 名称符合公司规范。
- 每个分包的文件数量和内容准确。
- 邮件草稿与本次外发一致。
- 外发历史可追溯。
- 原始 PDF 不被修改。
- 历史图号和历史外发记录不受影响。

**最终原则：资料批次负责提供文件，批次对比负责识别变更，BOM 负责辅助核对，用户负责最终确认，外发历史负责永久追溯。**
